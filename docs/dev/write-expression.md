# 式を書く・式言語を育てる

> 索引: [`README.md`](README.md)

パラメータ式（REQ-CORE-014）とフィールド式（REQ-CORE-015）の**使い方**と、
言語に名前を足すときの**手順**。

**構文と意味論の規範は
[`../specifications/expression-language.md`](../specifications/expression-language.md)。**
関数の定義・丸め方・`noise` の値域はそちらが決める。ここでは同じ表を書かない
（名前だけ並べ、定義は仕様へ送る）。

## チェックリスト — 言語に名前を足すとき

1. **仕様書を先に直す。** 綴りは `.ravprj` に永続化されるので、名前を決めた
   時点で移行問題が発生する。§9 の互換規則（「今エラーになる式を通す方向に
   しか変えない」）に反していないか確認する
2. 変数なら `crates/ravel-core/src/expression/scope.rs` の
   `PARAMETER_VARIABLES` / `FIELD_VARIABLES` に**末尾で**足す。スロットは
   宣言順で、既存のスロットを動かすと保存済みの式が別の変数を読む
3. 同じ名前を `crates/ravel-core/src/expression/context.rs` の `value_of` に
   足す。足し忘れは `every_declared_name_has_a_value` テストが落ちる
   （黙って `0.0` にならない）
4. 組み込み関数なら `crates/ravel-core/src/expression/builtin.rs`。
   **意味論は WGSL の同名ビルトインに合わせる**（仕様 §6。合わせないと GPU
   化した日に絵が黙って変わる）
5. `mise run check`

`noise` の実装は**動かさない**。値がそのままユーザーの絵になるので、
ゴールデンテストで固定してある。

## 式を書く側 — Properties から

パラメータ行の左に並ぶ 3 つのボタンのうち、いちばん右の Σ が式のトグル
（左からポート公開 ○、キーフレーム ◇、式 Σ）。チャネルを持てるパラメータ
（`Float` / `Channel` / `Channel2` / `Channel3` / `Channel4`）にだけ出る。

- **Σ を押すと、定数の成分にだけ式が付く。** 付いた成分は「いま表示されて
  いる値」をそのまま数値リテラルとして持つので、押した瞬間に絵は動かない
- **キーフレーム・ノード出力・ブレンドで駆動された成分は上書きしない。**
  式で置き換えるとその駆動元が消え、「外して定数・キーフレームに戻す」の
  戻り先が無くなる。全成分がそうなっている行では Σ 自体が無効表示になり、
  tooltip が理由を出す（式を付けたいならキーフレームを先に外す）
- 行の下に成分ごとの入力欄が出る。Enter か focus を外すと確定する
- **構文エラーは打鍵のたびに出る。** 打っている途中の文字列は下書きとして
  パネルが持ち、その場でコンパイルしてエラーだけ更新する。**下書きは文書に
  書かない**ので undo 履歴が打鍵で汚れない。確定は Enter と blur だけ
- **構文エラーは確定を妨げない。** 壊れた式もそのまま保存され、入力欄の下に
  位置付きのエラーが出て、値はチャネルの既定値になる。書きかけで手を止め
  られるようにするための設計で、`ParameterExpression` はコンパイルに失敗した
  ソースも保持し `.ravprj` を往復する
- **Σ をもう一度押すと外れる。** 各成分はそのとき表示されていた値の定数に
  戻る。式が付いていない成分（キーフレームなど）は触らない。式が
  `Blend` の中にある場合は **`Blend` を残したまま式の側だけ**定数になる
  ので、混ぜてあったキーフレームは消えない

ノードグラフのノード本体では、式で駆動されたパラメータは**数値ではなく
ソース文字列**が出る（評価コンテキストを持たない描画なので、数値を出すと
嘘になる）。

**レイヤーの殻プロパティ（位置・スケール・不透明度など）にはまだ Σ が出ない。**
式そのものは殻のチャネルでも評価されるが、付け外しの UI はノードパラメータ
だけにある。

## 変数

| 名前 | パラメータ式 | フィールド式 |
|---|---|---|
| `frame` `time` `fps` | ✅ | ✅ |
| `res.width` `res.height` `res.aspect` | ✅ | ✅ |
| `comp.width` `comp.height` `comp.aspect` | ✅ | ✅ |
| `elem.count` | — | ✅ |
| `@P.x` `@index` `@N.y` `@Cd.r` `@任意名` | — | ✅ |

`frame` は整数のフレーム番号ではなく**連続位置**（モーションブラーや
タイムリマップで小数になる）。`time` は `frame / fps` で、同じ瞬間を指す。

`pi` と `e` は変数ではなく**言語の定数**なので、`2 * pi` は評価前に潰れる。

パラメータ式で `@` を書くと専用のコンパイルエラー
（`attributes are not available here`）になる。パラメータにジオメトリは無い。

## 属性（フィールド式だけ）

`@名前` に成分を付けて読む（`@P.x`、`@Cd.r`。`.r` `.g` `.b` `.a` は
`.x` `.y` `.z` `.w` の別名）。**成分を付けないベクトル属性はコンパイル
エラー** — 式はスカラーを 1 個返すため。

- 見えるのは**サンプルされているドメインの属性だけ**。point の式から
  primitive の列には届かないし、暗黙の昇格もしない
- 存在しない属性・数値でない列・成分の無い列は `0.0` を読み、
  **サンプルごとに 1 回だけ**警告する（要素ごとに出すと 1e5 要素 × 全フレーム
  でログが溢れる）
- `@P` はドメインの `P` 列を本来の幅で読む。2D ジオメトリでは `@P.z` が
  `0.0` になるが、これは平面の位置の実際の第 3 座標であって欠損値ではない

## 組み込み関数

定義は仕様 §5。名前だけ:

```text
sin cos tan asin acos atan atan2
exp exp2 log log2 pow sqrt abs sign
floor ceil round fract
min max clamp mix step smoothstep
noise
```

引数の個数が合わなければ位置付きのコンパイルエラー。**べき乗演算子は無い**
（`pow(a, b)` を使う）。

## 書けないもの

ループ・代入・関数定義・コメント・文字列は**文法に存在しない**。ループを
書けないことが停止性の保証そのもの（REQ-INFRA-007 の段 0）なので、
サンドボックス機構を足す前にここを疑う必要は無い。

ベクトルを返す式も v1 には無い。成分ごとにチャネルがあるので、成分ごとに
式を置く。

## エラーが出たら

`ExpressionError` は行・列・範囲を持つ。**UI で位置を計算し直さない** —
コア層が持っているものをそのまま出す。メッセージはユーザーが書いた識別子や
ソースの断片を引用するので、**ロケールキーではなくデータとして扱う**
（`t!` を通さずそのまま出す。翻訳できるのは書式であって、ユーザーが打った
識別子ではない）。
