# Viewer の表示オプションと検査 実装計画

> **Status**: Done — INSP-1 (#213, 2026-07-30), INSP-2 (#479), INSP-3 (#480),
> INSP-4 (#482), INSP-5 (判断のみ、2026-08-25)

対象: Viewer で「出ている絵が本当に正しいか」を確かめる手段を用意する。
背景色の配線、透過の可視化、チャンネル単独表示、ピクセル値の読み取り、
再生・キャッシュ状態の表示。関連要件: REQ-UI-004（スコープ付きビューア）、
REQ-LAYER-001。

## 問題

### 1. `Composition.background_color` が誰にも読まれていない

`background_color: Color` は `Composition` のフィールドとして定義され
（`crates/ravel-core/src/composition/mod.rs:360`）、**コンプ設定フォームで
編集でき**（`composition_form.rs:66, 116`）、**保存もされる**。しかし
評価・合成のどこにも現れない。Viewer は黒 quad をハードコードして絵を
重ねている（`viewer.rs:1614`）。

`layer-shell-wiring-plan.md` が `track_matte` / `time_remap` について指摘した
「データモデルと永続化が先行して、設定したのに効かないバグに見える」の
**すでに顕在化した例**。こちらは UI が既にあるので今日踏める。

issue: `MED-CORE-09`（本計画が引き受ける）。

### 2. 透過を確認する手段が無い

コンプ出力は straight alpha の RGBA f32（`FrameBuffer`）だが、Viewer は
黒の上に重ねて表示するだけ。**「アルファが 0 なのか黒なのか」が区別できない。**
キーイング（`FX-4`）やマットを入れると、この区別ができないまま作業することになる。

### 3. 値を数値で確かめられない

カラー作業とノードのデバッグで最初に欲しくなるのは「この点の値は何か」。

> **2026-08-05 更新**: この節は当初「`ViewerFrame::Frame` が
> `Arc<FrameBuffer>`（f32）を持っているので 8bit 変換前の評価値はすでに
> UI 側にある」と書いていた。`gpu-compositing-plan.md` の `GPUCOMP-9`
> （HIGH-08）が f32→BGRA 変換を評価ワーカーへ移したので、**UI 側にあるのは
> BGRA u8 の表示画像だけ**になった（`ViewerFrame::Frame { image: ViewerImage }`）。
> したがって `INSP-3` は f32 値の入手経路を自分で用意する必要がある
> （評価結果の `FrameBuffer` を表示画像と併せて運ぶか、ワーカーに問う）。
> **どちらを採るかは `INSP-3` 着手時の判断**で、フレームごとに f32 を
> UI スレッドへ運ぶ形は `GPUCOMP-9` が外した費用を戻すことになる点に注意。
>
> **2026-08-25 決着**: 前者（表示画像と併せて運ぶ）を、**読み取りが有効な間
> だけ**という条件付きで採った。理由と採らなかった案は `INSP-3` の節に。

### 4. 再生とキャッシュの状態が Viewer に出ない

`Transport` はドロップフレーム数を数えている（`playback.rs:82, 108`）が、
どこにも表示されない。プロキシ・解像度低下・キャッシュヒットの状態も同じ。
`cache-plan.md` の `CACHE-6` は Timeline のキャッシュ帯を持つが、**Viewer 側の
状態表示は誰も持っていない**。

## 決定事項

### 背景色は合成の最下段で敷く。Viewer 側で誤魔化さない

`background_color` は評価結果に含める。Viewer が「背景色っぽい quad」を描く
方式は採らない — それだと書き出し（`EXPORT-*`）で背景が消え、Viewer と
出力が食い違う。

### 透過表示は「背景の描き方」のオプションで、オーバーレイではない

チェッカーボードは絵の下に敷くもので、絵の上に重ねる
`done/viewer-overlay-manipulator-plan.md` の機構には乗らない。背景の描画モード
（コンプ背景色 / チェッカーボード / 単色）として持つ。

### チャンネル単独表示は表示経路の変換で行う

`R` / `G` / `B` / `A` の単独表示は、リニアバッファから表示バイト列を作る
表示変換に表示モードを渡して行う。**評価結果は変えない**（ノードを挿し込む
方式は採らない）。

**`CM-7` でこの変換は GPU へ移った**（`ravel_nodes::DisplayTransform` /
`display_transform.wgsl`）ので、モードはシェーダのユニフォームとして渡す。
変換は**評価ワーカーで走る**ままなので、モード切り替えは再評価ではなく
**変換のやり直し**として届ける必要がある（詳細は `INSP-2` の節）。

### 表示オプションはコンプにもプロジェクトにも保存しない

背景モード・チャンネル・ガイド表示などの Viewer 表示状態は
**セッション内のパネル状態**とする。`.ravprj` にも `ui_state.json` にも
書かない。理由は「同じプロジェクトを別の目的で開くたびに前回の検査モードが
復元されると邪魔になる」ため。永続化したい要求が出た時点で
`settings-screen-plan.md` の設定として扱う（表示オプションを設定画面に
出すのは「設定が挙動を変えるときだけ」という同計画の規約に合う）。

### 状態表示は「異常時だけ出す」

ドロップ・プロキシ・低解像度は**通常時に何も出さない**。常時 HUD を出すと
絵の確認を邪魔する。異常が続いている間だけ小さく出し、解消したら消す。

## 実装単位

### INSP-1: `background_color` の配線とチェッカーボード

- 殻合成の最下段でコンプ背景色を敷く。評価結果に含め、Viewer と書き出しで
  同じ絵になるようにする
- 背景色のアルファが 1.0 未満のときは透過として扱う（不透明を強制しない）
- Viewer の背景描画モードを追加: コンプ背景色（既定） / チェッカーボード /
  単色。チェッカーボードはスクリーン空間の固定サイズで描く（ズームで
  マスの大きさが変わらない）
- ハードコードされた黒 quad（`viewer.rs:1614`）を撤去する

**完了条件**

- 背景色を変えると評価結果のピクセルが変わるテスト（Viewer 側の描画ではなく
  `FrameBuffer` を検証する）
- 背景色のアルファ 0 のコンプで、レイヤーが無い領域のアルファが 0 になるテスト
- チェッカーボードのマス目がズームに依存しないこと（性質テスト）
- `MED-CORE-09` の解消

**フェーズ**: A5（`roadmap.md`）。この単位だけ前出しする — 編集できるのに
効かないフィールドが残っているのは他の検査機能より痛い。

### INSP-2: チャンネル単独表示

- 表示モード: RGB（既定） / R / G / B / A / アルファをマット表示
- 単独チャンネルはグレースケールで描く
- 表示変換（`CM-7` 以降は GPU の `display_transform.wgsl`、評価ワーカーが投げる）に
  表示モードを渡す形にし、評価経路は触らない。モード切り替えはワーカーの
  変換に届く必要がある（再評価ではなく変換のやり直し）
- 切り替えはコマンド（`CommandId`）＋ Viewer ツールバー。キーバインドは
  `assets/keybindings/default.toml` の `[viewer]` セクションに置く

**完了条件**

- 各モードで期待するピクセル値が出るテスト（変換関数の単体テスト）
- モード切り替えが再評価を発生させないテスト
- ロケール（en / ja）にモード名が入っていること

### INSP-3: ピクセル値の読み取り

- ポインタ位置のコンプ座標と、その点の RGBA を f32 のまま表示する
- 表示形式は f32（既定）と 8bit 換算の切り替え
- ズームルーペ（ポインタ周辺の拡大表示）は**この単位に含めない**（下記非対象）
- 値の表示はスクリーン空間なので、`OVL-1` のスクリーン空間描画 API に乗る

**依存**: `OVL-1`（スクリーン空間の描画）

**完了条件**

- コンプ座標 → バッファ添字の変換が端でずれないテスト（境界値）
- 評価バッファがコンプ解像度より小さいときも正しい点を読むテスト
  （`ViewerFrame::Frame` は両方の解像度を持つ）
- フレーム外にポインタがあるとき何も出ないテスト

**f32 の入手経路（実装時の判断、2026-08-25）**

「3. 値を数値で確かめられない」が保留していた選択は、**読み取りが有効な間だけ
リニアフレームの CPU コピーを表示バイト列に添えて運ぶ**で決着した
（`DisplayFrame::linear`、ホストの `Arc<AtomicBool>` を評価ワーカーの
`DisplayTransform` が毎フレーム読む — `INSP-2` のチャンネルセルと同じ形）。

- **採った理由**: **無効な間は 1 バイトも増えない。** `GPUCOMP-9` が外した
  1 画素 16 バイトの読み戻しは、ユーザーが値を見ている間だけ戻る。そして
  ポインタ移動では再評価も読み戻しも起きない — UI は手元の `FrameBuffer` を
  添字するだけで、オーバーレイは評価ターゲットを 1 つも宣言しない
- **採らなかった案**: 部分読み戻し（`read_texture` の region 版）。コピーは
  小さくなるが、**ポインタ移動ごとに GPU 同期が要る**か **UI スレッドで GPU を
  待つ**ことになる（`.agents/rules/rust.md`「UI スレッドをブロックしない」に
  反する）。`ravel-gpu` の `read_texture` は `origin: Origin3d::ZERO` 固定で
  部分読み戻し API 自体が無く、足す価値がこの用途では出ない
- **採らなかった案**: オーバーレイの `eval_targets` / `ScopedTarget` で運ぶ。
  生の値は届くが、コンテキストがポインタ移動ごとに組み直されるので**移動の
  たびに評価要求が飛ぶ**
- **対価**: 有効な間、出力段フレームキャッシュの 1 エントリが 4 倍になる
  （`DisplayFrame::byte_size` はコピーを数える）。on/off の切り替え時は完成
  フレームを捨てて `InvalidationHint::None` で 1 回だけ要求する — キャッシュ
  済みのフレームは f32 を持たないため

8bit 換算は**同じ値を 0-255 の目盛りに置き換えるだけ**で、画面に出ている表示
バイト列ではない。表示変換はユーザーの LUT 込みで評価ワーカー側にあり、UI が
LUT 抜きの近似をもう一度掛けるとグラフのどこにも存在しない値を報告することに
なる。

### INSP-4: 再生とキャッシュの状態表示

- ドロップフレームが続いている間だけ小さく表示する（`Transport::dropped_frames`）
- 表示解像度がコンプ解像度より低いとき、その旨を表示する
- キャッシュ状態は `cache-plan.md` の `cache_stats` API が入ってから表示する
  （**API より先に作らない**）

**依存**: キャッシュ表示のみ `CACHE-6`

**完了条件**

- ドロップが 0 のとき何も描かれないテスト
- 解消後に表示が消えるテスト
- `cache_stats` が無い状態でもビルド・動作すること（キャッシュ部分は後付け）

**実装メモ（2026-08-25）**

`CACHE-6` は済んでいるので、キャッシュ表示も同時に入れた。`cache-plan.md` の
`cache_stats` は作らず、Timeline のキャッシュ帯（`panels::cache_band`）を
そのまま割合にする — 帯と Viewer の割合が食い違わないのが主な理由で、
Viewer 専用の集計 API は要らなかった。帯が空（評価前）のときは割合を出さない
（`0%` は「測った結果 0」を主張することになる）。

出す位置は**画面右上**（`LabelPlacement::CanvasTopRight`）。左上はドラッグ
HUD、左下は `INSP-3` のピクセル読み取りが使っている。`priority` の値は他の
オーバーレイとの文字の取り合いを決めない — 隅が別なので、順序は registry 内の
並びが読みやすいかだけの問題。

**再生中だけ出すものが 2 つある。** ドロップフレームは
`Transport::dropped_frames` が再生開始でリセットされる累積値なので、停止後に
出し続けると終わった区間の話を報告することになる（停止が「解消後に消える」の
実装でもある）。キャッシュの割合は、停止中は Timeline の帯がフレーム単位で
同じことを言っているので二重表示にしない。プレビュー解像度だけは進行中の
事象ではなく画面の性質なので停止中も出す。

**Global を 1 つ足した**（`panels::PlaybackStatus { playing, dropped_frames }`）。
`PlaybackPosition` にフィールドを足さなかったのは、あれを組む箇所がテスト込みで
20 か所あり、そのどれもドロップ数を知らないため。書き手は
`PlaybackController::publish_position` の 1 経路だけで、**値が変わったときだけ**
書く（`set_cache_band` と同じ理由）。**観測者は置かない** — 再生中はプレイヘッドの
再描画が毎フレーム走るので、購読すると `HIGH-21` と同型の二重再描画になる。

**プレビュー解像度の要素は「適応降格中だけ」に絞った**（2026-08-25 のユーザー
判断）。計画書の原文は「表示解像度がコンプ解像度より低いとき」だが、既定係数が
1/2 なのでそれだと常時表示になり、ツールバーの係数表示と二重になる上に、
居座った警告は隣のドロップ数まで読まれなくなる。判定は**選択係数と実効係数の
比較**で、`OverlayContext` は両方を対で運ぶ（画素数の対からは復元しない —
`apply` は `div_ceil` なので奇数幅で戻せず、選択係数はそもそも画素数に
入っていない）。要素の判断と 1 行の組み立ては
`ravel_ui::panels::viewer::playback_status_text`（純粋関数、ロケールキーは
呼び出し側が解決する）。

### INSP-5: スコープ 4 種の引き取り判断

REQ-UI-004 は波形モニタ / ベクトルスコープ / ヒストグラム / パレードを
要求しており、ワークスペースプリセット（`assets/workspaces/color.toml`）は
4 枚を配置しているが、実装は `PlaceholderPanel`。

- 4 種を本計画が引き取るか、別計画に切るかを決める
- 決めるべき点: 同じ `FrameBuffer` を 4 パネルで共有するか、パネルごとに
  サンプルするか。OCIO（REQ-UI-004 が要求）をどの段で通すか
- **判断の単位であり、実装の単位ではない**

**完了条件**

- 判断が `docs/implementation/README.md` に記録されること
- 引き取る場合は単位分割を本計画に追記、切る場合は新計画を作って
  `backlog.md` / `roadmap.md` を更新

**判断（2026-08-25）: 引き取らず、`viewer-scopes-plan.md` に切った。**

理由は 3 つ。**測るデータが UI に無い** — `GPUCOMP-9` / `CM-7` 以降 UI が持つのは
表示バイト列だけで、`INSP-3` が入れたリニアフレームの添付は
`Arc<AtomicBool>` 1 本、つまり消費者 1 つ前提。スコープは消費者が 4 種 ×
多重インスタンスなので**添付の要求を数える**仕組みが要り、これは表示
オプションではなく評価経路の変更。**毎フレームの統計計算**が入り、間引き幅と
共有と（必要なら）GPU への移動という段取りが必要。**OCIO** が REQ-UI-004 に
含まれるが色管理の計画が 1 つも無く、本計画で抱えると計画の主題が 2 つに割れる。
複数クレート・複数パネル・評価経路に跨るので AGENTS.md の Design gate に
当たり、独立した計画が妥当と判断した。

なお**トグルとレイアウトは既に動いている**（`PanelKind` の 4 種、
`View ▸ スコープ` = `Alt+6` が `SCOPE_PANELS` をまとめて開閉、
`assets/workspaces/color.toml` が 4 枚を配置）。残るのは中身だけで、
`viewer-scopes-plan.md` が `MON-1`〜`MON-7` に分割した。

## 検証

- `mise run check`
- 背景色は `FrameBuffer` レベルで検証する（Viewer の描画結果は検証しない）
- チャンネル変換とピクセル読み取りは純粋関数の単体テスト
- ゴールデン画像は増やさない

## 非対象

- **ズームルーペ**。ピクセル値が数字で出れば大半の用途は足りる。必要になったら
  `OVL-1` のスクリーン空間描画で追加する
- **OCIO / カラースペース変換**。REQ-UI-004 が要求しているが、色管理は
  評価パイプライン全体の話なので本計画では扱わない（`INSP-5` の判断対象）
- **A/B 比較・差分表示・外部モニタ出力**。REQ-UI-004 の「将来」項目
- **ROI（作業領域）枠**。部分レンダリングの機能が無いので、枠だけ描いても
  何にも使われない。`cache-plan.md` / `done/render-export-plan.md` が部分評価を
  持った時点で引き取る（`done/viewer-overlay-manipulator-plan.md` の棚卸し表に
  見送りとして記録済み）
