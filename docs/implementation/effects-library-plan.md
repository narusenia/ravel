# ビルトインエフェクトライブラリ実装計画（REQ-MOGRAPH-005）

> **Status**: Planned — 2026-07-27

対象要件: REQ-MOGRAPH-005（優先度 Must）。関連: REQ-CORE-002、
REQ-CORE-007（統一アニメーションチャネル）、REQ-GPU-001。

## 問題

出荷時に外部プラグインなしで基本作業が完結する量のノードが要る、
という要件に対し、現在あるのは **4 つだけ**。

| カテゴリ | 要件が挙げるもの | 現状 |
|---|---|---|
| 合成 | ブレンドモード、マスク、キーイング | `merge` + `comp.merge.*`（ブレンドのみ） |
| カラー調整 | 明るさ/コントラスト、色相/彩度、カーブ、レベル | `color_correct` 1 つ |
| カラーグレーディング | リフト/ガンマ/ゲイン、カラーホイール、HSL カーブ、LUT、カラーマッチ | なし |
| ブラー/シャープ | ガウシアン、方向、ラジアル、シャープ | `blur`（ガウシアンのみ） |
| ディストーション | ワープ、レンズ歪み、波紋 | なし |
| 生成 | グラデーション、ノイズ、フラクタル、チェッカーボード | なし |
| スタイライズ | グロウ、シャドウ、ストローク、エンボス | なし |
| トランスフォーム | 移動、回転、スケール、ミラー、タイル | `transform`（ミラー/タイルなし） |
| トランジション | 20 種程度 | なし |
| 時間 | タイムリマップ、フレームブレンド、フリーズ | なし |

`registry/builtin.rs` の集計テストが示すとおり Image カテゴリ 5 個、
Color カテゴリ 2 個、Time カテゴリ **0 個**。

## 決定事項（2026-07-27 設計セッション）

### トランジションは本計画に含めない

受入条件の「トランジションがタイムライン UI から適用できる」は、
エフェクトノードの実装ではなく**タイムライン側の仕事**
（クリップ境界の概念、ドロップ操作、デュレーション編集）。
ノード量産と混ぜると計画が読めなくなるので分ける。

結果として REQ-MOGRAPH-005 は本計画完了時点で
「トランジションを除いて完了」になる。

### 全ノードを GPU で実装する（既存方針の踏襲）

本計画のノードは**すべて FrameBuffer → FrameBuffer** で、
`GpuFrameBuffer` の常駐チェーンが既に確立している
（`done/eval-render-performance-plan.md`、実測で往復 8.8 ms を削減）。
GPU が主経路であることに議論の余地はなく、`gpu-resident-geometry-plan.md`
（ジオメトリ側の常駐化）とは独立に進められる。

CPU 参照実装はカテゴリごとに 1 本だけ書く（下記「検証」参照）。
全ノードに CPU 版を用意するのは過剰。

### 既存の GPU ノードパターンを踏襲する

`blur.rs` が確立した形をそのまま使う。

```rust
const SHADER_SRC: &str = include_str!("shaders/<name>.wgsl");
#[repr(C)] struct Params { ... }        // bytemuck::Pod
pub struct XProcessor { ctx, pipeline, pool }
```

`ShaderManager::compile_source` + `ComputePipeline` + `TexturePool`。
`gpu_util` のレイアウトヘルパを使う。新しい GPU 基盤は導入しない。

### 時間系ノードだけは評価エンジンに触る

タイムリマップ / フレームブレンド / フリーズは
「上流を**別のフレームで**評価する」必要があり、他の 9 カテゴリと
性質が違う。`EvalContext.frame` を差し替えて上流を pull する仕組みが要る。

**この仕組みは `evaluation-scope-plan.md` の単位 2 が用意する**
（`PathSegment::TimeShift`）。本計画で独自に組まない。

理由: 現行の `NodeKey` は 1 ノードにつき値を 1 つしか持てず、`frame` は
キーではなく検証条件なので、同じ上流を `f` と `f'` で要求すると
**互いを上書きし続けて再計算する**。同じ制約に `stateful-eval-plan.md` と
グラフ内反復も当たっており、3 つが別々の回避策を持つのを避ける。

時間系は最後の単位に置き、他が全部済んでから着手する。

### 生成ノードはフィールド層と重複させない

`field.noise` は既にある。生成カテゴリの「ノイズ」「フラクタル」は
**FrameBuffer を出す**ノードで、フィールドとは出力型が違う。
実装は共有せず、WGSL で独立に書く（CPU の simplex とパラメータ互換に
する必要はない。互換を装うと後で必ずズレる）。

### LUT は `.cube` のみ

3D LUT の業界標準。`.3dl` / `.look` は非対象。

## 実装単位

カテゴリごとに分け、単位内は並列委譲しやすいよう独立なノードだけを束ねる。

### 単位 1: カラー調整とカラーグレーディング

- 明るさ/コントラスト、色相/彩度、レベル（入出力レンジ + ガンマ）、
  トーンカーブ（RGB + 個別チャンネル）
- **トーンカーブは `ParameterValue::Curve` を使う**
  （`properties-parameter-editors-plan.md` が型とエディタを所有する）。
  チャンネルごとに 1 本、計 4 本の `Curve` パラメータを持つ。
  独自のカーブ表現とエディタを作らない — 同じ型の消費者が
  `field.curve_remap` と `math.curve` にもあり、3 者で表現が分かれると
  エディタも 3 つになる
- リフト/ガンマ/ゲイン、カラーホイール、HSL カーブ、LUT 適用（`.cube`）
- カラーマッチは**非対象**（参照画像の統計マッチングは別物）

> **2026-10-06 実装**: LUT 適用（`.cube`）を**除いて**入れた
> （`comp.brightness_contrast` / `hue_saturation` / `levels` / `curves` /
> `lift_gamma_gain` / `hsl_curves`、`crates/ravel-nodes/src/comp/grade.rs`）。
> LUT はファイル参照の設計（パス文字列か素材か）が未決なので別単位 `FX-1b`。
> カラーホイールのウィジェットは作らず、`comp.lift_gamma_gain` の
> RGB ベクタのパラメータ（色パラメータではない。ピッカーが 0〜1 に
> クランプし、暗くする方向にしか振れないため）がホイールの演算を担う。下の完了条件のうち LUT の項目だけが
> 残っている。

**完了条件**

- 各ノードのゴールデンテスト（既知の入力パッチ → 期待画素）。
- LUT: 恒等 LUT を通して入力と一致するテスト、
  既知の変換 LUT でのテスト、壊れた `.cube` でエラーになるテスト。
- 全パラメータが統一アニメーションチャネルに乗ることのテスト。

### 単位 1c: `color_correct` を総合グレーディングノードにする

2026-10-06 追加。単位 1 の 6 ノード（`comp/grade.rs`）はノードグラフで
部分的に使う**部品**として残し、`color_correct` を Lumetri 相当の
**入口**に育てる。1 ノードでよくある補正が完結することが目的。

- セクション構成（Lumetri に倣う）:
  - ベーシック: 色温度 / 色かぶり、露光量、コントラスト、ハイライト /
    シャドウ / 白レベル / 黒レベル、彩度、自然な彩度
  - カーブ: RGB + チャンネル別、HSL カーブ
  - カラーホイール: シャドウ / 中間調 / ハイライト（リフト / ガンマ / ゲイン）
  - クリエイティブ: フェード、ビネット。LUT は `FX-1b` の設計が決まってから足す
- 単位 1 の演算を**書き直さず**に再利用する。`comp_grade.wgsl` の各段を
  1 パスで順に通す形にし、総合ノードと単独ノードで同じ入力が同じ画素になる
- **既存の `brightness` / `contrast` / `saturation` パラメータは名前と意味を
  変えない**。保存済みの `.ravprj` をフォーマットを上げずに読めるように、
  新しいパラメータは既定値が恒等になる形で後ろに足す。意味を変える必要が
  出たら、そこで移行を設計する
- 0〜1 を超える量（露光量、ゲイン、負のリフトなど）を色パラメータに
  載せない（色ピッカーが 0〜1 にクランプする。単位 1 のレビューで出た）
- Properties 上のセクション分け（折りたたみ）が今の UI で表現できるかを
  最初に確認する。できなければ、その UI の追加を別単位に切り出す

> **実装メモ**: セクション分けは既存の `NodeTemplate::with_param_group`
> （`basic` / `curves` / `wheels` / `creative`）で表現でき、UI の追加は不要だった。
> 既存 3 パラメータは名前・意味・既定値とも不変で、ブライトネスはコントラストの
> 前に加算される（旧シェーダと同じ）ので、共有段へは `brightness * contrast`
> として渡す。`grade_stages.wgsl` に単位 1 の段を移して `comp_grade.wgsl` と
> `color_correct.wgsl` の両方へ前置し（`gpu_util::with_grade_stages`）、カーブの
> テーブルも `comp/grade.rs` の `bake_curves` / `bake_hsl` を共有する。パラメータが
> すべて中立の段は旗でスキップする（カーブのテーブルは 0〜1 にクランプするため、
> HDR の画素を無駄に変えない）。対応ノードのない段（色温度 / 色かぶり、露光量、
> ハイライト / シャドウ / 白 / 黒、自然な彩度、フェード、ビネット）の式は
> `color_correct.wgsl` が正で、既知のパッチのテストで固定している。
> 完了条件の「全パラメータが統一アニメーションチャネルに乗る」は、単位 1 と同じく
> **`ParameterValue::Curve` の 7 本を除く**（Curve 型はチャネルを持たない。Float /
> ベクタの 18 本はテストで固定）。保存済み `.ravprj` の互換は、旧 3 パラメータだけの
> `Node` を旧シェーダの式と比べるテストで見ており、実ファイルを開く統合テストは
> `ravel-nodes` が `ravel-project` に依存しないため入れていない。

**完了条件**

- 既存の `color_correct` を含む `.ravprj` を開いて、出力画素が変わらないテスト。
- 新しいパラメータが全部既定値のとき恒等になるテスト。
- 各セクションを単独で動かしたとき、対応する単位 1 のノードと同じ画素に
  なるテスト（同じ段を通していることの保証）。
- 全パラメータが統一アニメーションチャネルに乗ることのテスト。

### 単位 2: ブラー / シャープ / ディストーション

- 方向ブラー、ラジアルブラー、シャープ（アンシャープマスク）
- ワープ（メッシュではなく変位マップ方式）、レンズ歪み、波紋

> **2026-10-06 実装**: 6 ノードを入れた（`comp.directional_blur` /
> `radial_blur` / `sharpen` / `warp` / `lens_distortion` / `ripple`、
> `crates/ravel-nodes/src/comp/distort.rs`、シェーダは
> `comp_distort.wgsl` の 1 本）。境界は**端の画素へ clamp**（均一な不透明画像は
> 端まで均一）、補間は premultiplied の双一次。長さの量はコンポジションの
> ピクセルで持ち `composition_scale` を掛けるのでプレビュー縮小で絵が変わらない。
> ワープは変位マップ方式（2 本目の入力、R=横 G=縦、中間グレーが無変位）で、
> メッシュワープは作っていない。シャープのぼかしは既存の `blur` プロセッサを
> 再利用する。

**完了条件**

- 方向ブラー: 角度 0 で水平方向のみににじむテスト。
- ラジアルブラー: 中心画素が不変であるテスト。
- レンズ歪み: 係数 0 で恒等になるテスト。
- 各ノードで境界画素の扱い（clamp）が定義どおりであるテスト。

### 単位 3: 生成とスタイライズ

- グラデーション（線形/放射状、多ストップ）、ノイズ、フラクタル、
  チェッカーボード
- **グラデーションのストップは `ParameterValue::Ramp` を使う**
  （`properties-parameter-editors-plan.md` が型とエディタを所有する）。
  同じ型の消費者が `field.ramp` と `color.ramp` にもあるため、独自の
  ストップ表現とエディタを作らない
- グロウ、ドロップシャドウ、ストローク、エンボス

> **2026-10-06 実装**: 生成系は `comp.gradient` / `comp.noise` /
> `comp.fractal` / `comp.checkerboard`（`comp/generate.rs`、
> `comp_generate.wgsl`、1 本のシェーダ + 判別値）。位置はフレームに対する割合、
> または合成ピクセル × `composition_scale` で持ち、解像度に依存しない。
> グラデーションのストップは `Ramp` パラメータで、CPU の `RampParam::evaluate`
> を 256 エントリの表に焼いて GPU へ渡す（`comp.curves` と同じ。評価の実装は
> 1 本）。ノイズは `field.noise` と実装を共有しない WGSL の勾配ノイズで、
> `seed` がハッシュに入る。スタイライズ系は `comp.glow` / `comp.drop_shadow` /
> `comp.stroke` / `comp.emboss`（`comp/stylize.rs`、`comp_stylize.wgsl`）。
> グロウとシャドウは既存の `BlurProcessor` を呼び（半径に `composition_scale`
> を掛ける）、ストロークは距離重みつきの膨張 / 収縮、エンボスは輝度 + 被覆を
> 高さとする傾き。式は各ファイル冒頭の doc コメントが正。グロウに輝度しきい値は
> なく、ストロークは外側 / 内側のみ（中央は無い）で、探索半径は 48 ピクセルで
> 頭打ち。

**完了条件**

- 生成系は解像度非依存（同じ内容が解像度に応じてスケールする）テスト。
- ノイズ / フラクタルの決定性テスト（seed 固定で同一出力）。
- グロウ / シャドウ: アルファ 0 の入力で出力もアルファ 0 のテスト。
- ストローク: 幅 0 で入力と一致するテスト。

### 単位 3b: 単色・塗り・アルファ操作

単位 3 と同じ生成カテゴリだが、**入力を持たない生成**と
**アルファを保った色の置換**は性質が違うので分ける。現状 raster 側の
生成ノードは 1 つも存在せず（`crates/ravel-nodes/src/comp/` は merge /
opacity / transform のみ、`rasterize` は Geometry 入力が必須）、
**単色の平面すら作れない**。

| ノード | 入出力 | 内容 | AE 相当 |
|---|---|---|---|
| `comp.solid` | なし → FrameBuffer | 単色。サイズは評価解像度 | 平面レイヤー |
| `comp.fill` | FrameBuffer → FrameBuffer | アルファを保って RGB を単色に置換 | Fill |
| `comp.tint` | FrameBuffer → FrameBuffer | 輝度を 2 色間にマッピング | Tint |
| `comp.alpha` | FrameBuffer → FrameBuffer | アルファ操作（反転 / 輝度→アルファ / アルファ→輝度 / 別入力をマットにする） | Channel 系 |

`comp.fill` は**ジオメトリ側の `style.fill` とは別概念**
（`style-attributes-plan.md`）。あちらは要素に属性を書くノードで
ラスタライズしない。名前が似ているので、ロケールのラベルとカテゴリで
区別する（`comp.fill` = Image / 生成、`style.fill` = Geometry）。

**完了条件**

- `comp.solid`: 入力なしで評価でき、全画素が指定色になるテスト。
  解像度が評価コンテキストに追従するテスト。
- `comp.fill`: アルファが入力と bit 一致し、RGB が指定色になるテスト。
  アルファ 0 の画素で出力もアルファ 0 のテスト。
- `comp.tint`: 黒→色 A、白→色 B に写るテスト。
- `comp.alpha`: 反転を 2 回適用して入力に戻るテスト。
  マット入力の解像度が異なるときの扱いが定義どおりであるテスト。
- 全ノードがアルファ規約（`blur.wgsl` に揃えた premultiplied 規約。
  GPUCOMP-4）に従うテスト。

### 単位 4: トランスフォーム拡張と合成

- ミラー、タイル
- マスク（ジオメトリ入力でのマット）、キーイング（クロマ / ルミナンス）

> **2026-10-06 実装**: `comp.mirror` / `comp.tile`（`comp/tile.rs`、
> `comp_tile.wgsl`）、`comp.mask`（`comp/mask.rs`）、`comp.key`（`comp/key.rs`、
> `comp_key.wgsl`）。ミラーは**反転**（2 回で元に戻る）で、半分を写す
> カレイドスコープ型は作っていない。タイルは端で**回り込む**（wrap）。
> マスクは新しい被覆計算を持たず、`RasterizeProcessor` でジオメトリを描き、
> その結果を `CompAlphaProcessor` の `matte_alpha` へ渡す。キーはクロマ
> （最大チャンネルで正規化した CbCr 距離）とルミナンスのみで、アルファだけを
> 変える（スピル抑制・エッジ処理・ガベージマットは非対象のまま）。

**完了条件**

- タイル: 1×1 で入力と一致するテスト。
- ミラー: 2 回適用で入力に戻るテスト。
- マスク: ジオメトリ外がアルファ 0 になるゴールデンテスト。
- キーイング: 単色背景が抜けるゴールデンテスト。

**完了条件**

- タイムリマップ: 恒等カーブで入力と一致するテスト。
- フリーズ: 全フレームで同一出力になるテスト。
- フレームブレンド: 中間フレームが両端の平均になるテスト。
- **時間系ノードの下流でキャッシュが誤ヒットしないテスト**
  （フレーム差し替えがキャッシュキーに効いていることの回帰）。

## 検証

- ゴールデンテストは GPU アダプタを要求する。CI にアダプタが無い場合は
  `#[ignore]` ではなく **CPU 参照実装との比較**にする経路を検討する
  （`rasterize` が GPU / CPU の二経路を持つ先例がある）。
  全ノードに CPU 参照を書くのは過剰なので、**カテゴリごとに 1 本**だけ
  CPU 参照付きにして、残りは GPU 前提テストとする。
- パラメータ範囲（`with_param_range`）は全ノードで設定する。
  スクラブ UI が無範囲だと使い物にならないため。

## 非対象

- **トランジション**。ノードもタイムライン UI も別計画。
- **カラーマッチ**（参照画像の統計マッチング）。
- **`.3dl` / `.look` LUT**。`.cube` のみ。
- **メッシュワープ**（コントロールポイントを引っ張る歪み）。
  変位マップ方式のワープのみ。
