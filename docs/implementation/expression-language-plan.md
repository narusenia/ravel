# 式言語 実装計画（REQ-CORE-014 / REQ-CORE-015）

> **Status**: Planned — 2026-08-03

対象要件: REQ-CORE-014（パラメータ式）、REQ-CORE-015（フィールド式）。
関連: REQ-CORE-007、REQ-CORE-010、REQ-CORE-012、REQ-MOGRAPH-001、REQ-INFRA-007。

## 問題

**プレースホルダが 2 つ、登録済みで黙って既定値を返している。**

| 場所 | 現状 |
|---|---|
| `ChannelSource::Expression(ExpressionPlaceholder)` | `evaluate` が `DEFAULT_VALUE`（0.0）を返す（`animation/channel.rs:64`, `:96`） |
| `ExpressionField { expression, default }` | `sample()` が `vec![default; positions.len()]` を返す（`geometry/field.rs:266-269`） |

後者は **`field.expression` としてノードレジストリに登録済み**
（`ravel-nodes/src/lib.rs:188`）。つまりユーザーがグラフに追加できて、
何も起きない。これは `issues/` に起票されていない。

さらに 4 つの要件の受入条件がこれ待ちで止まっている
（REQ-CORE-007 / REQ-CORE-010 / REQ-CORE-012 / REQ-MOGRAPH-001）。

## 決定事項（2026-08-03 設計セッション）

### 言語は Lua ではない

要件側の根拠は REQ-CORE-014 に書いた。実装計画として重要な帰結は 2 つ。

1. **他ノード参照を式が持たない。** `ChannelSource::NodeOutput(NodeId,
   OutputPortIndex)` が独立バリアントとして存在し（`channel.rs:69`）、
   `Blend` で合成できる。式が担うのは `EvalContext` と自分の入力から
   値を作ることだけ。
2. **依存が静的に列挙できる。** パーサが AST を持つので、式が参照する
   変数・属性名を評価前に列挙できる。これがキャッシュキー（`CacheIdentity`）と
   dirty 伝播に直接使える。

### 全域関数にして実行時エラーを消す

**これが本計画で最も効く決定。**

`ChannelSource::evaluate(&self, frame: f64, ctx: &EvalContext) -> f32` は
同期・`&self`・`Result` なし。この形の呼び出しは `ravel-core` /
`ravel-nodes` / `ravel-ui` / `ravel-app` に散在する（`composition/transform.rs:103-108`
のように、1 つの Transform を解決するだけで 6 回呼ぶ）。**シグネチャを
`Result` にすると 100 箇所超が、対処できないエラーを伝播させるだけの
コードになる。**

代わりに**言語を全域にする**。

- すべての演算をすべての入力に対して定義する（`1/0` → `inf`、
  `sqrt(-1)` → `NaN`、`log(0)` → `-inf`）
- **構文エラーと未定義変数は編集時に検出する。** 変数集合は静的に決まる
  （`EvalContext` の項目 + 宣言された属性名）ので、パース時に全部わかる
- 不正な式は「コンパイル済み表現を持たない」状態で保存され、評価では
  既定値を返す
- 有限でない結果はチャネル境界（`ChannelSource::evaluate` 内）で
  既定値に落とす。1 箇所

結果として**シグネチャ変更が要らない**。`channel.rs:86-89` の doc コメントが
「`ctx` は式とノード出力の解決が API を壊さずに利用できるよう安定シグネチャの
一部として置いてある」と書いており、その設計意図に沿う。

### コンパイル済み表現を持つ

`ExpressionPlaceholder { source: String }` は `Serialize` されるので、
**永続化されるのはソース文字列のまま**にする（言語の内部表現を
`.ravprj` に漏らさない）。ロード時とソース編集時にコンパイルし、
コンパイル済み表現をメモリに持つ。

これにより毎フレームのパースが無くなり、フィールド式（要素数 × フレーム）で
致命的にならない。

### フィールド式はバッチ評価

`Field::sample(&self, input: &FieldSample<'_>) -> AttributeArray` は
**位置の配列を受けて配列を返す契約**（`field.rs:266`）。要素ごとの
呼び出しに縛られていない。

コンパイル済み AST を配列に対して回す。要素ごとの固定オーバーヘッドは
「AST ノードごとのディスパッチ」だけになる。将来的に式を WGSL へ落とす
（REQ-GPU-001 / REQ-INFRA-009）道も AST があるので閉じない。

### キャッシュキーに式を含める

`CacheIdentity`（`eval.rs:684`）に式が参照するものが入らなければ、
式を書き換えてもキャッシュがヒットして絵が変わらない。`cache-plan.md` の
`CACHE-2` が導入した `CacheIdentity` に、**式ソースのハッシュと参照集合**を
加える。

### EXPR-1 式言語コア

`ravel-core` に置く（UI を持たず、フィールドとチャネルの両方から使う）。

- 字句・構文・AST。**ループ・代入・関数定義を持たない**（REQ-INFRA-007 の段 0）
- 演算子: 算術・比較・論理・三項（条件）
- 組み込み関数: 三角、`exp` / `log` / `pow` / `sqrt` / `abs` / `floor` /
  `ceil` / `round` / `min` / `max` / `clamp` / `mix` / `smoothstep` / `noise`
- **全域性**: 各関数がすべての入力で値を返す。テストで網羅する
- 変数解決は「宣言された名前集合」に対して行い、未定義名はコンパイルエラー
- 定数畳み込み（`2 * pi` のような部分式を評価前に潰す）
- **依存抽出**: 式が参照する変数名・属性名の集合を返す
- エラーはソース内の位置（行・列・範囲）を持つ

**完了条件**

- 演算子と全組み込み関数の値テスト
- **全域性のテスト**: 定義域外入力（`sqrt(-1)`、`1/0`、`log(0)`、
  `pow(-1, 0.5)`）が panic せず値を返す
- 未定義変数がコンパイルエラーになり、位置が正しい
- 構文エラーの位置が正しい（開き括弧の不一致、不完全な式、不正なトークン）
- 依存抽出が参照集合を正しく返す（重複なし、未参照を含まない）
- 定数畳み込みが結果を変えない（畳み込み前後の値一致テスト）
- ループを書く構文が存在しない（パーサがそれを受理しないテスト）

### EXPR-2 パラメータ式の配線

- `ExpressionPlaceholder` を、ソース文字列 + コンパイル済み表現を持つ型に
  置き換える。**永続化はソース文字列のみ**（既存の `.ravprj` が往復する）
- 変数集合は `EvalContext` 由来（`frame` / `time` / `fps` / 解像度 /
  コンプ解像度）+ 定数（`pi` / `e`）
- `ChannelSource::evaluate` で評価し、**有限でない結果を既定値に落とす**
- コンパイル失敗した式は評価に使わず既定値を返す

**完了条件**

- `frame` / `time` / `fps` / 解像度が式から読める
- `amplitude * sin(frame * frequency + phase)` 相当が期待値を返す
- サブフレーム位置（モーションブラー・タイムリマップ）で連続的に評価される
- 不正な式が既定値を返し、評価が失敗しない
- NaN / 無限を返す式が既定値に落ちる
- 式ソースが `.ravprj` に往復する（既存フォーマットのまま）
- **`ChannelSource::evaluate` のシグネチャが変わらない**
- `Blend` で式と他ソースを合成できる

### EXPR-3 キャッシュキーと dirty 伝播への統合

**この単位を飛ばすと「式を変えても絵が変わらない」形で静かに壊れる。**

- `CacheIdentity` に式ソースのハッシュと参照集合を含める
- 式の編集が下流を dirty にする
- 式が `frame` を参照するかどうかで時不変判定を分ける（`frame` を
  参照しない式は時間軸で再評価しなくてよい）

**完了条件**

- 式を書き換えた後の評価が新しい値を返す（キャッシュを踏み抜かない）テスト
- `frame` を参照しない式が時間軸のキャッシュ再利用に乗るテスト
- `frame` を参照する式がフレームごとに再評価されるテスト
- 式の編集が下流ノードを dirty にするテスト

### EXPR-4 Properties の式入力 UI

- パラメータ行から式に切り替える操作と、式が付いているバッジ表示
- 編集中の構文エラーを位置付きで表示する
- 式を外して定数・キーフレームに戻す操作
- ロケール文字列（`t!` 経由）

**完了条件**

- 式の設定・編集・解除ができる
- 構文エラーが編集中に表示され、確定を妨げない（保存はできるが評価されない）
- 式が付いたパラメータが一覧で判別できる
- `assets/locales/{en,ja}.toml` にキーが揃っている

### EXPR-5 フィールド式

- `ExpressionField` をコンパイル済み表現を持つ型にする
- `sample()` でコンパイル済み AST を位置配列に対して回す
- 変数は `EvalContext` 由来 + 位置（`P` の成分）
- `field.expression` の登録を実装済みのものに差し替える

**完了条件**

- 位置に依存する式が要素ごとに正しい値を返す
- 他のフィールドと合成（`field.add` / `field.multiply` / `field.max`）できる
- **要素数に対して線形**であることの測定（1e3 / 1e4 / 1e5 要素で計測し
  `perf-baseline.md` に記録）
- 要素の順序に依存しない（順序を入れ替えて同一結果）
- 1 回のサンプルで式のパースが起きない（コンパイル済みを使う）テスト

### EXPR-6 属性アクセス（`@attr` 相当）

REQ-CORE-010 の受入条件「式から属性値を参照できる」を回収する。

- 属性名を式から参照する構文
- 参照する属性名を依存抽出が返す（存在しない属性はコンパイル時に
  判定できないので、サンプル時に既定値へフォールバックし警告する）
- ドメイン（point / primitive / instance）の扱いを決める

**完了条件**

- 標準属性（`P` / `index` / 法線 / 色）と任意名の属性を参照できる
- 存在しない属性が既定値になり、フィールド単位の警告が出る
- ドメイン不一致が明示的に扱われる（暗黙の昇格をしない、または
  昇格規則が文書化されている）

### EXPR-7 文書更新

- `REQ-CORE-007` / `-010` / `-012` / `REQ-MOGRAPH-001` の受入条件を埋める
- `docs/dev/` に式の書き方ページ（組み込み関数一覧・変数一覧）
- `docs/agent-api-reference.md` に式言語の公開 API
- `docs/ui-impl-status.md` の Properties 欄

## 検証

- EXPR-1〜3、5、6 はヘッドレス（`ravel-core`）
- EXPR-4 は実機
- **全域性が本計画の安全弁。** 定義域外入力のテストを網羅し、
  「評価中に失敗しうる経路が無い」ことを担保する
- **決定性**: 同一式・同一フレームで 2 回評価して一致すること。
  `noise` は座標から決定的に導出し、乱数状態を持たない

## 非対象

- **Lua**（REQ-PLUGIN-003 / REQ-CODE-001 のコード Layer）。別計画
- **ベクトル・色を返す式**。v1 はスカラーのみ。ベクトルは成分ごとに
  式を置く（`Channel2` / `Channel3` は成分ごとにチャネルを持つので成立する）
- **式から他ノードを参照する構文**。`ChannelSource::NodeOutput` が担う
- **ユーザー定義関数・変数**。式の再利用は将来の判断
- **オーディオリアクティブ変数**（`ChannelSource::AudioReactive` が別途担う）
- **式の GPU 評価**。AST を持つので道は閉じないが、REQ-INFRA-009 の後
- `field.expression` が黙って既定値を返す現状の起票。本計画が直すので
  `issues/` には起こさない
