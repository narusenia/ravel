# ジオメトリ破砕（Cell Fracture） 実装計画

> **Status**: Planned — 2026-07-29

対象: 形状を Voronoi セルで破片に分割する。Blender の Cell Fracture 相当。
関連要件: REQ-CORE-010、REQ-MOGRAPH-001、REQ-3D-003。

## 問題

形状を「割る」手段が無い。文字が砕けて飛び散る、板が破片になって崩れる、
といったモーショングラフィックスの定番表現が組めない。

破片を個別に動かす下流は既に計画がある。

| 必要なもの | 状況 |
|---|---|
| 破片ごとの反復 | `evaluation-scope-plan.md` の `SCOPE-3`（`geometry.iterate`。`piece` 属性で分割） |
| 破片ごとの変換 | `geometry-ops-plan.md` の `OPS-7`（`geometry.repeat`）、`field.apply` |
| 破片の削除・並べ替え | `OPS-1` / `OPS-2` |

**入口だけが無い。** 破砕が `piece` 属性付きのジオメトリを出せば、
下流はすべて既存計画の資産で足りる。

## 決定事項（2026-07-29 設計セッション）

### boolean には依存しない

**Voronoi セルは凸**である。この性質があるので、汎用のポリゴンブーリアンを
使わずに厳密な破砕が書ける。

```text
シード点から各セルの半平面集合を作る
  （セル i = シード i と他の全シード j の垂直二等分線による半平面の交差）
元の形を三角形分割する
  → 各三角形を各セルの半平面で順に切る
      三角形は凸・クリップ領域は凸 → Sutherland–Hodgman が厳密
  → piece ごとに三角形集合ができる
  → 境界を抽出（1 回しか現れない辺を辿る）→ piece ごとに閉パス
      穴も別ループとして自然に出る
```

**先に三角形分割するのが要点。** Sutherland–Hodgman が壊れるのは被写体が凹の
ときだけで、三角形はすべて凸なのでアーティファクト（面積ゼロの橋）が原理的に
出ない。境界抽出は辺のカウントで O(E)、これも厳密。

したがって **`path-ops-plan.md` の `PATH-0a`（ブーリアンの方針判断）に
道連れにされない**。`PATH-0a` がクレート採用を却下しても破砕は作れる。

ただし三角形分割器は必要なので、**`PATH-0b`（三角形分割器の採用判断）には
依存する**。`PATH-0b` は「クレート採用」か「自前実装」のどちらかで
見送りが無いため、破砕が宙に浮くことはない。

Voronoi セル自体も Delaunay 三角形分割を必要としない。セルを半平面の交差
として直接構成すれば O(n²) だが、破砕のシード数（数十〜数百）では問題ない。

### 三角形分割器は共有基盤

三角形分割は**回避できない**。しかも破砕専用ではない。

| 使う側 | 用途 |
|---|---|
| 本計画（`FRAC-2`） | 破砕の既定経路 |
| `3d-scene-plan.md` 単位 8 | 押し出しの前面 / 背面キャップ（穴あき多角形を埋める） |

`earcut` クレート採用か自前実装かの判断は **`PATH-0b`** で決着した
（2026-08-06、`path-ops-plan.md` に調査結果と根拠がある）。**`earcut` を採用する**
— 毎フレーム評価される経路で内部バッファを再利用でき、出力が `Vec<u32>` なので
`Primitive::Mesh` の索引表現とそのまま噛み合う。

### アルゴリズムは選択式。既定は依存なしで固定する

`algorithm` パラメータで経路を選べるようにする。

| 値 | 内容 | 依存 |
|---|---|---|
| `triangulate_clip`（**既定**） | 三角形分割 + 半平面クリップ | 三角形分割器のみ |
| `boolean` | 汎用ポリゴンブーリアンでセルと交差 | Cargo feature（`PATH-1` 由来） |

規約を 2 つ置く。

- **既定値は今後変えない。** アルゴリズムを変えると出力頂点が変わるため、
  既定を変更すると既存プロジェクトの描画が変わる。より良い経路が入っても
  新規ノードで選んでもらう
- **使えない選択は明示エラー。** feature が無いビルドで `boolean` を選んで
  いたら評価エラーにし、**黙って既定へフォールバックしない**。フォールバック
  すると同じファイルがビルドによって違う絵になり、書き出しとプレビューで
  結果が食い違う

feature の有無に応じた選択肢の列挙は、`render-export-plan.md` の `EXPORT-1`
（エンコーダの実行時列挙）と同じ問題。レジストリの `param_options` は静的
なので、**機構を共有する**。

### 2D と 3D は variant を分ける

破砕はアルゴリズムが本質的に分岐する（2D = ポリゴンのクリップ、
3D = メッシュの平面 bisect）ので、仕様書の 2D/3D 命名規約に従って分ける。

| | ラベル | type_key |
|---|---|---|
| 2D | `Cell Fracture` | `geometry.cell_fracture` |
| 3D | `Cell Fracture 3D` | `geometry.cell_fracture_3d` |

3D 側は**面積ゼロの橋の問題が無い**（平面でメッシュを切る操作は凹メッシュでも
正しい）。あの制約は 2D のポリゴンクリップ固有。

### 破片は `piece` 属性で表す

`piece`（I32、Primitive ドメイン）は `evaluation-scope-plan.md` が
`geometry.iterate` の既定分割属性として予約している。

**ただし `geometry/names.rs` に定数がまだ無い**（`procedural-geometry.md` の
記述だけが存在する）。`SCOPE-3`（`geometry.iterate`）と本計画の単位 2 の
どちらも `piece` を必要とするので、**先に着手した方が定数を追加する**。
`geometry-ops-plan.md` の `OPS-10`（文書）は仕様書への追記を担当するが、
定数追加は担当していない。

元の属性は破片へ転送する。点は新設されるため 1 対 1 対応しないので、
**最近傍から転送**（既存の `ops.rs` の `nearest_index` / `attribute_transfer`
と同じ規約）。primitive 属性と Detail は元の値を引き継ぐ。

### 物理シミュレーションは対象外

破砕は**形状操作**であり、破片が落ちる・跳ねるは扱わない（REQ-3D の非対象）。
破片を動かすのは `field.apply` と `geometry.iterate` の仕事。

## 実装単位

### 単位 1: 多角形の三角形分割器（`FRAC-1`）

**依存**: `PATH-0b`（三角形分割器の採用判断）

- 穴あき多角形を三角形に分割する。穴はブリッジ挿入で扱う
- 入力は平坦化済みポリライン（`flatten.rs` の `FLATTEN_TOLERANCE = 0.25px`
  を共有する）
- 出力は頂点インデックス列。`Primitive::Mesh` の形と一致させる
- 毎フレーム評価されるのでバッファを再利用する

**完了条件**

- 凸多角形・凹多角形・穴あき多角形の三角形数が期待どおりになるテスト
- 全三角形の面積の和が元の多角形の面積と一致するテスト（符号付き）
- 退化入力（頂点 2 個以下、面積ゼロ、重複頂点、自己交差）でパニックしない
  テスト
- 決定性テスト（同一入力で 2 回実行して一致）

### 単位 2: `geometry.cell_fracture`（2D）

**依存**: 単位 1

- シード点の与え方: 入力ジオメトリの点を使う / 乱数（`seed` パラメータ）/
  別のジオメトリ入力
- 各セルを半平面集合として構成し、三角形をクリップして piece を作る
- 境界抽出（1 回しか現れない辺を辿る）で piece ごとに閉パスを出す
- `piece` 属性を書き、元の属性を最近傍転送する
- `algorithm` パラメータ（既定 `triangulate_clip`）

**完了条件**

- シード数と piece 数が一致するテスト（形状の外に落ちるセルを除く）
- 全 piece の面積の和が元の面積と一致するテスト
- **凹形状（`L` 字）で piece が正しく分離される**テスト（面積ゼロの橋で
  繋がっていないことを、piece ごとの連結性で確認する）
- 穴あき形状（`o`）で穴が保存されるテスト
- 属性（`Cd` / `pscale`）が破片へ転送されるテスト
- 決定性テスト（`seed` 固定で 2 回評価して一致）
- シード 1 個で元の形状がそのまま 1 piece になるテスト
- `geometry.iterate` と繋いで piece ごとに変換できる結合テスト

### 単位 3: `geometry.cell_fracture_3d`

**依存**: 単位 1、`3d-scene-plan.md` 単位 1a / 1b（`P` の次元と `Primitive::Mesh`）

- 3D の Voronoi セルを半空間集合として構成する
- Mesh を平面で bisect する操作を繰り返して piece を作る
- 切断面に新しい面を張る（キャップ）。**単位 1 の三角形分割を使う**
- 切断面の法線 `N` を書く
- `piece` 属性、属性の最近傍転送

**完了条件**

- 立方体を 2 平面で切って 4 piece になるテスト
- 全 piece の体積の和が元の体積と一致するテスト
- 切断面が閉じている（水密である）ことのテスト
- 切断面の `N` が外向きであるテスト
- **凹メッシュで正しく分割される**テスト（2D の橋の問題が無いことの pin）
- 決定性テスト

### 単位 4: アルゴリズム選択式と実行時列挙（`FRAC-4`）

**依存**: 単位 2、`PATH-1`（ブーリアン本体）

- `algorithm` の選択肢を feature の有無に応じて実行時列挙する
- 使えない選択が保存されていた場合の評価エラー（メッセージに feature 名を
  含める）
- Properties の Select が実行時の選択肢を反映する

**完了条件**

- feature 無しビルドで `boolean` が選択肢に出ないテスト
- feature 無しビルドで `boolean` を保存したファイルを開くと評価エラーになる
  テスト（**黙ってフォールバックしない**ことの pin）
- 両経路の出力が同じ piece 数・同じ総面積になるテスト（頂点列の一致は
  要求しない）

### 単位 5: レジストリ / ロケール / 文書

- テンプレート登録、パラメータ範囲、`algorithm` の選択肢
- `assets/locales/{en,ja}.toml`
- `docs/specifications/procedural-geometry.md` に `piece` の記述と
  2D/3D 命名の実例を追記
- REQ の受入条件を更新

## 検証

- `mise run check`
- 全単位 headless（`ravel-core` / `ravel-nodes`）。GPU 不要
- **面積 / 体積の保存**を中心に据える。ゴールデン画像より数値検証が
  破砕の正しさを直接示す
- 決定性は全単位で確認する（`seed` 固定で 2 回評価）

## 非対象

- **物理シミュレーション**（破片の落下・衝突）。REQ-3D の非対象
- **再帰破砕**（破片をさらに破砕）。`geometry.iterate` の入れ子が
  1 段に制限されているため（`procedural-geometry.md`）。破砕ノードを
  直列に繋げば 2 段は作れる
- **不均一な破砕パターン**（ガラスの放射状クラック等）。シード点の配置で
  近いことはできるが、専用のクラック生成は別スコープ
- **Mesh 同士のブーリアン**（`mesh.boolean`）。破砕は半平面クリップで足りる
- **破片の厚み付け**（2D の破片を 3D 化）。`3d-scene-plan.md` の押し出しを
  破砕結果に適用すれば済む
