# ノードの発見性と説明 実装計画

> **Status**: Planned — 2026-07-30

対象: ノードが「何をするものか」を製品内で知れるようにする。ホバー時の詳細
Popover、ノード検索パレット、ノードのラベル・説明・パラメータ説明の
ロケール化。関連要件: REQ-UI-002（ノードグラフエディタ）、REQ-UI-006、
REQ-CORE-002。

## 問題

### 1. ノードの説明がどこにも無い

`NodeTemplate`（`crates/ravel-core/src/registry/mod.rs:64-78`）は
`type_key` / `label` / `category` / ポート / パラメータ既定値 / 範囲 /
選択肢を持つが、**説明文のフィールドが無い**。ノードエディタが描くのは
`node.metadata.label` かフォールバックの `type_key`
（`node_editor/painting.rs:486`）だけ。

つまり `field.noise` が何をするノードなのかを製品内で知る手段が無い。
組み込みテンプレートは 42 個あり、Houdini の i ボタンに相当するものが無い。

### 2. ラベルが英語のハードコードで、ロケールキーが無い

`NodeTemplate::new("field.noise", "Noise Field", ...)` のように **`label` は
英語リテラル**で、`assets/locales/*.toml` に `node.*` のキーは 1 つも無い。
`ja.toml` は 235 キーを維持しているのに、ノード名だけ英語のまま残る。

これは `LOW-APP-11`（ハードコードされたユーザー向け英語）と同じ層の問題で、
`roadmap.md` はフェーズ C（`SET-1` で日本語が到達可能になった後）に置いている。
**説明文を足すときに同じ場所を触るので、一緒にキー化する。**

### 3. ノード検索パレットが仕様にあって実装が無い

`docs/specifications/ui-spec.md` は「Tab 押下またはキャンバスダブルクリックで
検索パレット」「インクリメンタル検索」「カテゴリ別フィルタ」「最近使用した
ノードを優先」「ドラッグ中のワイヤーから発動した場合は接続可能な型のみ」を
書いているが、**実装は右クリックのコンテキストメニューだけ**。`CommandId` に
パレットは存在しない。

検索は「ノード名 + 説明文」を対象にできると効くので、説明文のキー化と同じ
計画で扱う。

## 決定事項

### 説明文はロケールに置き、`label` もキーへ移す

`NodeTemplate` に英語の説明文フィールドを増やす方式は採らない。
ロケールに寄せる。

```toml
# assets/locales/ja.toml
[node."field.noise"]
label = "ノイズフィールド"
description = "座標に対して値を返す場を生成する。……"

[node."field.noise".params]
frequency = "繰り返しの細かさ"
amplitude = "値の振れ幅"
```

- `NodeTemplate.label` は**ロケールキーの解決結果**を返す形にする。
  キーが無いときは `type_key` にフォールバックする（新しいノードを足した
  瞬間にビルドが壊れない）
- 説明とパラメータ説明は任意。無ければ Popover のその節を出さない
- コア層（`ravel-core`）はロケールを知らない。**キーの解決は UI 側**
  （`ravel-i18n` の `t!` を使えるのは `ravel-ui` / `ravel-app`）。
  `NodeTemplate` はキーの材料（`type_key`）だけ持つ

### Popover はホバー滞留で自動的に出し、ジェスチャー中は出さない

- 約 500ms の滞留で表示。ノード移動・接続ドラッグ・矩形選択の最中は出さない
- `i` ボタンをノードに描く方式は採らない — ノード上のクリック領域を増やすと
  ポートのヒットテスト（`HIGH-22` で z 順を直した箇所）と競合する
- 内容: ラベル / カテゴリ / 説明 / 入出力ポート（名前 + 型）/
  パラメータ（名前 + 説明 + 現在値）
- 評価時間は既にノード下に描かれているので Popover では繰り返さない

### 検索パレットは既存のコンテキストメニューを置き換えない

パレットは追加の入口であり、右クリックからのノード追加は残す。パレットが
使う候補列挙・生成・配線の経路は既存のものを共有する（2 つ目の生成経路を
作らない）。

## 実装単位

### DISC-1: ノードのロケールキー化

- `assets/locales/en.toml` / `ja.toml` に `node.<type_key>` の
  `label` / `description` / `params.<name>` を追加（組み込み 42 個）
- UI 側でキーを解決するヘルパを 1 箇所に置き、ノードエディタ・Properties・
  Outliner がそれを使う
- キー欠落時は `type_key` フォールバック
- `NodeTemplate` の英語 `label` リテラルの扱いを決める（キーがある型では
  UI がリテラルを使わない）

**完了条件**

- 42 個すべてに en / ja の label があるテスト（レジストリを走査して
  キー欠落を検出する）
- 未知の `type_key` でフォールバックが働くテスト
- コア層がロケールに依存していないこと（`ravel-core` の依存に
  `ravel-i18n` が入らない）

### DISC-2: ホバー Popover

- ノードのホバー滞留で Popover を表示。ジェスチャー中は抑制
- 内容は上記「決定事項」のとおり
- パラメータ現在値は表示中のフレームでの値（アニメーション中は追従する）
- 描画は gpui-component の Popover を使う（自前のフローティング層を作らない）

**依存**: `DISC-1`

**完了条件**

- 滞留前に出ない・ジェスチャー中に出ないテスト
- 説明が無いノードで説明の節が出ないテスト
- 表示中に再評価が走らないこと（Popover が評価要求を出さない）
- キーボードだけでも同じ情報に到達できること（選択中ノードの説明が
  Properties にも出る）

### DISC-3: ノード検索パレット

- Tab / キャンバスダブルクリックで表示
- インクリメンタル検索の対象は label と description（ロケール解決後の文字列）
- カテゴリフィルタ、最近使用したノードの優先表示
- ワイヤードラッグから発動した場合は接続可能な型のみを候補にする
- 生成・配線は既存のコンテキストメニューと同じ経路

**依存**: `DISC-1`

**完了条件**

- 日本語ロケールで日本語の語句で検索できるテスト
- 型フィルタが接続不能なノードを候補から外すテスト
- 候補選択からの生成が既存経路と同じ Document 変更になるテスト（1 undo）
- パレットを閉じても状態が残らないこと

### DISC-4: 文書

- `docs/specifications/ui-spec.md` のノードグラフ節を実装に合わせる
  （検索パレットの記述はこの単位で初めて正しくなる）
- `docs/ui-impl-status.md` の NodeEditor 表を更新
- REQ-UI-002 の受入条件に Popover とパレットを追加

**完了条件**

- 3 文書が実装と一致していること
- 未実装項目を実装済みとして書いていないこと

## 検証

- `mise run check`
- ロケールキーの網羅はレジストリ走査のテストで機械的に確認する
- 検索の絞り込みは純粋関数の単体テスト
- GPUI テストは Popover の表示抑制とパレットの入力経路に限る

## 非対象

- **ユーザー定義ノードの説明**。REQ-CODE-001（スクリプト）待ち
- **オンラインヘルプ / 外部ドキュメントへのリンク**。製品内で完結させる
- **ノードのプリセット保存**（REQ-UI-002 のテンプレート機能）。発見性とは
  別の機能なので混ぜない
- **`LOW-APP-11` の全体解消**。本計画が回収するのはノード名・説明・
  パラメータ名の層だけ。他のハードコード英語は issue 側に残る
