# ノードグラフの可読性 実装計画

> **Status**: Planned — 2026-08-08

対象: `ravel-core` の `NodeMetadata::position`、`ravel-project` の
`SettingsLayer`、`ravel-app` のノードエディタ（`node_editor/` と
`panels/node_editor.rs`）。要件は `REQ-UI-002` / `REQ-UI-003` の周辺（操作系）。

**リリース前に入れるのは自動整列と設定の 2 つだけ。** 上→下フローモード、
Reroute、エッジ間挿入、型によるエッジ配色はリリース後に送る。
その線引きの根拠は各単位に書いた。

## 問題

### 1. レイアウトが崩れたときに直す手段が手作業しかない

Subnet の collapse / extract、ノードの挟み込み、ネットワーク境界の
生成後は、ノードが重なるか離れすぎるかのどちらかになる。
直すには 1 個ずつドラッグするしかない。`NETIF-6` の後始末として挙がっていた
話で、ノード数が増えるほど直す気が失せる。

### 2. エッジスタイルがどこにも保存されていない

`EdgeStyle`（`crates/ravel-app/src/node_editor/mod.rs:12`。`Bezier` /
`Straight` / `Step`）は **`NodeEditorPanel` のパネルローカル状態**として
持たれている:

- 宣言 — `crates/ravel-app/src/panels/node_editor.rs:673`
- 初期化 — 同 `:783`、`EdgeStyle::default()`
- 変更 — 同 `:3398` / `:3408` / `:3418`（コンテキストメニュー）

**`.ravprj` にも設定ファイルにも UI 状態にも入っていない。** パネルを
作り直すたびに黙って既定（`Bezier`）へ戻る。ユーザーが選んだのに
消えるので、機能があること自体が信用されない。

### 3. 横方向レイアウト固定で、縦に伸びるグラフが読めない

ポートの描画位置は左が入力・右が出力に固定されている。Houdini に慣れた
使い方（上から下へ流す）ができない。

### 4. 配線が交差したときに逃がす手段が無い

Reroute が無いのでエッジは端点間を直接結ぶしかなく、ノードが増えると
束になって交差する。

### 5. エッジが一色で、何が流れているか分からない

ポートの色は型で決まっている（`node_editor/port_colors.rs`）のに、
**エッジは一色**。型の情報を持っているのに描画に反映していない。

## 決定事項

### 自動整列は手動コマンド。自動で走らせない

Houdini の L キーと同じで、**選択範囲またはネットワーク全体を明示的に
整列する**。ノードの追加・削除・collapse に反応して自動で走らせない。

理由は所有権にある。**ノード位置は `NodeMetadata::position`
（`crates/ravel-core/src/graph.rs:374`）に保存される**ので、整列は
表示の調整ではなく**保存データの書き換え**である。ユーザーが意図して
置いた位置を、こちらの都合で黙って動かしてよい根拠が無い。

### 整列は undo に乗る

上記のとおり保存データを書き換えるので、**取り消せなければならない**。
既存のノード移動と同じ経路に乗せる — ドラッグ終了時の
`commit_graph`（`crates/ravel-app/src/panels/node_editor.rs:2979-2981`）が
1 ジェスチャー 1 undo の単位なので、整列も**1 コマンド 1 `commit_graph`**に
する。新しい undo 経路を作らない。

### 上→下フローモードは表示の設定。保存形式は変えない

切り替えで変わるのは 2 つだけ:

- **ポートの描画位置** — 入力が上、出力が下
- **自動整列の軸** — 層を縦に積む

`NodeMetadata::position` の意味（ネットワーク座標系の点）は変わらないので、
`.ravprj` のフォーマットは上げない。**既存グラフは切り替えた後に一度整列を
押せば収まる。** 切り替え時に自動で整列しないのは上の決定と同じ理由。

### エッジスタイルとフロー方向は `SettingsLayer` の `node_editor` 節に置く

`crates/ravel-project/src/settings.rs:240` の `SettingsLayer` に
**`node_editor` 節を新設**し、`edge_style` と `flow_direction` を置く。
既存の 4 層マージ（`default → global → project → user`。同 `:270` の
`merge_all`）にそのまま乗る。

**パネルローカル状態にも `ui_state.json` にも置かない。** どちらも
「このマシンのこのウィンドウ」の話になるが、エッジスタイルとフロー方向は
**人の好み**であって、プロジェクトを開き直しても、別のプロジェクトを
開いても同じであってほしい。global 層はそれを表せる唯一の場所。

**この節はエッジスタイルの取りこぼし（問題 2）を同時に塞ぐ。**

### `edge_style` と `flow_direction` は同じ節だが、入る時期が違う

`node_editor` 節はリリース前に `edge_style` だけを持って入る。
**`flow_direction` はフローモード本体（`NGR-5`）と同時に入る。**

理由は `settings-screen-plan.md` の統治規則
（「設定ダイアログに項目が出るのは、その設定が挙動を変えるときだけ」）。
フローモードが未実装のうちに `flow_direction` を置くと、
**何も変えない死んだ設定**が 1 つ増える。節の追加は 1 回で済むので、
キーを 1 つ後から足すことに費用は無い。

## 実装単位

| ID | 単位 | 依存 | 時期 |
|---|---|---|---|
| NGR-1 | 自動整列の計算（ヘッドレス） | — | リリース前 |
| NGR-2 | 整列コマンドと undo | NGR-1 | リリース前 |
| NGR-3 | `SettingsLayer` の `node_editor` 節と `edge_style` の永続化 | — | リリース前 |
| NGR-4 | 型によるエッジ配色 | — | リリース後 |
| NGR-5 | 上→下フローモード（描画・整列軸・`flow_direction`） | NGR-1, NGR-3 | リリース後 |
| NGR-6 | Reroute ノード | — | リリース後 |
| NGR-7 | エッジへのドロップでノードを挟む | — | リリース後 |
| NGR-8 | ロケール / 文書 | NGR-2〜7 | 随時 |

### 単位 1: 自動整列の計算（ヘッドレス）

- 入力は「グラフ + 対象 `NodeId` の集合 + ノードごとの寸法 + 軸」、
  出力は「`NodeId` → 新しい位置」。**`Graph` を書き換えない純粋関数**にする
- 層割りは DAG の深さ。**評価器の既存の走査に相乗りしない**
  （整列は編集時の一回きりで、評価の hot path とは別の都合）
- ノードの寸法は呼び出し側が渡す。描画側の
  `BASE_NODE_WIDTH`（`node_editor/painting.rs:41`）と行数から出るので、
  計算側が GPUI を知る必要が無い
- 軸（横 / 縦）は引数。`NGR-5` はここに縦を渡すだけになる

置き場所は **`ravel-app` の `node_editor/`**。`ALIGN-1`（レイヤーの整列・分布）が
`ravel-ui` の headless 側にあるのと非対称に見えるが、こちらはノードの**描画
寸法**を前提にする計算で、寸法を知っているのは `ravel-app` だけ。

**完了条件**

- 同じグラフに 2 回かけて同じ結果になる（決定的）
- 出力に重なりが無い（矩形が交差しない）ことのテスト
- 選択が空のときは全ノード、部分選択のときはその集合だけが動く
- 循環の無い DAG 前提を破らない（`Graph` は DAG なので入力側で保証される）

### 単位 2: 整列コマンドと undo

- コマンドを 1 つ足す。**選択が空ならネットワーク全体、選択があればその範囲**
- 適用は `commit_graph` 1 回。**1 コマンド 1 undo**
- キーバインドを `assets/keybindings/` に足す。既存割り当てとの衝突を確認する
- **自動では絶対に走らせない。** collapse / extract / ノード追加のいずれの
  経路からも呼ばない

**完了条件**

- 整列後に undo 1 回で元の全位置に戻る
- 部分選択の整列が、選択外のノードを 1 つも動かさない
- Subnet を collapse した直後に整列を押すと重なりが解消する
- キーバインドが ja / en 両方の資産に入っている

### 単位 3: `SettingsLayer` の `node_editor` 節と `edge_style` の永続化

- `SettingsLayer` に `node_editor: NodeEditorLayer` を足し、
  `edge_style: Option<EdgeStyle>` を持たせる。`merge` に 1 行足す
- `EdgeStyle` は現在 `ravel-app` にある。**設定に載せるには
  `ravel-project` から見える場所へ移す**必要がある。`ravel-project` は
  `ravel-core` と `ravel-ui` にしか依存しないので、**移し先は `ravel-ui`**
- パネルは起動時に解決済み設定から読み、コンテキストメニューでの変更を
  設定へ書き戻す
- **設定ダイアログへの露出は `settings-screen-plan.md` の `SET-*`** に
  乗せる。この単位は値の所在と適用経路だけを持つ

**完了条件**

- コンテキストメニューで選んだスタイルが、パネルを閉じて開き直しても残る
- アプリを再起動しても残る
- 設定ファイルが無い状態で `Bezier` になる（既定が現在の挙動と一致）
- 層マージのテスト（global で `Step`、project で未指定 → `Step`）

### 単位 4: 型によるエッジ配色

ポートの色は `node_editor/port_colors.rs` が型から決めている。**同じ関数を
エッジにも使う。**新しい配色表を作らない（`DISC-5` のカテゴリ配色と
2 つの真実を持たない）。

- 色は**出力側ポートの型**から取る（入力側は暗黙変換で異なりうる）
- 選択中・ホバー中のエッジのハイライトは型色に優先する

**完了条件**

- 型の違うエッジが違う色で描かれる
- ポートの色とエッジの色が一致する
- ハイライト表示が型色に潰されない

### 単位 5: 上→下フローモード

- `NodeEditorLayer` に `flow_direction` を足す（`Horizontal` / `Vertical`。
  既定 `Horizontal`）
- ポートの描画位置とヒットテストを軸で分ける。**`painting.rs` の
  ポート座標計算 1 箇所に軸を通す**のであって、描画経路を 2 本作らない
- 整列は `NGR-1` に縦軸を渡すだけ
- **切り替え時に自動整列しない。** 既存グラフは一度整列を押せば収まる、と
  文書に書く

**完了条件**

- 縦モードで入力が上・出力が下に描かれ、ヒットテストが一致する
- エッジの 3 スタイルが縦モードでも破綻しない（`Step` の折れ方が軸に従う）
- 縦モードで整列を押すと層が縦に積まれる
- 設定が再起動をまたいで残る

### 単位 6: Reroute ノード

配線の折り返し点。**見た目は小さく**（ポート名も値も描かない点だけの表示）。

- 型は入力の型をそのまま通す。**専用の処理は持たない**（評価では
  パススルー）
- 既存の bypass 経路に相乗りできるかを着手時に確かめる。できるなら
  ノード種別を 1 つ足すだけで済む

**完了条件**

- エッジ上に Reroute を作れて、両側の接続が保たれる
- 評価結果が Reroute の有無で変わらない
- 削除すると両側が直結に戻る

### 単位 7: エッジへのドロップでノードを挟む

エッジの上にノードをドロップすると、そのエッジを切って前後に繋ぎ直す。

- 対象は**型が通る場合だけ**。通らないときは挟まずに、ドロップ位置へ
  ただ置く（黙って失敗しない）
- 繋ぎ直しは**1 undo**
- ノード検索パレットからの追加（`MED-APP-27` の経路）でも同じ挙動にする

**完了条件**

- 挟んだ後に上流 → 新ノード → 下流の順で繋がっている
- 1 undo で元のエッジに戻る
- 型が通らないノードを落としても既存の接続が壊れない

### 単位 8: ロケール / 文書

**完了条件**

- 追加した文言とキーバインドが ja / en 揃っている
- `docs/specifications/ui/` のノードエディタの記述が追随
- `docs/ui-impl-status.md` が更新されている
- `docs/dev/` の設定変更の手順が `node_editor` 節を含む

## 非対象

- **自動でのレイアウト維持**（ノードを足すたびに整列し直す）。上記のとおり
  ユーザーの置いた位置を黙って動かさない
- **レイアウトアルゴリズムの選択式**（Sugiyama / force-directed の切り替え）。
  1 つで足りないと分かってから
- **ノードの折り畳み表示 / グループ枠。** 別の問題（画面占有）で、
  `PGRP-5`（パラメータ値表示トグル）が先に効くかを見てから判断する
- **エッジのラベル表示。** 配色（`NGR-4`）で足りるかを先に見る
