# ワークフロー貫通の UX 洗い出しと改善 実装計画

> **Status**: `UX-4`〜`UX-8` / `UX-11` 実装済み（#351 / #355 / #356 / #357 / #353 / #352）、
> 残るは `UX-1`〜`UX-3`（計器と測定）と `UX-9` / `UX-10` / `UX-12` — 2026-08-10

対象: `ravel-ui` の Timeline / Properties モデルとノード検索、`ravel-app` の
Timeline・Outliner・MediaBin・Viewer・ノードエディタの各パネル、
`ravel-project` の設定層。要件は `REQ-UI-002`〜`REQ-UI-004`、`REQ-UI-013`
の周辺（操作系）。**リリース前に片を付ける UX の枠**であり、
ノードグラフの可読性は `node-graph-readability-plan.md`、Wrangle と
ユーザー定義パラメータは `wrangle-plan.md` が持つ。この計画書はそれらを含まない。

## 問題

### 1. 平坦な要望リストは「ごちゃついている」に届かない

2026-08-08 の実機セッションで 47 件が挙がり、機能要望 23 件は
`backlog.md` の「実機フィードバック由来の機能要望」へ並んだ
（棚卸しの記録は `hands-on-findings-handoff.md`）。

**同じ形のリストをもう 1 枚増やしても、体感の主因には届かない。**
1 件ずつは正しいが、どれも「この画面のこの操作が足りない」という
パネル単位の指摘で、**1 つの目的を遂げるまでに何回パネルを渡り歩くか**を
誰も数えていない。ごちゃつきの正体はそこにある可能性が高いのに、
今のリストの粒度ではそれが見えない。

### 2. 同じ情報が複数のパネルに散っていて、どこが正か決まっていない

レイヤーの時間配置は Timeline とプロパティの両方に出る。素材は MediaBin と
Outliner とプロパティに出る。キーフレームは Timeline とカーブエディタに出る。
**「この情報はどのパネルが持っているか」を書いた表が 1 枚も無い。**
表が無いので、新しい情報を足すときの置き場所も毎回その場で決まる。

### 3. 直したかどうかを測る尺度が無い

「使いやすくなった」を確かめる手段が無いと、修正の効果は主観でしか語れない。
効果が測れないものは優先順位も付かない。

## 決定事項

### 洗い出しの軸は「ワークフロー貫通」であって、パネルごとの棚卸しではない

パネルごとに見ると、既にある 47 件と同じ形のリストがもう 1 枚できる。
**ワークフローを 1 本通して、その間に起きたことを記録する。**
パネル単位では見えない「往復」は、貫通させて初めて数えられる。

### 問題と見なす基準は「往復回数」と「探し直しの回数」

- **往復回数** — 1 つの目的を遂げるのに、パネルの間を何回行き来したか
- **探し直しの回数** — 同じ情報を 2 箇所以上で探したか

**数えられる基準にするのは 2 つの理由から。** 第 1 に、数が大きい順に並べれば
優先順位が自動で付く。第 2 に、修正後に同じ尺度で測り直せば「減った」ことが
確かめられる。「使いにくい」は測り直せないが、「往復 6 回が 2 回になった」は
測り直せる。

### 測るのはユーザー、計器を作るのは実装側

ユーザーに「気になったところを挙げてください」と頼むと、また平坦な 47 件に
戻る。実装側が先に、

1. **情報の所在表** — どのパネルがどの情報を持っているか
2. **往復が発生しそうな候補** — コードから読める範囲での予測
3. **シナリオ台本と集計表** — 何をどの順で触り、何を数えるか

を用意する。ユーザーはそれを持って**一回通しで触り、○× を付けるだけ**にする。

### シナリオは 2 本

| # | シナリオ | 選ぶ理由 |
|---|---|---|
| 1 | 素材 → レイヤー → キーフレーム → 書き出し | 動画編集の芯。AE の期待と比較しやすく、ずれが往復として出る |
| 2 | シェイプ → scatter → フィールド変調 → ラスタライズ → 書き出し | Ravel 固有の価値が出る側。ノードとレイヤーをまたぐ経路の往復が出る |

2 本にとどめるのは、通しで触る作業がユーザーの時間を使うため。**3 本目は
1 と 2 の結果を見てから決める**（両方で同じ往復が出るなら、3 本目を足しても
新しい情報は出ない）。

### 既知分を先に単位化する。測定が遅れても実装は止まらない

`backlog.md` の実機フィードバックと `issues/` の UI 系から、**確度の高いものは
測定を待たずに単位にする**。測定の役目は「新しい仕事を作ること」ではなく、

- 既知の単位に**優先順位を付けること**
- 誰も挙げていない往復を**見つけること**

の 2 つ。したがって `UX-4` 以降の実装単位は `UX-1`〜`UX-3` に依存しない。
測定が 1 週間遅れても実装は 1 日も止まらない。

### 設定になる項目は `settings-screen-plan.md` に載せる

「停止したら再生開始位置へ戻す」「起動時にコンポを作るか」は設定 1 つずつ。
**設定の入れ物と適用経路は `settings-screen-plan.md` が単独で持つ**規約なので、
この計画書は項目を定義するだけで、ダイアログへの露出はそちらの `SET-*` に
乗せる。ユーザー向けの設定経路を 2 本作らない。

### 単位 1: 情報の所在表と往復候補の列挙

- **表を 1 枚作る**: 行が情報（レイヤーの時間配置、不透明度、素材、キーフレーム、
  ノードのパラメータ、評価エラー、…）、列がパネル。セルは「編集できる」
  「見えるだけ」「出ない」の 3 値
- 表から**同じ情報を 2 箇所以上が編集できる行**を抜き、往復候補として並べる
- 置き場所は `docs/ui-impl-status.md` ではなく**この計画書の付録**。
  `ui-impl-status.md` は「今動くもの」を書く文書で、所在の設計判断は持たない

**完了条件**

- 表が全パネル（Viewer / Timeline / Properties / Outliner / MediaBin /
  ノードエディタ / レンダーキュー）を覆っている
- 往復候補が根拠（どのパネルとどのパネルか）付きで列挙されている

### 単位 2: シナリオ 2 本の台本と集計表

- 台本は**操作の並びだけ**を書く。「ここが不便」は書かない（誘導になる）
- 集計表は 1 手順 1 行で、`往復` / `探し直し` / `詰まった` の 3 列
- 2 本とも**書き出しまで到達する**こと。途中で切ると、成果物が出るまでの
  経路にある往復が数から漏れる

**完了条件**

- 台本どおりに触れば、両シナリオとも実際に成果物が出る（台本自体が通る）
- 集計表が単位 1 の往復候補と突き合わせられる形になっている

### 単位 3: 測定結果の取り込みと単位化

**この単位は測定が済むまで着手できない。**`backlog.md` では `❓`
（前提条件の判断待ち）として持つ。

- 集計表の数を大きい順に並べ、**上位から実装単位に起こす**
- 単位 1 の往復候補に無かったものは、**なぜ予測から漏れたか**を 1 行残す
  （次の計器の精度が上がる）
- 既存の `UX-4`〜`UX-11` の順序を測定結果で並べ替える

**完了条件**

- 新しい単位が `backlog.md` とこの計画書の両方に登録されている
- 予測から漏れた項目に理由が付いている

### 単位 4: ノード検索を `type_key` でも引く

`ravel-ui/src/node_search.rs:45` の `match_tier` は `label` と `description`
しか照合しない。`type_key` は同点時の並べ替えにしか使われないので、
**`shape.rect` のような型名で引けない**。日本語 UI では `label` が日本語に
なるため、型名で引けないことの痛みが大きい。

- `match_tier` に `type_key` の照合段を足す。段の優先度は
  `label` → `type_key` → `description`
- `DISC-3`（表示名とキーの体系）の後追いなので、`type_key` の表示は変えない

**完了条件**

- `shape.rect` で `shape.rect` が引ける（ja / en どちらのロケールでも）
- 既存の label 一致が順位を落とさないことのテスト

### 単位 5: Timeline のプロパティ行の絞り込み

AE の reveal ショートカット一式。**行の生成そのものは変えず、フィルタを
1 枚かぶせる**。`MED-APP-13`（行レイアウト走査が 4 箇所に複製されている）に
触れるため、着手時にその個票を読むこと。

#### 対応表

Ravel に対応物があるものだけを入れる。**無いものは「今は入れない」ことを
ここに書き残す**（後から「なぜ P はあるのに M が無いのか」を調べ直さないため）。

| AE | 意味 | Ravel | 判断 |
|---|---|---|---|
| `U` | アニメート済み（キーのある行） | 全行 | 入れる |
| `P` | Position | `PropertyGroup::Position` | 入れる |
| `S` | Scale | `Scale` | 入れる |
| `R` | Rotation | `Rotation` | 入れる |
| `T` | Opacity | `Opacity` | 入れる |
| `A` | Anchor Point | `AnchorPoint` | 入れる |
| `L` | Audio Levels | `AudioGain` | 入れる |
| `UU` | 既定から変更済みの行 | 全行 + 既定値比較 | 入れる（chord は下記） |
| `EE` | 式を持つ行 | `AnimationChannel::Expression` の行 | 入れる（同上） |
| `E` | Effects | — | **入れない**。Ravel の「効果」はノードネットワークで、行に対応する概念が無い。ネットワークのパラメータ行は `U` / `UU` に含まれる |
| `LL` | Audio Waveform | — | **入れない**。波形表示が未実装（`AUDIO-5`） |
| `M` / `MM` / `F` / `TT` | マスク各種 | — | **入れない**。マスクが無い |

**Timeline のキーコンテキストは今 `Delete` / `Backspace` / `Cmd+D` しか
使っていない**ので、上の 1 文字はすべて空いている。Viewer の `P`（ペン）と
NodeEditor の `L`（自動整列）とはコンテキストが違うので衝突しない。

#### 二度押しをどう表すか

`UU` / `EE` は AE では**同じキーの二度押し**だが、`KeyChord`
（`ravel-ui/src/keybindings/`）に二度押しの表現が無い。機構を 1 本増やすより
**別 chord を割り当てる**: `Alt+U`（変更済み）と `Alt+E`（式を持つ行）。

- `Shift+<key>` は AE では「置換でなく追加」の意味なので、そちらに残す
- 二度押しを実装するとキーバインド資産の書式・衝突検出・環境設定の一覧まで
  波及する。**AE 互換のためだけに機構を増やさない**

#### 追加と置換

AE と同じく、`Shift` 併用で**現在の絞り込みに足す**（`P` の後に `Shift+S` で
Position と Scale）。修飾なしは置換。同じキーをもう一度押すと全表示に戻る。

**完了条件**

- 上表の「入れる」7 つ + `Alt+U` / `Alt+E` が切り替わり、
  もう一度押すと全表示に戻る
- `Shift+<key>` が現在の絞り込みに足し、修飾なしが置換する
- レイヤーを選び直しても絞り込みが保たれる
- 該当行の無いレイヤーで押すと空になる（エラーにしない）
- 追加した chord が ja / en のキーバインド資産に入り、衝突検出を通る

### 単位 6: Timeline 上での値スクラブ

プロパティ行の値を Timeline 上で直接いじる。**Properties への往復を消す**のが
目的で、往復基準に直接効く単位。

- 既存の `ScrubInput` の挙動に合わせる（`done/param-range-scrub-input-plan.md`）
- **コミットは 1 ジェスチャー 1 undo**。`HIGH-28`（スクラブ中の再構築で
  `Commit` が失われる）と同じ穴を作らないこと。着手時に `HIGH-28` の
  修正が入っているかを確認し、入っていなければ先に直す

**完了条件**

- Timeline 上のドラッグで値が変わり、Viewer が追随する
- 1 ドラッグが 1 undo
- キーが打たれている行では、その時刻のキーが更新される

### 単位 7: プレイヘッド操作

- **Shift + プレイヘッド移動でキーへスナップ** — 表示中のキーフレームに吸着
- **AE 相当のショートカット** — レイヤーの分割、始端 / 終端をプレイヘッドに
  合わせる、プレイヘッドへ移動

ショートカットは `assets/keybindings/` に足す。`MED-APP-31`（ポップアップ表示中も
ワークスペースのショートカットが勝つ）は #349 で解決済みで、アセット由来の
バインドは `!Input && !PopupMenu && !AppMenuBar` を、パネル固有のバインドは
自分の文脈を同じく narrowing したものを持つ。**足すのは Timeline の
キーコンテキスト**で、`UX-5` の reveal キーと衝突しないことを確かめる。

**完了条件**

- スナップが「表示中の」キーだけを対象にする（畳んだ行のキーに吸われない）
- 追加したショートカットが ja / en のキーバインド資産に入っている
- レイヤー分割が 1 undo で、分割後の 2 枚が元の時間範囲を過不足なく覆う

### 単位 8: 時間ルーラ

- **コンポ終端の可視化** — Timeline 上で Duration の終わりが分かる。
  範囲外を落とす帯を敷く（ズーム制限にしないのは、範囲外を見たい場面が
  あるため）
- **BPM グリッド** — 音楽に合わせる用途。**フレームグリッドと別に持つ**。
  BPM とオフセットはコンポの属性ではなく **UI 状態**（`ui_state.json`）に置く。
  絵に影響しないので `.ravprj` を上げる理由が無い

**完了条件**

- 終端の外が視覚的に区別できる
- BPM グリッドの on/off と BPM 値が再起動をまたいで残る
- フレームグリッドと BPM グリッドが同時に出せる

### 単位 9: ループ範囲とループ再生

イン / アウトを決めて、その区間だけ繰り返す。

- 範囲は**コンポ単位**。レイヤーごとに持たない（用途が無い）
- ループ再生中に範囲外へシークしたら**ループを外す**（黙って引き戻さない）
- 範囲は UI 状態（`ui_state.json`）。作業の都合であって作品の属性ではない。
  **AE のワークエリアはコンポごとに `.aep` へ入る**ので明示的に確認したうえで
  `ui_state.json` に決めた（2026-08-09）。プロジェクトを人に渡したとき
  ループ範囲は付いていかない。**付いてこなくて困る実例が出てから `.ravprj` へ
  移す**（移すこと自体がフォーマット版 1 つなので、先送りしても取り合いは
  無くならない — 今取らないだけ）

**完了条件**

- 範囲の設定・解除ができ、再生が範囲内で折り返す
- 音声が折り返しで途切れない（`ravel-audio` の再生キューに折り返しを伝える）
- 範囲外へのシークでループが外れる

### 単位 10: 素材からレイヤーへの経路

- **AssetImport 時の自動配置をやめる。** インポートはインポートだけにする
- **ドラッグで Add as Layer** — 現在はメニュー経由のみ
- **Outliner からのレイヤー追加** — 現在は Timeline / Layer メニューのみ

3 つを 1 単位にするのは、**同じ「素材をレイヤーにする」経路の追加と削除**で、
別々に入れると「インポートで配置されなくなったのにドラッグがまだ無い」
という穴の開いた状態が中間に生まれるため。

**完了条件**

- インポートしてもレイヤーが増えない
- MediaBin からのドラッグでレイヤーになり、1 undo
- Outliner からレイヤーを足せる

### 単位 11: 再生停止位置と起動時コンポの設定 2 つ

- **停止したら再生開始位置へ戻す**（既定 off。現在の挙動を既定に据える）
- **起動時にコンポを作るか**（既定 on。同上）

どちらも `SettingsLayer` の `playback` / 起動側に足し、**ダイアログへの露出は
`settings-screen-plan.md` の `SET-*` に乗せる**。この計画書は挙動と既定値だけを
決める。

**完了条件**

- 2 つの設定が既定値で現在の挙動と一致する
- 設定を切り替えると挙動が変わり、再起動をまたいで残る
- `settings-screen-plan.md` に露出の行が足されている

**完了条件**

## 非対象

- **ノードグラフの可読性**（自動整列、フロー方向、Reroute、エッジ配色）。
  `node-graph-readability-plan.md` が持つ
- **Wrangle とユーザー定義パラメータ**。`wrangle-plan.md` が持つ
- **パネルレイアウトの作り直し。** 往復の原因がレイアウトだと**測定で
  分かってから**判断する。先に組み替えると、測る前に尺度が変わって
  比較できなくなる
- **設定ダイアログの項目追加そのもの**。`settings-screen-plan.md` の領分
- **`issues/` に起票済みの UI バグを単位として取り込むこと**。個票は
  `issues/` のまま、着手順は `roadmap.md` のクラスタのままにする。
  取り込むと「計画書が引き受けた issue はクラスタから外す」規約
  （`roadmap.md` の「issues の扱い」）に従ってロードマップ側のクラスタを
  組み替えることになり、この計画書の範囲を超える。
  **`UX-3` の測定は、これらの issue を単位と同じ尺度（往復回数）で
  並べる**ので、優先順位の比較はできる。取り込みが要ると判断したときは
  クラスタの組み替えと同時に行う（候補は `MED-APP-27` と `MED-APP-20`）
