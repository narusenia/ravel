## 決定事項

### 「出す項目 = 実際に効く項目」を規約にする

**設定画面に項目を出す条件は、その設定が挙動に反映されること。** 効かない
項目は画面に出さない（コメントアウトでもグレーアウトでもなく、存在させない）。

- 受入条件は UI ではなく**挙動**で書く。「言語を切り替えると次の描画で
  UI 文字列が変わる」であって「言語の dropdown がある」ではない。
- 機能が未実装の設定（プロキシ、カラー管理）は**画面に出さず**、要件側に
  「未対応」と明記する。機能が入った時点で項目を足す（下記のゲート付き単位）。
- この規約が `MED-APP-10` の再発防止そのものになる。

### `gpui_component::setting::Settings` を使う

自前でフォームを組まない。同コンポーネントは
`Settings → SettingPage → SettingGroup → SettingItem → SettingField` の
階層とサイドバーを持ち、フィールドは switch / checkbox / input / dropdown /
scrollable_dropdown / number_input / 任意 element を備える。

層モデルに使うのは **`on_reset(is_dirty, reset)` の方だけ**:

- `is_dirty` = **編集中の層に明示値がある**（マージ後の値が既定と違う、では
  ない。層に値があるかどうか）
- `reset` = **その層からその値を消す**（下位層の値へ戻る）

**`default_value()` は使わない。** あれは「静的な既定値を書き戻す」reset
機構（`fields/mod.rs` のコメントが "this value can be used to reset the
setting to its default state" と書いている）で、層モデルでは**上書きを消す
のではなく既定値と同じ明示値を作ってしまう**。`on_reset` は
`default_value` ベースの reset より優先されると明記されているので、全
フィールドで `on_reset` を付ける。

これで「この項目はこの層で上書きしている」の表示と解除がコンポーネントの
標準機能で成立し、独自のバッジ UI を作らずに済む。

### モーダルダイアログにする

`window.open_dialog` の前例が 2 箇所（`ravel-app/src/workspace.rs:793`、
`:1026`）あり、フォームの前例は `composition_form.rs`（345 行）。

- 独立ウィンドウにしない理由は、**分離ウィンドウの既知負債
  （`MED-APP-01`: OS ウィンドウを閉じるとシェルが desync、`reattach_window` が
  dead API）に触れないため**。設定画面のためにあの負債を先に直す価値はない。
- ドック可能パネルにしない理由は、常時見るものではないのに
  パネル登録とワークスペースプリセット資産の全更新が付いてくるため
  （パネル配置の再設計は `done/free-pane-docking-plan.md` に移った）。
- **将来方向**: カラー管理が入って Viewer と見比べる必要が出たら独立
  ウィンドウ化を検討する。その時点で `MED-APP-01` が前提になる。

### 環境設定とプロジェクト設定の 2 画面に分ける（AE 型）

| 画面 | 書き込み先 | 内容 |
|---|---|---|
| 環境設定（Preferences） | **`global` 層**（`<config_base>/ravel/settings.toml`） | 一般（停止位置・起動時コンポ）、外観、言語、キーバインド、キャッシュ、自動保存 |
| プロジェクト設定 | **`project` 層**（`.ravprj` の `settings.toml`） | 既定フレームレート、将来のカラースペース |

**書き込み先が画面で決まる**ので、行ごとに層を選ぶ UI が要らず、誤って
グローバルへ書く事故も起きない。

**層の対応はこの向きでないと壊れる。** 解決順は
`default → global → project → user`（後ろが強い。`project/mod.rs:319-332`）なので、
環境設定を最上位の `user` 層に書くと**プロジェクト設定が環境設定に負ける** —
REQ-PROJ-004 の「プロジェクト固有設定でグローバル設定を上書きできる」が
成立しなくなる。`global` こそが per-user のグローバル設定
（`project/paths.rs:6-7`「user-wide preferences survive across projects」）で、
これに書けば `project` が正しく上書きする。

`user` 層は**現在ファイルの置き場も呼び出し元も無い**（`resolved_settings` の
第 2 引数にテストしか値を渡していない）。本計画では触らず、「マシン固有の
最終上書き」「CLI からの一時上書き」用の枠として空けておく。

### 即時適用。undo には載せない

- 変更した瞬間に反映し、ダイアログは閉じるボタンのみ。
- **設定は `Document` ではないので undo に載せない。** 載せると undo 履歴が
  「編集の履歴」でなくなる。
- 「既定に戻す」はコンポーネントの `on_reset` を使う（層の値を消す）。
- 永続化は変更ごとに TOML を書く。書き込み失敗は**無言にしない**
  （`CRIT-02` と同じ失敗形を作らないため、通知を出す）。

### 適用経路は 1 本にする

設定の適用は `ResolvedSettings` を配る 1 経路に限る。

- 解決済み設定は**耐久状態**なので Global に置いてよい（`.agents/rules/gpui.md`
  の「新 Global は耐久状態のみ」に合致）。ダイアログは設定を書き、Global を
  更新し、購読側が反応する。**ダイアログが各機能を直接叩かない。**
- 設定ダイアログを開くのは `CommandId` + `for_each_command!` テーブル経由
  （`AppPreferences` / `ProjectSettings` を追加）。メニューは File または Edit
  の慣例に合わせ、`menu.edit` へ入れる（macOS のアプリメニュー慣例との整合は
  `native_menu` 対応時に再検討）。
- `render()` の中で設定を書かない。ロケール変更後の再描画は、購読側が
  `cx.notify()` する形にする（render 純粋性）。

### 設定ファイルは単一 `settings.toml` のまま。要件を改訂する

REQ-PROJ-004 は `general` / `appearance` / `keybindings` / `performance` /
`plugins` の 5 ファイル構成を指定しているが、**4 層マージが既に単一ファイルで
動いている**ので、分割は読み込み先を 4×5 に増やすだけで得が無い（項目は
まだ十数件）。

- 単一 `settings.toml` を正とし、要件を改訂する。
- **キーバインドだけは例外**で、既に別資産（`assets/keybindings/default.toml`）
  になっている。ユーザー上書きも `<config>/ravel/keybindings.toml` として
  別ファイルで読む。
- 項目数がファイルとして扱いにくい規模に育ったら分割を再検討する（判断は
  先送りではなく「今は単一が正」と決めた上での将来方向）。

### 単位 6 (`SET-6`): プロジェクト設定画面

- `project` 層へ書く画面。**効く項目のみ** = 既定フレームレート
  （新規コンプ作成時の初期値に配線する）。
- 未保存プロジェクトでの扱い（保存時に一緒に書かれる）。

**完了条件**

- 既定フレームレートを変えると新規コンプの初期値が変わるテスト。
- **プロジェクト層の値がグローバル（`global` 層）を上書きするテスト**（層の
  向きを間違えると逆になるので、これを回帰として残す）。
- 「既定に戻す」でプロジェクト層の値が消え、グローバル値に戻るテスト。
- 未保存プロジェクトで設定してから保存すると `.ravprj` に入るテスト。

**実装で確定した点**

- **優先順位は「アクティブなコンポジションの書式 > 設定の既定値 > 組み込みの
  既定」。** 既存の継承挙動は変えない（より局所的なシグナルを優先する）。
  結果として**アクティブなコンプがある間はこの設定が観測できない** — 効くのは
  `File ▸ New` の root コンプと、アクティブが無い状態の `Composition ▸ New…`。
  この性質は `ProjectState::new_composition_defaults` の doc コメントと
  [`../specifications/ui/settings.md`](../specifications/ui/settings.md) に書いた。
- 優先順位の判断は 1 箇所（`ProjectState::new_composition_defaults`）に置く。
  ダイアログを開く `prompt_new_composition` は呼ぶだけ。
- **`.ravprj` を開いたときは `manifest.frame_rate` が正**で、この設定は関係ない
  （保存済みの事実を設定で上書きしない）。
- 値の書式は fps 表記と有理数の両方を読む（`"30"` / `"29.97"` / `"30000/1001"`）。
  放送レートは `frame_rate_from_fps` を通して正確な `n*1000/1001` にする。
  **画面は closed list（よく使う fps）にして、解釈できない値を層に書かせない** —
  自由入力だと `"24fps"` のような値が層に入り、読むたびに無視されるのに画面には
  出続ける。ファイルが既に持っている値は、読める場合だけ選択肢に足す。
- `File ▸ New` はプロジェクト層を**ドキュメント構築より前に**捨てる。順序を逆に
  すると、閉じたプロジェクトのフレームレートが次のプロジェクトに漏れる。

「出す項目 = 効く項目」規約により、これらは**前提機能のマージ後**に着手する。
計画としては今確定させ、着手条件だけを書いておく。

| ID | 項目 | 着手条件 |
|---|---|---|
| `SET-8` | キャッシュ（場所 / 各層の上限 / sim 予約率 / ディスク層の有無） | `cache-plan.md` の `CACHE-3`（`CacheBudget`）がマージされたら |
| `SET-9` | 自動保存（間隔 / 無効化） | REQ-PROJ-002 の自動保存タイマーが実装されたら |
| `SET-10` | プロキシ（`proxy_mode` / 解像度） | プロキシ生成（REQ-PROJ-005）が実装されたら |
| `SET-11` | カラー（OCIO / working / display space） | カラー管理（REQ-RENDER-003）が実装されたら |
| `SET-12` | キーバインドの割り当て編集（衝突検出 / chord 入力キャプチャ。REQ-UI-007） | 一覧（`SET-5`）の後。規模が大きいので別計画に切り出す判断もあり |
| `SET-14` | UI スケーリング（REQ-UI-006） | **調査が前提** — `Theme` は `font_size` / `mono_font_size` を持つが、Ravel のパネルが px 直書きでどれだけ無視しているか未調査。無視されるなら「効く項目」の条件を満たさない |
| `SET-15` | 色覚多様性テーマ / アニメーション削減（REQ-UI-006） | テーマ資産の追加と、アニメーションを持つ箇所の棚卸しが前提 |
| `SET-13` | 設定の import / export | 項目が揃ってから（今やると出力形式が毎回変わる） |
| `SET-16` | 再生（停止したら再生開始位置へ戻す = `playback.stop_returns_to_play_start`）と起動（起動時にコンポジションを作る = `startup.create_composition`） | **実装済み。** 挙動と既定値は `refactor-plan-0808.md` の単位 11 が入れた（既定はどちらも従来の挙動。`false` / `true`）。露出は環境設定の新しい「一般」ページに switch 2 つ。どちらも `global` 層へ書く |

## 検証

- **単位 1 が UI 無しで完結すること**が本計画の骨。ここが入れば
  `MED-APP-10` は UI の有無に関係なく消える。
- 設定を変えた結果は**挙動でテストする**（dropdown の存在ではなく、
  文字列 / 配色 / 初期値が変わること）。
- ダイアログは `.agents/rules/gpui.md` の 3 点を明示的に検査する:
  `render()` に focus 変更とコマンド実行を持たない、`FocusedPanelGlobal` を
  奪わない、コマンド経路が `dispatch_command` に限られる。
- ロケール追加時の抜けは既存の i18n テストで捕まえる。

## 非対象

- **キー割り当ての編集 UI**（`SET-12`。一覧までが本計画）。
- **設定の import / export**（`SET-13`）。
- **プラグイン設定**（REQ-PLUGIN 系が未実装）。
- **UI スケーリング・色覚多様性テーマ・アニメーション削減**（`SET-14` /
  `SET-15`。REQ-UI-006 の残りの受入条件）。
- **カテゴリ別 5 ファイル構成**（要件を改訂して単一ファイルを正にする）。
- **`user` 層を UI から書くこと**（置き場も呼び出し元も無い。マシン固有の
  最終上書き用の枠として空けておく）。
- **分離ウィンドウ化**（`MED-APP-01` を前提にするので将来方向）。
- **設定を undo に載せること**。
