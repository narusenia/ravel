# Viewer の表示オプションと検査 実装計画

> **Status**: Planned — 2026-07-30

対象: Viewer で「出ている絵が本当に正しいか」を確かめる手段を用意する。
背景色の配線、透過の可視化、チャンネル単独表示、ピクセル値の読み取り、
再生・キャッシュ状態の表示。関連要件: REQ-UI-004（スコープ付きビューア）、
REQ-LAYER-001。

## 問題

### 1. `Composition.background_color` が誰にも読まれていない

`background_color: Color` は `Composition` のフィールドとして定義され
（`crates/ravel-core/src/composition/mod.rs:360`）、**コンプ設定フォームで
編集でき**（`composition_form.rs:66, 116`）、**保存もされる**。しかし
評価・合成のどこにも現れない。Viewer は黒 quad をハードコードして絵を
重ねている（`viewer.rs:1614`）。

`layer-shell-wiring-plan.md` が `track_matte` / `time_remap` について指摘した
「データモデルと永続化が先行して、設定したのに効かないバグに見える」の
**すでに顕在化した例**。こちらは UI が既にあるので今日踏める。

issue: `MED-CORE-09`（本計画が引き受ける）。

### 2. 透過を確認する手段が無い

コンプ出力は straight alpha の RGBA f32（`FrameBuffer`）だが、Viewer は
黒の上に重ねて表示するだけ。**「アルファが 0 なのか黒なのか」が区別できない。**
キーイング（`FX-4`）やマットを入れると、この区別ができないまま作業することになる。

### 3. 値を数値で確かめられない

`ViewerFrame::Frame` は `Arc<FrameBuffer>`（f32）をそのまま持っている
（`panels/mod.rs:515-518`）ので、**8bit 変換前の評価値がすでに UI 側にある**。
それを読む手段が無いだけ。カラー作業とノードのデバッグで最初に欲しくなるのは
「この点の値は何か」。

### 4. 再生とキャッシュの状態が Viewer に出ない

`Transport` はドロップフレーム数を数えている（`playback.rs:82, 108`）が、
どこにも表示されない。プロキシ・解像度低下・キャッシュヒットの状態も同じ。
`cache-plan.md` の `CACHE-6` は Timeline のキャッシュ帯を持つが、**Viewer 側の
状態表示は誰も持っていない**。

## 決定事項

### 背景色は合成の最下段で敷く。Viewer 側で誤魔化さない

`background_color` は評価結果に含める。Viewer が「背景色っぽい quad」を描く
方式は採らない — それだと書き出し（`EXPORT-*`）で背景が消え、Viewer と
出力が食い違う。

### 透過表示は「背景の描き方」のオプションで、オーバーレイではない

チェッカーボードは絵の下に敷くもので、絵の上に重ねる
`viewer-overlay-manipulator-plan.md` の機構には乗らない。背景の描画モード
（コンプ背景色 / チェッカーボード / 単色）として持つ。

### チャンネル単独表示は表示経路の変換で行う

`R` / `G` / `B` / `A` の単独表示は、f32 バッファから `RenderImage` を作る
`frame_buffer_to_render_image`（`viewer.rs:1842`）に表示モードを渡して行う。
**評価結果は変えない**（ノードを挿し込む方式は採らない）。

### 表示オプションはコンプにもプロジェクトにも保存しない

背景モード・チャンネル・ガイド表示などの Viewer 表示状態は
**セッション内のパネル状態**とする。`.ravprj` にも `ui_state.json` にも
書かない。理由は「同じプロジェクトを別の目的で開くたびに前回の検査モードが
復元されると邪魔になる」ため。永続化したい要求が出た時点で
`settings-screen-plan.md` の設定として扱う（表示オプションを設定画面に
出すのは「設定が挙動を変えるときだけ」という同計画の規約に合う）。

### 状態表示は「異常時だけ出す」

ドロップ・プロキシ・低解像度は**通常時に何も出さない**。常時 HUD を出すと
絵の確認を邪魔する。異常が続いている間だけ小さく出し、解消したら消す。

## 実装単位

### INSP-1: `background_color` の配線とチェッカーボード

- 殻合成の最下段でコンプ背景色を敷く。評価結果に含め、Viewer と書き出しで
  同じ絵になるようにする
- 背景色のアルファが 1.0 未満のときは透過として扱う（不透明を強制しない）
- Viewer の背景描画モードを追加: コンプ背景色（既定） / チェッカーボード /
  単色。チェッカーボードはスクリーン空間の固定サイズで描く（ズームで
  マスの大きさが変わらない）
- ハードコードされた黒 quad（`viewer.rs:1614`）を撤去する

**完了条件**

- 背景色を変えると評価結果のピクセルが変わるテスト（Viewer 側の描画ではなく
  `FrameBuffer` を検証する）
- 背景色のアルファ 0 のコンプで、レイヤーが無い領域のアルファが 0 になるテスト
- チェッカーボードのマス目がズームに依存しないこと（性質テスト）
- `MED-CORE-09` の解消

**フェーズ**: A5（`roadmap.md`）。この単位だけ前出しする — 編集できるのに
効かないフィールドが残っているのは他の検査機能より痛い。

### INSP-2: チャンネル単独表示

- 表示モード: RGB（既定） / R / G / B / A / アルファをマット表示
- 単独チャンネルはグレースケールで描く
- `frame_buffer_to_render_image` に表示モードを渡す形にし、評価経路は触らない
- 切り替えはコマンド（`CommandId`）＋ Viewer ツールバー。キーバインドは
  `assets/keybindings/default.toml` の `[viewer]` セクションに置く

**完了条件**

- 各モードで期待するピクセル値が出るテスト（変換関数の単体テスト）
- モード切り替えが再評価を発生させないテスト
- ロケール（en / ja）にモード名が入っていること

### INSP-3: ピクセル値の読み取り

- ポインタ位置のコンプ座標と、その点の RGBA を f32 のまま表示する
- 表示形式は f32（既定）と 8bit 換算の切り替え
- ズームルーペ（ポインタ周辺の拡大表示）は**この単位に含めない**（下記非対象）
- 値の表示はスクリーン空間なので、`OVL-1` のスクリーン空間描画 API に乗る

**依存**: `OVL-1`（スクリーン空間の描画）

**完了条件**

- コンプ座標 → バッファ添字の変換が端でずれないテスト（境界値）
- 評価バッファがコンプ解像度より小さいときも正しい点を読むテスト
  （`ViewerFrame::Frame` は両方の解像度を持つ）
- フレーム外にポインタがあるとき何も出ないテスト

### INSP-4: 再生とキャッシュの状態表示

- ドロップフレームが続いている間だけ小さく表示する（`Transport::dropped_frames`）
- 表示解像度がコンプ解像度より低いとき、その旨を表示する
- キャッシュ状態は `cache-plan.md` の `cache_stats` API が入ってから表示する
  （**API より先に作らない**）

**依存**: キャッシュ表示のみ `CACHE-6`

**完了条件**

- ドロップが 0 のとき何も描かれないテスト
- 解消後に表示が消えるテスト
- `cache_stats` が無い状態でもビルド・動作すること（キャッシュ部分は後付け）

### INSP-5: スコープ 4 種の引き取り判断

REQ-UI-004 は波形モニタ / ベクトルスコープ / ヒストグラム / パレードを
要求しており、ワークスペースプリセット（`assets/workspaces/color.toml`）は
4 枚を配置しているが、実装は `PlaceholderPanel`。

- 4 種を本計画が引き取るか、別計画に切るかを決める
- 決めるべき点: 同じ `FrameBuffer` を 4 パネルで共有するか、パネルごとに
  サンプルするか。OCIO（REQ-UI-004 が要求）をどの段で通すか
- **判断の単位であり、実装の単位ではない**

**完了条件**

- 判断が `docs/implementation/README.md` に記録されること
- 引き取る場合は単位分割を本計画に追記、切る場合は新計画を作って
  `backlog.md` / `roadmap.md` を更新

## 検証

- `mise run check`
- 背景色は `FrameBuffer` レベルで検証する（Viewer の描画結果は検証しない）
- チャンネル変換とピクセル読み取りは純粋関数の単体テスト
- ゴールデン画像は増やさない

## 非対象

- **ズームルーペ**。ピクセル値が数字で出れば大半の用途は足りる。必要になったら
  `OVL-1` のスクリーン空間描画で追加する
- **OCIO / カラースペース変換**。REQ-UI-004 が要求しているが、色管理は
  評価パイプライン全体の話なので本計画では扱わない（`INSP-5` の判断対象）
- **A/B 比較・差分表示・外部モニタ出力**。REQ-UI-004 の「将来」項目
- **ROI（作業領域）枠**。部分レンダリングの機能が無いので、枠だけ描いても
  何にも使われない。`cache-plan.md` / `render-export-plan.md` が部分評価を
  持った時点で引き取る（`viewer-overlay-manipulator-plan.md` の棚卸し表に
  見送りとして記録済み）
