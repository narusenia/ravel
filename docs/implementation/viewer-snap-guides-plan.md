# Viewer のスナップとガイド 実装計画

> **Status**: Complete — 2026-08-15（`SNAP-1`〜`SNAP-3` 完了。#444 / #446）

対象: Viewer でレイヤーやシェイプを動かすときの吸着（スナップ）と、
ユーザーが置くガイド線・定規。関連要件: REQ-UI-011（Viewer ツールシステム）、
REQ-UI-004。

## 問題

Viewer のドラッグは**どこにも吸着しない**。`move_dragged`（`viewer.rs:569`）は
ポインタのデルタをそのまま位置に足すだけで、他のレイヤーの端、コンプの中心、
セーフエリアとの関係は一切見ていない。修飾キーによる制約もシェイプ描画時の
正形・中心描画（`drag_geometry`、`:2136`）だけで、移動には無い。

結果として「中央に置く」「2 つのレイヤーの端を揃える」が目分量になる。
`align-panel-plan.md`（`ALIGN-1〜3`）は**整列パネル**であって、ドラッグ中の
吸着は含んでいない。

ガイド線と定規は概念自体が無い。`Composition` にガイドのフィールドは無く、
REQ にも記述が無い。

## 決定事項

### 吸着対象は「すでに存在するもの」から始める

先に入れるのは、新しいデータを持たない吸着だけにする。

| 吸着対象 | 由来 |
|---|---|
| 他レイヤーの bbox の端・中心 | 評価済み bounds（`layer_selection_comp_rects` と同じ経路） |
| コンプ枠の端・中心 | `Composition.resolution` |
| セーフエリア | 既存の `paint_safe_areas` と同じ比率 |

**ユーザーガイドは単位 2 に分ける。**単位 1 はデータモデルも永続化も触らない。

### 吸着はコンプ空間の距離ではなくスクリーン距離で判定する

閾値をコンプ空間で持つと、ズームアウト時に吸着が強すぎ、ズームイン時に
効かなくなる。**スクリーン上で一定の px**（既定 8px 前後）を閾値にし、
コンプ空間へ逆変換して比較する。

### 吸着中はガイド線を一時表示する

吸着していることが分からないと、吸着は「勝手に動く」バグに見える。
吸着が成立している軸に、そのフレームだけ線を描く。これは
`viewer-overlay-manipulator-plan.md` の機構に乗せる（新しい描画経路を作らない）。

### 吸着の無効化は修飾キーで行う

ドラッグ中に**プラットフォームの主修飾キー**（macOS は Cmd、Windows / Linux は
Ctrl）を押している間は吸着しない。トグル設定を先に作らない — 設定項目は
`settings-screen-plan.md` の「挙動を変えるときだけ出す」規約に従い、必要に
なってから追加する。

Alt は使わない。Alt は既にシェイプ描画で「中心から描画」（`drag_geometry`）、
殻のスケールで「アンカー基準」（`scale_edits`）の意味を持っているので、吸着抑制
まで兼ねると中心描画やアンカー基準スケールを使うドラッグが吸着を諦めることに
なる。実装は既存の `modifiers.platform || modifiers.control`（Node Editor /
Timeline と同じ綴り）を使う。

### 拘束修飾（Shift）が効くジェスチャーでは吸着しない

Shift が拘束として働くジェスチャーでは、拘束が吸着後の座標を上書きする。
`drag_geometry` は Shift で `max(|dx|, |dy|)` を両軸に適用し、`scale_edits` は
片方の ratio を両軸に適用するので、吸着した軸の値は残らない。ガイド線だけが
吸着先を指し、実際の端点は別の場所という**嘘をつくガイド**になる。

したがって Shift 中は**シェイプ描画**と**殻のスケールグリップ**で吸着しない。
Shift が何もしないジェスチャー（レイヤー移動、殻の Position / Anchor グリップ）
では吸着を続ける。判定は吸着の共通関数ではなく、拘束を持つ 2 経路の呼び出し側で
行う。

### ガイドはコンポジションに保存する。format version は上げない

ガイドは「そのコンポジションの作業上の目印」なのでコンポジション所有にする。
`Composition` への**追加フィールド**（`#[serde(default)]`）として持つ。

`Layer.audio` がフィールド追加で版を上げずに入った前例があるので
（`ui-impl-status.md`「`Layer.audio` は既存 v4 への追加フィールドで、
v5/migration は追加しない」）、**バージョンもマイグレーションも増やさない**。
実装時点の現行版は v8 で、`Composition.guides` はそこへの追加フィールドとして
入っている。
したがって `roadmap.md` の基準 1（移行コストが時間で増える単位を先に）は
この単位には効かない — 後回しにしてもコストは上がらない。

### 定規はガイドを作る手段として入れる

定規（ルーラー）単体では情報量が少ない。ガイドのドラッグ元として意味を持つので、
**単位 2 でガイドと同時に入れる**。定規だけ先に出さない。

## 実装単位

### SNAP-1: 既存要素へのスナップ

- 吸着候補の列挙: 他レイヤーの bbox（端・中心）、コンプ枠（端・中心）、
  セーフエリア
- スクリーン距離での判定と、コンプ空間への逆変換
- 対象ジェスチャー: レイヤー移動、シェイプ描画のドラッグ、`OVL-7` が入れば
  殻のスケール
- 吸着中のガイド線表示（オーバーレイ機構経由）
- 主修飾キー（Cmd / Ctrl）押下中は吸着しない
- 拘束修飾（Shift）が効くジェスチャーでは吸着しない

**依存**: `OVL-1`（吸着線の描画をオーバーレイ機構に載せるため）

**完了条件**

- 閾値内の候補に吸着し、閾値外では吸着しないテスト（純粋関数）
- ズーム倍率を変えても吸着閾値がスクリーン上で一定であるテスト
- 複数候補が同距離のとき決定的に 1 つを選ぶテスト
- 吸着が 1 ドラッグ 1 undo の規約を壊さないテスト
- 主修飾キー（Cmd / Ctrl）押下で吸着が消えるテスト
- Shift 押下で、拘束が効く 2 経路では吸着が消え、効かない経路では残るテスト

### SNAP-2: 定規とユーザーガイド

- `Composition` に追加フィールドとしてガイドを持つ（縦 / 横 + コンプ空間の位置）。
  `#[serde(default)]` で format version 据え置き（実装時点の現行版は v8）
- Viewer の縦横に定規を表示し、定規からのドラッグでガイドを作る
- ガイドの移動・削除、表示 / 非表示、ロック
- `SNAP-1` の吸着候補にガイドを追加する
- ガイド編集は 1 操作 1 undo（Document 変更なので既存の undo 経路に乗る）

**依存**: `SNAP-1`

**完了条件**

- ガイドを持つプロジェクトの保存・再読込・undo/redo が破綻しないテスト
- ガイドを持たない既存 `.ravprj`（現行版）がそのまま読めるテスト
- ガイドへの吸着が `SNAP-1` と同じ閾値規約で動くテスト
- 定規の目盛りがズームに追従することの性質テスト

### SNAP-3: ロケールと文書

- 定規・ガイド・吸着のロケール（en / ja）
- `docs/specifications/ui-spec.md` のビューア節に定規・ガイド・吸着を追記
- `docs/ui-impl-status.md` の Viewer 表を更新
- REQ-UI-011 の受入条件に吸着とガイドを追加

**完了条件**

- 3 文書が実装と一致していること
- ハードコードされたユーザー向け文字列が無いこと（`LOW-APP-11` を増やさない）

## 検証

- `mise run check`
- 吸着の判定と座標変換は純粋関数の単体テスト
- ガイドの永続化は既存の `.ravprj` ラウンドトリップテストに追加する
- GPUI テストはドラッグ経路に限る

## 非対象

- **ノードエディタのスナップガイド**。REQ-UI-002 が要求している（現状は
  10px グリッドスナップのみでガイド線は無い）が、対象が Viewer とは別なので
  同じ単位にしない
- **整列・分布パネル**。`align-panel-plan.md` の担当。本計画はドラッグ中の
  吸着だけを扱う
- **ピクセルグリッドへの吸着**。整数座標への丸めは吸着ではなく
  「位置の量子化」で、扱いが違う（キーフレーム値の丸めになる）
- **3D のスナップ**。`3d-scene-plan.md` 待ち
