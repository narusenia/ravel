# Viewer ツールの拡張 実装計画

> **Status**: TOOLX-1 complete — PR #484, 2026-08-28; TOOLX-2〜5 planned

対象: `done/tool-system-plan.md` が v1 として切り出した後の残り
（REQ-UI-011 の v1.5 項目）と、機能が無いまま UI にあるツールの実装。
関連要件: REQ-UI-011。

## 問題

### 1. Hand / Zoom ツールが動かない

ツールバーには 6 ツールが並び（`viewer.rs:1258-1264`）、`h` のホールドで
`ToolKind::Hand` に切り替わる（`:1815`）。しかし
`select_mouse_down`（`:398`）が `Select` 以外を弾くため、**Hand を選んでも
左ドラッグで何も起きない**。Zoom はどのハンドラにも現れない。

パンできるのは中ボタンドラッグだけで、これはトラックパッドのユーザーには
実質使えない。issue: `MED-APP-15`（本計画が引き受ける）。

この状態のため `done/pointer-feedback-plan.md` は Hand / Zoom のカーソル
（`OpenHand` / 虫眼鏡相当）を**意図的に見送っている** — 掴めるように見えて
動かない状態を作らないため。本計画がその保留も解消する。

### 2. Viewer に矩形選択が無い

NodeEditor には矩形選択がある（`DragMode::SelectBox`）が、Viewer には無い。
複数レイヤー・複数シェイプの選択は Outliner / Timeline / NodeEditor 経由でしか
できず、**画面を見ながら囲んで選ぶ**ができない。

### 3. REQ-UI-011 が v1.5 / v2 に送った項目が引受先を持っていない

`done/tool-system-plan.md` は完了して `done/` に移っており、REQ-UI-011 の
本文が挙げる次の項目は**どの live 計画にも無い**。

| 項目 | REQ-UI-011 での位置づけ |
|---|---|
| ヒット対象を他レイヤーへフォールバック | v1.5 |
| パスの点の挿入 / 削除 | v1.5 |
| Alt によるハンドル分離（接線の非対称化） | v1.5 |
| polygon / star のドラッグ描画 | v1 対象外（ドラッグ 1 回で決まらない） |
| ピクセル精度のヒットテスト | v2 |
| 殻変換が非恒等なレイヤーでの編集 | v2 |

## 決定事項

### Hand は「一時ハンド」を正とし、常時ハンドはその上に載せる

`h` ホールドの一時ハンドは既に状態遷移が実装済み（`viewer.rs:1795-1830`）なので、
**足すのは左ドラッグでパンする経路だけ**。ツールバーで Hand を選んだ常時ハンドも
同じ経路を使う。中ボタンドラッグは今の挙動を変えない（どのツール中でもパン）。

### Zoom ツールはクリックズームに限る

クリックで拡大、Alt+クリックで縮小、ドラッグで矩形ズーム。ズーム倍率の刻みは
既存のスクロールズームと同じ段を使い、別の倍率体系を作らない。

### 矩形選択のセマンティクスは NodeEditor と揃える

Shift でドラッグ開始したときは既存選択に加算する。NodeEditor は同じ意図の
実装で**開始時の選択を捨てるバグがある**（`LOW-APP-03`）。本計画は
**同じ間違いをしない**形（開始時の選択をキャプチャして和を publish する）で
実装し、`LOW-APP-03` の修正方針と同じ形にそろえる。

選択対象は `CanvasSelection`（ネットワーク内のノード）と `LayerSelection`
（レイヤー）のどちらか — **開いているネットワークがあるならノード、無ければ
レイヤー**という既存のクリック選択の規約をそのまま使う。新しい選択モデルを
作らない。

### 他レイヤーへのフォールバックは「アクティブ内でヒットしなければ」に限る

REQ-UI-011 の v1.5 記述どおり、アクティブレイヤー内でヒットが無いときだけ
他レイヤーを探す。常に全レイヤーを対象にすると、評価コストが選択駆動評価の
経路から外れる（同要件が v1 で対象を絞った理由）。

### 点の挿入 / 削除とハンドル分離は `PathPoints` の中だけで完結させる

パスの編集は `ParameterValue::PathPoints` の書き換えなので、既存の
undo・永続化・Properties 経路に乗る（`done/tool-system-plan.md` の設計を
変えない）。`in_tan` / `out_tan` の対称連動を切るのは点ごとのフラグではなく
**値そのもの**で表す（対称かどうかは 2 つの接線を見れば分かる。フラグを増やすと
永続化とマイグレーションが増える）。

## 実装単位

### TOOLX-1: Hand / Zoom ツールの実装

- Hand: 左ドラッグでパン（一時ハンドと常時ハンドの両方）
- Zoom: クリックで拡大 / Alt+クリックで縮小 / ドラッグで矩形ズーム
- どのツール中でも中ボタンドラッグはパン（既存挙動を維持）
- `done/pointer-feedback-plan.md` が保留したカーソル（Hand は `OpenHand` /
  ドラッグ中 `ClosedHand`、Zoom は `Crosshair`）をこの単位で付ける
- `MED-APP-15` を解消する

**完了条件**

- Hand の左ドラッグでビューポートオフセットが変わるテスト
- `h` ホールドが元ツールへ戻る既存挙動が壊れていないテスト
- Zoom のクリックがカーソル位置を基準に拡大するテスト（既存のスクロール
  ズームと同じアンカー規約）
- 矩形ズームが縦横比を壊さないテスト
- Hand / Zoom 中に選択やシェイプ描画が始まらないテスト

**実装メモ**

- 左ボタンの分岐は `ViewerPanel::left_mouse_down` の 1 か所（`ToolKind` の
  網羅 `match`。腕を足さずに 7 つ目のツールを増やせない）。Hand / Zoom は
  `overlay_handle_mouse_down` / `guide_mouse_down` の手前で分岐するので、
  ナビゲーション中はオーバーレイハンドルもガイドも押下を受けない
- パンは `pan_mouse_down` / `pan_dragged` / `pan_ended` の 1 経路。中ボタンの
  リスナーも Hand の左押下も同じ `PanDrag` を使う（一時ハンドと常時ハンドは
  `ToolState.active` の値でしか違わないので、経路の分岐は要らない）
- ズームの倍率は `zoom_factor(dy) = exp(-dy * ZOOM_RATE_PER_PIXEL)` 1 本。
  スクロールホイールはホイールの `dy` をそのまま渡し、Zoom のクリックは
  `ZOOM_CLICK_TRAVEL`（= ホイール 10 ノッチ分の 200px、≈ 1.49 倍）を渡す。
  別の倍率体系は作っていない
- 矩形ズームは `ViewerViewport::zoom_to_rect` を新設した（既存の `zoom_toward`
  のセマンティクスは変えていない）。短い側の比で合わせるので縦横比は保たれ、
  矩形の中心がパネル中心へ来る。両軸とも `ZOOM_RECT_MIN_PIXELS`（8px）に
  届かないドラッグはクリック扱い
- カーソルは `tool_pointer_hint` に集約した（ツール → `ViewerPointerHint` の
  唯一の写像。`ToolState` の observer と `pointer_hint_at` の両方がここを引く）。
  Hand は `OpenHand`、押下中は既存の `viewer_drag_cursor` が `ClosedHand` に
  し、Zoom は `Crosshair`。ハンドルを持つオーバーレイは 4 つとも `is_active` を
  `Select`（`PathEditOverlay` は `Select | Pen`）で閉じているので、Hand / Zoom の
  ためにパネル側でもう一段ゲートを置く必要は無い — 置いても落とせるテストが
  書けないため置いていない。約束と押下が一致することは
  `pointer_hint_at` の実測でテストに固定してある
- ドラッグ中の矩形は 1px の枠で描く。フィードバック無しの矩形ズームは
  「離すまで何も起きない」ジェスチャーになるため。`Escape` で取り消す

### TOOLX-2: 矩形選択

- Select ツールで空白からドラッグしたときに矩形選択を開始する
- 枠の描画はオーバーレイ機構（`OVL-1`）に乗せる
- Shift 開始で加算。**開始時の選択をキャプチャして和を publish する**
- 対象はネットワークが開いていればノード、無ければレイヤー

**依存**: `OVL-1`

**完了条件**

- 矩形と bbox の交差判定のテスト（境界に接する場合を含む）
- Shift 開始で既存選択が保たれるテスト（`LOW-APP-03` と同じ罠を踏まない）
- ドラッグが 0 距離のときは選択解除として扱われるテスト（既存のクリック挙動）
- 枠の描画がオーバーレイ機構経由であること

**実装メモ**

- 押下は `select_mouse_down` の中で分岐する。ヒットが無い（= 空白）ときだけ
  矩形選択が始まるので、ヒットのある場所からのドラッグは既存の `move_drag` の
  ままになる。ネットワークが開いていないとき（`CanvasSelection.path` が
  `None`、またはレイヤーが 2 枚以上選択されていて押下がどの bbox にも入らない
  とき）はレイヤー単位の矩形選択になる
- 交差判定は `rects_overlap`。**境界は閉じている**（辺・角が接するだけで掴む）。
  `rect_contains` が既に閉じた矩形として判定しており、クリックと矩形で境界の
  扱いが違うのは説明できないため。0 幅・0 高の bbox（点 1 個を置くジオメトリ）も
  掴めるという副作用は望ましい
- 距離 0 のドラッグはリリースで何も publish しない。押下が既にクリックの意味を
  publish しているので、和を publish すると空白クリックで消した選択が戻る
- **候補の bbox は評価済みでないと測れない。** `evaluated_bounds` はオーバーレイが
  宣言した評価ターゲットの結果を引くが、宣言しているのは
  `GeometryOverlay`（ノードが 1 つ以上選択されているとき）と
  `ShellManipulatorOverlay`（レイヤーが 1 枚選択されているとき）だけで、
  **何も選択していない状態には候補のデータが無い** — 矩形選択の本命の
  ユースケースがそこなので、ドラッグ中だけ有効な `BoxSelectOverlay` が候補を
  宣言する（開いているネットワークの `geometry_targets`、無ければアクティブ
  コンプの全レイヤーの分）
- そのため**スコープは Global**（`overlay::BoxSelectDrag`）に置く。評価要求を
  組み立てる `ProjectState::overlay_context_for_request` はパネルの状態を見られず、
  `is_active` / `eval_targets` が依存してよいフィールドしか埋めないので、
  そこから読めるのは Global だけ。矩形そのものはパネル側の状態から
  `OverlayContext` に載る（Viewer が 2 枚開いているとき、枠はポインタがいる方の
  ものだから）。Global は**スコープだけ**で、押下と離上の 1 回ずつしか書かない
  ので、ポインタ移動で評価要求が増えない
- **Global には所有者（`PanelInstanceId`）を載せる。** Viewer は複数開ける
  （REQ-UI-005）のに Global は 1 つなので、所有者を見ずにクリアすると
  **A のリリースが B の生きているドラッグの候補宣言を消す**。クリアは
  所有者一致のときだけ（`withdraw_box_select_candidates`）。
  **別の Viewer がドラッグ中に新しいドラッグが始まったら新しい方が奪う** —
  ポインタは 1 本なので、他インスタンスに残っているドラッグはリリースを
  取りこぼした古いもの。始めない側に振ると、古い方をつつくまでその Viewer が
  操作不能になる。奪う側に振れば、古いジェスチャーは自分のパネルの次の
  アイドル移動で畳まれ、所有者チェックのおかげで新しい宣言を消せない
- **ドラッグの畳み方はペンセッションと同じ規則**。意図的なツール切り替えで
  キャンセルし、`h` ホールド（一時ハンド）では保持する。アクティブコンプの
  変更でもキャンセルする（`set_active_composition` がレイヤー選択を書き換える
  ので、`LayerSelection` の observer がその報せになる。`ActiveComposition` の
  observer を増やさない）
- **レイヤースコープの押下もクリック相当の空選択を publish する。** ノード側は
  `select_mouse_down` が `selection_after_click` で publish しているので、
  揃えないと「レイヤーを選んだ状態で空白をクリックしても解除されない」になる
  （完了条件違反）。`initial` のキャプチャは publish の**前**
- 押下では**選択変更 observer と明示要求の 2 本が評価要求を出しうる**。
  observer は選択が実際に変わったときだけ要求するので、**何も選択していない
  状態で空白を押す**（矩形選択の本命）ケースでは要求が出ない — だから明示要求は
  省けない。両方出たときはワーカーが latest-wins で 1 回に畳む
- `rects_overlap` は**両辺が正規化済み（w, h >= 0）を前提**にする。掃いた矩形は
  `box_rect`、bbox は `geometry_bounds` / `transform_rect` が min/max で作るので
  負の幅は存在しない。ここで正規化を足すと「非正規化の矩形が来ることがある」
  という誤った前提をコードに書き込むことになる。NaN 座標は元からある穴で、
  その場合「何も選ばない」は安全側なのでこの単位では扱わない
- **残る制約**: 結果は非同期に届くので、ドラッグの最初の数フレームは箱の中身が
  空になりうる。確定はリリース時にその時点の結果で計算し直す

### TOOLX-3: ヒット対象のフォールバックと点編集

- アクティブレイヤー内でヒットが無いとき、他レイヤーの shape ノードを探す

- Alt ドラッグで接線の対称連動を切る
- 対称かどうかは接線の値から判定する（フラグを追加しない）

**完了条件**

- アクティブ内にヒットがあるとき他レイヤーを探さないテスト

- 点の削除が隣接接線を破壊しないテスト
- Alt ドラッグ後に反対側の接線が動かないテスト
- 一連の編集が 1 ジェスチャ 1 undo であるテスト
