# REQ-3D — 3D シーンと立体表現

2D コンポジット内に 3D 要素を配置する。**フル 3D シーンは目指さない。**
Element 3D / Cinema 4D Lite 相当のスコープで、主要ユースケースはリリック
モーションでの 3D テキスト多用。

REQ-MOGRAPH-003 が概要を定めていたが、実装に入れる粒度まで詳細化するために
本ファイルへ分割した。REQ-MOGRAPH-003 の ID は参照用に残す。

設計スケッチと実装単位は `docs/implementation/3d-scene-plan.md`。
ジオメトリ表現の規約は `docs/specifications/procedural-geometry.md`。

## REQ-3D-001: Scene とオブジェクト

- **優先度**: Should
- **ステータス**: Draft
- **説明**: Scene はノードグラフを流れるデータ型（`DataTypeId::SCENE`）で、
  **オブジェクト・カメラ・ライトのリスト**を持つ。オブジェクトは
  ジオメトリ（REQ-CORE-010）と 3D 変換の組で、ジオメトリは Mesh でも Path でも
  よい（平面的な表現を 3D 空間に置くため）。Scene を組み立てるノード
  （`scene.add` / `scene.camera` / `scene.light`）と、カメラを選んで
  FrameBuffer を出すノード（`scene.render`）で構成する。変換の階層は
  Scene を入れ子にすることで表す。Scene は subnet（REQ-LAYER-003）に
  収めて使い回せる。
- **受入条件**:
  - [ ] Scene にジオメトリをオブジェクトとして追加でき、3D 変換を与えられる
  - [ ] Mesh と Path の両方をオブジェクトにできる
  - [ ] Scene を入れ子にして変換の階層を作れる
  - [ ] `scene.render` が FrameBuffer を出し、殻の合成チェーンに流れる
  - [ ] 同一 Scene を複数のカメラで描画できる
- **依存**: REQ-CORE-010, REQ-3D-002, REQ-3D-003

## REQ-3D-002: カメラと投影

- **優先度**: Should
- **ステータス**: Draft
- **説明**: パースペクティブとオルソグラフィックのカメラを持つ。パラメータ
  （位置・注視点または回転・画角・near/far）は統一アニメーション
  チャネル（REQ-CORE-007）で駆動できる。投影は `scene.render` の内部で
  行い、ジオメトリの `P` を書き換えない（情報源を 1 つに保つ）。
- **受入条件**:
  - [ ] パースペクティブ / オルソグラフィックを選択できる
  - [ ] カメラパラメータにキーフレームを打てる
  - [ ] 投影後もジオメトリの `P` が元の値のままである
  - [ ] コンポジション解像度とアスペクト比が投影に反映される
- **依存**: REQ-CORE-007, REQ-3D-001

## REQ-3D-003: メッシュ表現と位置・回転データ

- **優先度**: Should
- **ステータス**: Draft
- **説明**: `Primitive::Mesh`（頂点範囲 + インデックス）をジオメトリ
  コンテナに追加する。コンテナ構造は変えず、`Primitive` の種別追加として
  行う。頂点位置 `P` の列型は**ジオメトリごとに Vec2（2D）と Vec3（3D）の
  どちらも許す**。位置の情報源を 2 つに分けない。

  変換データは**オーサリングと要素で表現を分ける**。人がキーフレームを
  打つ回転（Scene オブジェクト、レイヤー殻、ノードパラメータ）は
  オイラー角の成分別チャンネルとし、回転順を仕様で固定する。要素ごとの
  回転（Instance / Point 属性）はノードが計算する値なのでクォータニオン
  （`orient`: Vec4）とする。**統一アニメーションチャネルは成分ごとに
  独立補間するため、クォータニオンをキーフレーム対象にできない**（成分別に
  補間すると回転にならない）。
- **受入条件**:
  - [ ] `Primitive::Mesh` を持つジオメトリを構築・評価できる
  - [ ] `P` が Vec3 のジオメトリを既存の 2D ノードに通したときの挙動が
        仕様どおりである（対応 / 明示エラーの区別が文書と一致する）
  - [ ] Scene オブジェクトの回転にオイラー角でキーフレームを打てる
  - [ ] 要素ごとの回転が `orient` 属性として計算・消費される
  - [ ] 回転順が仕様で固定され、テストで pin されている
- **依存**: REQ-CORE-007, REQ-CORE-010

## REQ-3D-004: 押し出しとベベル

- **優先度**: Should
- **ステータス**: Draft
- **説明**: パスジオメトリ（テキスト輪郭を含む）を押し出して Mesh を生成する。
  前面・背面のキャップは多角形の三角形分割で埋め、側面は輪郭に沿って生成する。
  ベベルは押し出しの拡張として扱う。押し出し結果は通常のジオメトリなので、
  フィールド（REQ-CORE-012）とパーティクル（REQ-MOGRAPH-002）の影響を
  受けられる（REQ-MOGRAPH-004 の受入条件を満たすため、専用ノード内部で
  完結させる設計は採らない）。
- **受入条件**:
  - [ ] パスを押し出して Mesh になる
  - [ ] 穴あき形状（文字の `o` 等）のキャップが正しく埋まる
  - [ ] ベベルの幅・分割数を指定できる
  - [ ] 押し出した Mesh がフィールドで変調できる
  - [ ] 法線が生成され、ライティングに使われる
- **依存**: REQ-3D-003, REQ-MOGRAPH-004

## REQ-3D-005: 基本プリミティブ

- **優先度**: Should
- **ステータス**: Draft
- **説明**: ボックス / 球 / 円柱 / 平面を Mesh として生成する。2D の
  `shape.*` と対になる位置づけで、命名は 2D/3D の規約に従う
  （`docs/specifications/procedural-geometry.md`）。
- **受入条件**:
  - [ ] 4 種のプリミティブを生成できる
  - [ ] 分割数を指定できる
  - [ ] 法線と UV 相当の属性を持つ
- **依存**: REQ-3D-003

## REQ-3D-006: 基本ライティング

- **優先度**: Should
- **ステータス**: Draft
- **説明**: ディレクショナル / ポイント / アンビエントの 3 種。Scene に
  追加し、`scene.render` が Mesh の法線と合わせて陰影を計算する。
  **マテリアルとシェーダグラフは対象外**で、色は既存の `Cd` 属性と
  スタイル属性（`style-attributes-plan.md`）を使う。
- **受入条件**:
  - [ ] 3 種のライトを Scene に追加できる
  - [ ] ライトのパラメータにキーフレームを打てる
  - [ ] ライトが無い Scene でも Mesh が見える（アンビエント既定）
  - [ ] 法線を持たないジオメトリ（Path）がライティングで壊れない
- **依存**: REQ-3D-001, REQ-3D-003

## REQ-3D-007: 描画順と深度

- **優先度**: Should
- **ステータス**: Draft
- **説明**: 不透明な Mesh は深度バッファを使って描き、自己遮蔽（押し出し
  テキストの前面と側面の前後関係）が正しくなる。半透明オブジェクトと
  Path は `Pw.z` でソートして back-to-front で描き、深度テストは有効・
  深度書き込みは無効とする。

  **交差する半透明オブジェクト同士の前後関係は保証しない。** 現在の
  ラスタライザは Path をバウンド矩形に解析的カバレッジとして描くため、
  半透明部分が深度を書くと縁で背景が抜ける。この制約はスコープ線として
  明示する。
- **受入条件**:
  - [ ] 押し出しテキストの自己遮蔽が正しい
  - [ ] 半透明オブジェクトが不透明 Mesh の背後で正しく隠れる
  - [ ] Path のアンチエイリアス縁で背景が抜けない
  - [ ] 交差する半透明同士が不正確であることがテストで明示されている
        （将来の改善で挙動が変わったと分かるように）
- **依存**: REQ-3D-001, REQ-GPU-001

## REQ-3D-008: モデル読み込み

- **優先度**: Could
- **ステータス**: Draft
- **説明**: glTF / OBJ の 3D モデルを Mesh として読み込む。メディアアセット
  （REQ-PROJ-001 の相対パス解決）と同じ仕組みでプロジェクトに参照を持つ。
  マテリアル・アニメーション・スキニングは対象外で、**ジオメトリと法線のみ**
  読む。読み込んだ Mesh は通常のジオメトリなので、破砕（`geometry.cell_fracture_3d`）
  やフィールド変調の対象になる。
- **受入条件**:
  - [ ] glTF / OBJ からジオメトリと法線を読める
  - [ ] 複数メッシュを持つファイルの階層を Scene の入れ子として表現できる
  - [ ] アセット参照が相対パスで永続化される
  - [ ] 読み込んだ Mesh を破砕・変調できる
  - [ ] 読み込み失敗が UI に表示される
- **依存**: REQ-3D-003, REQ-PROJ-001

## 非対象

要件として**作らないと決めたもの**。「なぜ無いのか」に答えられる線を引く。

- **シャドウ / 反射 / グローバルイルミネーション**。ライティングは陰影計算
  のみ
- **マテリアル / シェーダグラフ**。色は `Cd` とスタイル属性で表す
- **交差する半透明の正確な前後関係**（REQ-3D-007）
- **3D 空間でのパーティクル**。REQ-MOGRAPH-002 は 2D のポイントジオメトリ
- **IK / リギング / アニメーションのインポート**
- **物理シミュレーション**。破砕は形状操作であり、破片の落下は対象外
- **3D テキストの縦書き / 複雑な組版**。REQ-MOGRAPH-004 の範囲
