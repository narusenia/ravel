# REQ-GPU — GPU計算パイプライン

## REQ-GPU-001: wgpu基盤 + ネイティブフォールスルー

- **優先度**: Must
- **ステータス**: Revised (v2 — 2026-08-03。バックエンドは REQ-INFRA-009 で内製化)
- **説明**: 通常のシェーダ処理は単一の GPU 抽象で統一。ハードウェアデコード（macOS VideoToolbox、Windows NVDEC/AMF等）やベンダー固有最適化が必要な箇所だけネイティブAPIにフォールスルー。UI 描画とコンピュートで GPU デバイスを共有する（これは移行を通じて維持する不変条件）。
  **v2**: 抽象の実装は当初 wgpu だが、REQ-INFRA-009 で Metal / D3D12 / Vulkan の
  内製バックエンドへ置き換える。この要件の受入条件はバックエンドに依らず成立する
  形に書いてある。
- **受入条件**:
  - [ ] コンピュートシェーダでノード評価が実行される
  - [ ] UI フレームワークと GPU デバイスが共有される
  - [ ] macOSでVideoToolbox経由のHWデコード出力をGPUメモリ上でゼロコピーで受け取れる
  - [ ] WindowsでNVDEC/AMF出力をGPUメモリ上で受け取れる
- **依存**: REQ-UI-001
- **関連**: REQ-INFRA-009（バックエンドの内製化）

## REQ-GPU-002: Hybridシェーダ管理

- **優先度**: Should
- **ステータス**: Draft
- **説明**: ビルトインシェーダはビルド時にコンパイルしてバイナリに埋め込み（起動速度確保）。ユーザーカスタムWGSLシェーダ（REQ-GPU-003）はランタイムコンパイル。開発ビルド（`#[cfg(debug_assertions)]`）では全シェーダがランタイムコンパイル + ホットリロード対応。
- **受入条件**:
  - [x] リリースビルドでビルトインシェーダがバイナリに埋め込まれている（TASK-005: `include_str!` 埋込）
  - [ ] ユーザーシェーダがランタイムでコンパイル・実行される
  - [ ] 開発ビルドで全シェーダのホットリロードが機能する
  - [ ] コンパイル済みシェーダのディスクキャッシュが機能する

## REQ-GPU-003: WGSLカスタムシェーダノード

- **優先度**: Should
- **ステータス**: Draft
- **説明**: ユーザーがWGSLを記述してカスタムエフェクトノードを作成できる。入出力テクスチャとユニフォームパラメータを宣言的に定義し、Ravelが実行環境を提供。Shadertoy的な体験。
  **宣言は REQ-PROJ-006 の公開パラメータ宣言と同じ機構を使う**（2026-08-03 追記）。
  同じ実行機構を manifest で配布可能にしたものが REQ-PLUGIN-002 の WGSL
  シェーダプラグインで、両者は「プロジェクト内のコンテンツか、配布物か」だけが違う。
- **受入条件**:
  - [ ] シェーダノードをノードグラフに追加できる
  - [ ] WGSLコードエディタ（シンタックスハイライト付き）が提供される
  - [ ] 入力テクスチャ、出力テクスチャ、ユニフォームパラメータを宣言できる
  - [ ] ユニフォームパラメータが統一アニメーションチャネル（REQ-CORE-007）に接続可能
  - [ ] コンパイルエラーがユーザーにわかりやすく表示される
- **依存**: REQ-GPU-001, REQ-GPU-002, REQ-CORE-007, REQ-PROJ-006
