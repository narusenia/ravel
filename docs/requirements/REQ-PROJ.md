# REQ-PROJ — プロジェクト管理

## REQ-PROJ-001: .ravprj zipコンテナ プロジェクトファイル

- **優先度**: Must
- **ステータス**: Draft
- **説明**: プロジェクトファイルは`.ravprj`拡張子のzipコンテナ。配布/受け渡し時は単一ファイル、編集中はワーキングディレクトリに展開して操作。git管理したい場合は展開状態のまま扱える。**派生キャッシュ（サムネイル・波形・フレーム）はコンテナ内に置かず、グローバルなキャッシュディレクトリに置く** — 未保存プロジェクトでも効かせるため、また保存サイズ・保存時間・保存のバイト決定性にキャッシュ生成を絡ませないため（REQ-CORE-006）。
- **内部構造**:
  ```
  project.ravprj (zip)
  ├── manifest.json          # バージョン、メタデータ
  ├── graph/
  │   ├── main.ron           # ルートノードグラフ
  │   └── subgraphs/         # サブグラフ定義
  ├── timeline/
  │   └── sequences.ron      # タイムライン永続化表現
  ├── assets/
  │   └── refs.json          # v4 で廃止（参照は document/main.ron に一本化）
  └── settings.toml          # プロジェクト固有設定
  ```
  派生キャッシュはコンテナ内に置かない（REQ-CORE-006）。
- **受入条件**:
  - [ ] `.ravprj`ファイルの保存/読み込みが動作する
  - [ ] zip圧縮/展開が正常に行われる
  - [ ] ノードグラフがRON形式で永続化される
  - [ ] アセット参照が相対パスで記録される
  - [ ] 派生キャッシュがコンテナに含まれない
  - [ ] git diff可能なテキスト形式でグラフが保存される

- **優先度**: Must
- **ステータス**: Draft
- **説明**: 定期自動保存に加え、全操作をジャーナル（WAL的）に追記。クラッシュ後は最後の自動保存 + ジャーナルリプレイで復元。REQ-CORE-004のイミュータブルデータ構造のバージョン履歴とジャーナルが対応。レンダリングやOFXプラグイン実行を子プロセスに分離し、クラッシュがメインプロセスに波及しない設計。自動保存間隔は設定UIで変更可能（秒数/操作数/無効化）。`.ravprj`内に`.journal/`を設け、正常終了時にコンパクション。

  - [ ] クラッシュ後にジャーナルリプレイで復元できる
  - [ ] OFXプラグインが別プロセスで実行される
  - [ ] プラグインプロセスのクラッシュがメインプロセスに影響しない
  - [ ] 正常終了時にジャーナルがコンパクションされる

- **優先度**: Must
- **ステータス**: Draft
- **説明**: `manifest.json`にフォーマットバージョンを記録。古いバージョンのプロジェクトを開く際、マイグレーション関数を順次適用して変換。マイグレーション実行前に`.ravprj.bak`として自動バックアップ。変更内容をユーザーに表示して確認を求める。不可逆な変更がある場合は警告。マイグレーション関数はバージョン連鎖（v1→v2→v3→...）で実装し、各ステップがユニットテスト可能。

  - [ ] 古いバージョンのプロジェクトが自動マイグレーションで開ける
  - [ ] マイグレーション前にバックアップが自動作成される
  - [ ] マイグレーション内容がユーザーに表示される
  - [ ] 不可逆変更に対して警告が表示される
- **依存**: REQ-PROJ-001

## REQ-PROJ-004: カテゴリ別設定 + プロジェクトオーバーライド

- **優先度**: Should
- **ステータス**: Draft
- **説明**: グローバル設定をカテゴリ別ファイル（general/appearance/keybindings/performance/plugins）で管理。設定UIで変更。プロジェクトごとに`settings.toml`でオーバーライド可能（カラースペース、FPS等）。設定のインポート/エクスポートで環境移行を容易に。パスはOS別に配慮（macOS: `~/Library/Application Support/Ravel/`、Windows: `%APPDATA%\Ravel\`、Linux: `~/.config/ravel/`）。`dirs`クレートで解決。
- **グローバル設定構造**:
  ```
  {config_dir}/
  ├── general.toml
  ├── appearance.toml    # テーマ設定含む
  ├── keybindings.toml
  ├── performance.toml
  └── plugins.toml
  ```
- **受入条件**:
  - [ ] グローバル設定が各カテゴリファイルに保存される
  - [ ] 設定UIで全設定を変更できる
  - [ ] プロジェクト固有設定でグローバル設定を上書きできる
  - [ ] 設定のインポート/エクスポートが可能
  - [ ] OS別の適切なパスに設定が保存される

## REQ-PROJ-006: 公開パラメータ宣言

- **優先度**: Must
- **ステータス**: Draft（2026-08-03 新設）
- **説明**: 「名前・型・既定値・説明を宣言し、内部のパラメータに束縛する」という
  **単一の機構**。宣言は外部から見える契約で、内部のノード構成・レイヤー名・
  配線を変えても壊れない。

  **統一するのは「宣言」の層だけ。** 名前・型・既定値・説明・束縛と、その検証・
  永続化・列挙を 1 つの機構にする。**その下のポート配管を統一するとは言っていない** —
  `network-interface-editing-plan.md` は `expose_param_port`（通常ノードのパラメータ
  昇格）と subnet の promote パラメータ（ピン同期が管理）を**別機構として維持する**と
  決めており、本要件はそれを変えない。宣言層はその上に載る。

  **4 つの用途が同じ宣言機構に乗る。** 別々に作ると同じものを 4 回設計することに
  なるので、1 つの要件として切り出す。

  | 用途 | 宣言の置き場 | 利用者 |
  |---|---|---|
  | テンプレートレンダリングの入力 | プロジェクト | REQ-RENDER-005（`--param 名前=値`） |
  | サブグラフテンプレートの公開パラメータ | サブグラフ | REQ-PLUGIN-005（HDA / Gizmo 相当） |
  | ネットワークインターフェース | レイヤーネットワーク | REQ-LAYER-002 / REQ-LAYER-003（`net.in` / `net.out`） |
  | シェーダノードの入出力とユニフォーム | シェーダ manifest | REQ-GPU-003、REQ-PLUGIN-002 |

  値の範囲は**定数**（数値 / ベクトル / 色 / bool / 文字列）と**素材参照**
  （メディアファイル）。キーフレーム・カーブ・パス形状の丸ごと差し替えは対象外で、
  必要になったら別要件にする（`ParameterValue` の内部表現を外部契約に露出させない
  ため）。宣言された入力は統一アニメーションチャネル（REQ-CORE-007）の値ソースを
  置き換えるのではなく、その**既定値を与える**位置に立つ。

  素材参照の解決は REQ-PROJ-005 の変数・相対パス規約に従う。不在の素材は
  「黙って空フレーム」ではなく明示的な失敗として扱う。

- **受入条件**:
  - [ ] 名前・型・既定値・説明を持つ公開入力を宣言できる
  - [ ] 宣言が内部の任意のパラメータへ束縛される
  - [ ] 宣言が `.ravprj` に永続化され、旧バージョンからマイグレーションできる
  - [ ] 束縛先のノードやレイヤーを改名・再配線しても宣言が壊れない
  - [ ] ポート名 / パラメータキーの改名時に宣言の束縛が同一コミットで追従する
        （`network-interface-editing-plan.md` の「改名は 4 箇所を 1 つの操作で
        書き換える」に宣言を加える）
  - [ ] 宣言に無い名前を与えたとき、型が合わないときは明示的なエラーになる
  - [ ] 宣言の一覧を機械可読形式で取得できる（CLI から入力を発見できる）
  - [ ] 素材参照を差し替えられ、不在の素材が明示的な失敗になる
  - [ ] 宣言の追加 / 削除 / 改名 / 並べ替えを UI から行える
  - [ ] 同じ宣言機構でサブグラフテンプレートの公開パラメータが表現できる
- **依存**: REQ-PROJ-001, REQ-PROJ-003, REQ-LAYER-002, REQ-LAYER-003,
  REQ-CORE-007
