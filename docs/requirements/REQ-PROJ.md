# REQ-PROJ — プロジェクト管理

## REQ-PROJ-001: .ravprj zipコンテナ プロジェクトファイル

- **優先度**: Must
- **ステータス**: Draft
- **説明**: プロジェクトファイルは`.ravprj`拡張子のzipコンテナ。配布/受け渡し時は単一ファイル、編集中はワーキングディレクトリに展開して操作。git管理したい場合は展開状態のまま扱える。**派生キャッシュ（サムネイル・波形・フレーム）はコンテナ内に置かず、グローバルなキャッシュディレクトリに置く** — 未保存プロジェクトでも効かせるため、また保存サイズ・保存時間・保存のバイト決定性にキャッシュ生成を絡ませないため（REQ-CORE-006）。
- **内部構造**:
  ```
  project.ravprj (zip)
  ├── manifest.json          # バージョン、メタデータ
  ├── graph/
  │   ├── main.ron           # ルートノードグラフ
  │   └── subgraphs/         # サブグラフ定義
  ├── timeline/
  │   └── sequences.ron      # タイムライン永続化表現
  ├── assets/
  │   └── refs.json          # v4 で廃止（参照は document/main.ron に一本化）
  └── settings.toml          # プロジェクト固有設定
  ```
  派生キャッシュはコンテナ内に置かない（REQ-CORE-006）。
- **受入条件**:
  - [ ] `.ravprj`ファイルの保存/読み込みが動作する
  - [ ] zip圧縮/展開が正常に行われる
  - [ ] ノードグラフがRON形式で永続化される
  - [ ] アセット参照が相対パスで記録される
  - [ ] 派生キャッシュがコンテナに含まれない
  - [ ] git diff可能なテキスト形式でグラフが保存される

  - [ ] マイグレーション内容がユーザーに表示される
  - [ ] 不可逆変更に対して警告が表示される
- **依存**: REQ-PROJ-001

## REQ-PROJ-004: 設定の層マージ + 設定 UI + プロジェクトオーバーライド

- **優先度**: Should
- **ステータス**: Revised (v2 — 2026-08-03 カテゴリ別 5 ファイルを単一
  `settings.toml` に変更)
- **説明**: グローバル設定を**単一の `settings.toml`** で管理する。設定は
  `default → global → project → user` の 4 層マージで解決し、**後ろの層が前を
  上書きする**（= プロジェクト固有設定がグローバル設定に勝つ）。設定 UI は
  **2 画面**で、書き込む層は画面が決める — 環境設定が `global` 層、
  プロジェクト設定が `project` 層（`.ravprj` 内の `settings.toml`）。
  プロジェクト側でオーバーライドするのは既定フレームレート、将来のカラースペース。
  設定のインポート / エクスポートで環境移行を容易にする。パスは OS 別に配慮
  （macOS: `~/Library/Application Support/ravel/`、Windows: `%APPDATA%\ravel\`、
  Linux: `~/.config/ravel/`）。`dirs` クレートで解決。
- **カテゴリ別 5 ファイル構成は採らない**（v1 からの変更）: 4 層マージが単一
  ファイルで動いており、分割は読み込み先を 4×5 に増やすだけで得が無い（項目は
  まだ十数件）。**キーバインドだけは例外で別ファイル**（既定アセットと同じ形式
  なので、他人が作ったプリセットをそのまま置ける。層マージがフィールド単位なのに
  対し、バインドはコマンド単位でマージし chord を別コマンドから外す規則を持つ）。
  ワークスペース配置も層化しないので別ファイル。判断の根拠は
  [`../implementation/settings-screen-plan.md`](../implementation/settings-screen-plan.md)。
  項目がファイルとして扱いにくい規模に育ったら分割を再検討する。
- **グローバル設定構造**（`<config_base>` は OS 別の設定ベース。上記参照）:
  ```text
  <config_base>/ravel/
  ├── settings.toml       # 4 層マージの global 層（全カテゴリ）
  ├── keybindings.toml    # キー割り当ての上書き（形式が別なので別ファイル）
  └── layout.toml         # ワークスペース配置（層化しないので別ファイル）
  ```
- **「出す項目 = 効く項目」**: 設定画面に項目を出す条件は、その設定が挙動に
  反映されること。効かない項目は画面に存在させない（グレーアウトでもなく）。
  現在**未対応**の設定は次のとおりで、前提機能が入った時点で画面に足す。

  | 設定 | 未対応の理由 | 担当 |
  |---|---|---|
  | プロキシ（モード / 解像度） | プロキシ生成が未実装（REQ-PROJ-005） | `SET-10` |
  | カラー管理（OCIO / working / display space） | カラー管理が未実装（REQ-RENDER-003） | `SET-11` |
  | 自動保存（間隔 / 無効化） | 自動保存タイマー自体が無い（REQ-PROJ-002） | `SET-9` |
  | キャッシュ（場所 / 各層の上限） | `settings.toml` の `[cache]` は解決されるが走行中の予算へ届いていない（`CacheBudget` 自体は実装済み） | `SET-8` |
  | プラグイン | REQ-PLUGIN 系が未実装 | 未定 |

- **受入条件**:
  - [x] グローバル設定が `<config_base>/ravel/settings.toml` に保存される
  - [x] 挙動に反映される設定は設定 UI から変更できる（言語、テーマモード、
        ライト / ダークのテーマ、プロジェクトの既定フレームレート）。キー割り当ては
        一覧までで、編集は REQ-UI-007 / `SET-12`
  - [x] プロジェクト固有設定でグローバル設定を上書きできる
  - [ ] 設定のインポート / エクスポートが可能 — 未実装。担当は `SET-13`
        （項目が揃ってから。今やると出力形式が毎回変わる）
  - [x] OS 別の適切なパスに設定が保存される

## REQ-PROJ-006: 公開パラメータ宣言

- **優先度**: Must
- **ステータス**: Draft（2026-08-03 新設）
- **説明**: 「名前・型・既定値・説明を宣言し、内部のパラメータに束縛する」という
  **単一の機構**。宣言は外部から見える契約で、内部のノード構成・レイヤー名・
  配線を変えても壊れない。

  **統一するのは「宣言」の層だけ。** 名前・型・既定値・説明・束縛と、その検証・
  永続化・列挙を 1 つの機構にする。**その下のポート配管を統一するとは言っていない** —
  `network-interface-editing-plan.md` は `expose_param_port`（通常ノードのパラメータ
  昇格）と subnet の promote パラメータ（ピン同期が管理）を**別機構として維持する**と
  決めており、本要件はそれを変えない。宣言層はその上に載る。

  **4 つの用途が同じ宣言機構に乗る。** 別々に作ると同じものを 4 回設計することに
  なるので、1 つの要件として切り出す。

  | 用途 | 宣言の置き場 | 利用者 |
  |---|---|---|
  | テンプレートレンダリングの入力 | プロジェクト | REQ-RENDER-005（`--param 名前=値`） |
  | サブグラフテンプレートの公開パラメータ | サブグラフ | REQ-PLUGIN-005（HDA / Gizmo 相当） |
  | ネットワークインターフェース | レイヤーネットワーク | REQ-LAYER-002 / REQ-LAYER-003（`net.in` / `net.out`） |
  | シェーダノードの入出力とユニフォーム | シェーダ manifest | REQ-GPU-003、REQ-PLUGIN-002 |

  値の範囲は**定数**（数値 / ベクトル / 色 / bool / 文字列）と**素材参照**
  （メディアファイル）。キーフレーム・カーブ・パス形状の丸ごと差し替えは対象外で、
  必要になったら別要件にする（`ParameterValue` の内部表現を外部契約に露出させない
  ため）。宣言された入力は統一アニメーションチャネル（REQ-CORE-007）の値ソースを
  置き換えるのではなく、その**既定値を与える**位置に立つ。

  素材参照の解決は REQ-PROJ-005 の変数・相対パス規約に従う。不在の素材は
  「黙って空フレーム」ではなく明示的な失敗として扱う。

- **受入条件**:
  - [ ] 名前・型・既定値・説明を持つ公開入力を宣言できる
  - [ ] 宣言が内部の任意のパラメータへ束縛される
  - [ ] 宣言が `.ravprj` に永続化され、旧バージョンからマイグレーションできる
  - [ ] 束縛先のノードやレイヤーを改名・再配線しても宣言が壊れない
  - [ ] ポート名 / パラメータキーの改名時に宣言の束縛が同一コミットで追従する
        （`network-interface-editing-plan.md` の「改名は 4 箇所を 1 つの操作で
        書き換える」に宣言を加える）
  - [ ] 宣言に無い名前を与えたとき、型が合わないときは明示的なエラーになる
  - [ ] 宣言の一覧を機械可読形式で取得できる（CLI から入力を発見できる）
  - [ ] 素材参照を差し替えられ、不在の素材が明示的な失敗になる
  - [ ] 宣言の追加 / 削除 / 改名 / 並べ替えを UI から行える
  - [ ] 同じ宣言機構でサブグラフテンプレートの公開パラメータが表現できる
- **依存**: REQ-PROJ-001, REQ-PROJ-003, REQ-LAYER-002, REQ-LAYER-003,
  REQ-CORE-007
