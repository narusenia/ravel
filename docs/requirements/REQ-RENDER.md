# REQ-RENDER — レンダリング・エクスポート

## REQ-RENDER-001: キューベースバックグラウンドレンダリング

- **優先度**: Must
- **ステータス**: Draft
- **説明**: レンダージョブをキューに積み、バックグラウンドで順次処理。編集作業と並行可能。ジョブ管理UI（進捗、一時停止/再開、キャンセル、優先度変更）を提供。レンダリングはREQ-CORE-005の評価スレッドプール + デコードプールを使用。
  レンダーワーカーは**GUI と CLI（REQ-RENDER-005）の共有部品**とし、UI に依存
  しない層に置く。したがって `.ravprj` の永続化も GUI 非依存でなければならない
  （`.agents/rules/rust.md` の「persistence logic must work without a live UI」）。
  ジョブは投入時の `Arc<Document>` スナップショットを持ち、レンダー中の編集は
  出力に影響しない。
- **受入条件**:
  - [ ] レンダージョブをキューに追加できる
  - [ ] バックグラウンドでレンダリングが実行される
  - [ ] レンダリング中も編集操作が可能
  - [ ] ジョブの進捗がUIに表示される
  - [ ] ジョブの一時停止/再開/キャンセルが可能
- **依存**: REQ-CORE-002, REQ-CORE-005

## REQ-RENDER-002: Write Nodeノード単位中間出力

- **優先度**: Should
- **ステータス**: Draft
- **説明**: 任意のノードの出力にWrite Nodeを接続し、中間ファイルとして書き出し可能。デバッグや素材生成に使用。Write Nodeもレンダーキュー（REQ-RENDER-001）で管理。出力フォーマットはFFmpeg経由で全コーデック対応。画像シーケンス（EXR/PNG/TIFF/DPX）出力もサポート。
- **受入条件**:
  - [ ] Write Nodeをノードグラフに追加できる
  - [ ] 任意ノードの出力をファイルに書き出せる
  - [ ] 出力フォーマット（コーデック/コンテナ）を選択できる
  - [ ] 画像シーケンスとして出力できる
  - [ ] レンダーキューで管理される
- **依存**: REQ-RENDER-001, REQ-MEDIA-001

## REQ-RENDER-003: OCIO + GPU LUTカラーマネジメント

- **優先度**: Must
- **ステータス**: Draft
- **説明**: OpenColorIO（OCIO）で色変換を統一管理。ACES/Rec.709/sRGB/Rec.2020等のカラースペース変換。`.ocio`設定ファイルをプロジェクトに読み込み可能。ビューア表示用にOCIO変換をGPU 3D LUTにベイクしwgpuシェーダで適用（リアルタイム性確保）。LUT再生成は設定変更時のみ。RustからはFFI経由。
- **受入条件**:
  - [ ] `.ocio`設定ファイルを読み込める
  - [ ] 入力/作業/表示カラースペースを設定できる
  - [ ] カラースペース変換が正確に動作する
  - [ ] ビューア表示にGPU LUTが適用される
  - [ ] ACES, Rec.709, sRGB, Rec.2020がサポートされる
- **依存**: REQ-GPU-001

## REQ-RENDER-004: モーションブラー

- **優先度**: Should
- **ステータス**: Draft（2026-07-27 新設）
- **説明**: レイヤー単位のモーションブラー。シャッター区間を N 分割して評価し積算する `Sampled` モードを基本とし、要素速度から方向性のあるにじみを作る `Velocity` モードを将来追加する。モードはユーザーが明示的に選ぶ（プレビューと書き出しでシステムが黙って方式を差し替えない）。サンプリングはレイヤーのネットワーク全体に及び、殻の Transform だけでなくネットワーク内部の時変要素（文字単位アニメーション等）もブレる。シャッター角度・位相は Composition 設定、有効化はレイヤー単位。実装計画は `docs/implementation/motion-blur-plan.md`。
- **前提**: アニメーションチャネルの連続時間評価（`KeyframeCurve::sample(f64)`）。現行は整数フレームのみで、サブフレーム評価してもキーフレーム駆動の要素がブレない。
- **受入条件**:
  - [ ] レイヤー単位で有効化でき、シャッター角度・位相が設定できる
  - [ ] 等速直線運動が期待範囲ににじむ
  - [ ] 回転がその方向にブレる
  - [ ] レイヤーネットワーク内部で動く要素（文字単位アニメーション等）がブレる
  - [ ] 時不変サブグラフがサンプル数ぶん再評価されない
  - [ ] プレビューと最終で品質段階（サンプル数）を分けられる
  - [ ] サンプル数 1 で無効時と一致する
- **依存**: REQ-CORE-002, REQ-CORE-006, REQ-CORE-007, REQ-CORE-009

## REQ-RENDER-005: CLI ヘッドレスレンダリング

- **優先度**: Must
- **ステータス**: Draft（2026-08-03 新設）
- **説明**: GUI を起動せずに既存の `.ravprj` をレンダリングするコマンドライン
  経路。用途はテンプレートレンダリング（1 つのプロジェクトを雛形に、文字・色・
  数値・素材を差し替えて複数本を書き出す）と CI / バッチ / レンダーファーム。
  差し替え対象は **REQ-PROJ-006 の公開パラメータ宣言**で、`--param <名前>=<値>`
  として名前で指定する。レイヤー名やノードパスではないので、内部構造を変えても
  外部から見た契約が壊れない。

  CLI と GUI の書き出しは**同一のレンダーワーカーを使う**（REQ-RENDER-001）。
  `Quality::Final` と `min_precision = F32` を要求し、プレビュー用に縮約された
  キャッシュを踏まない。

  **`.ravprj` は読み取り専用に開く。** パラメータ上書きはメモリ上の `Document`
  にのみ適用し、ロード時マイグレーションの結果も書き戻さない。したがって GUI が
  同じファイルを開いていても安全で、ロックを要らない。

  **フレーム範囲を指定して外部から分割できる。** 連番出力のファイル名は指定範囲に
  依らず**絶対フレーム番号**になるので、`--range` を分けた N プロセスの出力を
  そのまま連結できる。プロセス内並列レンダリングは非対象（分割は呼び出し側の
  責任）。動画コンテナ出力は分割できない（結合が別問題）。

  **音声を含む**。動画コンテナ出力では多重化し、連番出力では同じ範囲の WAV を
  併置する。音声トラックを持つプロジェクトを音声なしで書き出す状況では警告を
  出す（黙って音が消えない）。

- **受入条件**:
  - [ ] GUI を起動せずに `.ravprj` を指定範囲でレンダリングできる
  - [ ] 出力先・コンプ・フレーム範囲・形式をコマンドライン引数で指定できる
  - [ ] 公開パラメータを名前で上書きでき、宣言に無い名前と型不一致は
        レンダリング開始前にエラーになる
  - [ ] 素材ファイルを差し替えられ、不在の素材は開始前にエラーになる
  - [ ] 連番出力のファイル名が `--range` に依らず絶対フレーム番号になる
  - [ ] 音声が出力に含まれる（コンテナは多重化、連番は WAV 併置）
  - [ ] 音声トラックがあるのに音声を出さない設定では警告が出る
  - [ ] `.ravprj` が書き換わらない（マイグレーション結果も書き戻さない）
  - [ ] 失敗が分類された終了コードになる（引数不正 / ロード失敗 / パラメータ
        不一致 / 評価失敗 / エンコード失敗 / 中断）
  - [ ] 進捗と結果が機械可読形式で出力でき、CI からパースできる
  - [ ] 同一入力・同一範囲で 2 回実行して連番出力がビット等価になる
  - [ ] 中断時に書きかけのファイルが残らない
  - [ ] 利用不可なコーデックを指定したとき、理由付きで開始前に失敗する
- **依存**: REQ-RENDER-001, REQ-PROJ-006, REQ-CORE-005, REQ-CORE-009,
  REQ-MEDIA-001, REQ-MEDIA-002
