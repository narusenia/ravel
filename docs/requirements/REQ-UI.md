## REQ-UI-003: Composition タイムライン（AEモデル）

- **優先度**: Must
- **ステータス**: Revised (v3 — レイヤーネットワークモデル)
- **説明**: タイムラインパネルは選択中の Composition 内 Layer 群を表示する。左パネルに Layer リスト（名前、solo/mute/lock、▼プロパティ展開）、右パネルに時間軸上の Layer バー（in/out 範囲）とキーフレーム菱形を表示する。Layer のプロパティ（position/scale/rotation/opacity 等）を ▼ で展開し、キーフレームの追加・移動・削除が可能。v3: レイヤーのノードネットワークをノードエディタで開いて自由な接続編集が可能（REQ-LAYER-011）。キーフレームを持つネットワーク内パラメータもプロパティツリーに列挙する（REQ-LAYER-004）。内部表現は常にノードグラフで、タイムラインUIは Composition の「ビュー」として機能する。
- **NLE的クリップ配置は廃止**: Track/Clip ベースの NLE モデルは採用しない。メディアは Layer のネットワーク内の Video ノード（REQ-LAYER-008）として配置する。複数メディアの切り替えはプリコンプで実現する。
- **受入条件**:
  - [ ] Layer の追加・削除・並べ替え（合成順序変更）が可能
  - [ ] Layer の in/out フレームをドラッグで変更（トリム）できる
  - [ ] Layer の start_frame をドラッグで変更（スリップ）できる
  - [ ] Layer のプロパティ（Transform 等）を展開しキーフレームを打てる
  - [ ] キーフレームの菱形がタイムライン上に表示される
  - [ ] キーフレームを持つネットワーク内パラメータがプロパティツリーに列挙される
  - [ ] Layer のノードネットワークをノードエディタで開ける
  - [ ] Composition 間の遷移（Outliner からダブルクリック等）が可能
        — REQ-UI-013 で設計・実装する
  - [ ] ノードグラフでの変更がタイムライン表示に反映される
- **依存**: REQ-UI-001, REQ-CORE-001

## REQ-UI-005: ワークスペースプリセット + フリードッキング

- **優先度**: Must
- **ステータス**: Revised (v2 — 2026-07-31 フリードッキング設計確定)
- **説明**: デフォルトのワークスペースプリセット（Edit/Node/Color/Motion）を提供。
  レイアウトは再帰 Split ツリー + エリア内タブで表現し、独自実装のドッキング
  UI（`ravel-dock`）で描画する。v2 で `gpui_component` の dock 依存を廃止する
  （テーマ・汎用部品は引き続き `gpui_component` に従う）。
  ウィンドウ内フローティング（オーバーレイパネル）は採用せず、浮くパネルは
  デタッチ（REQ-UI-009）に一本化する。
- **多重インスタンス**: 同一パネルを複数枚表示できる（全 17 種、例外なし）。
  ドキュメント状態（プロジェクト・選択・アクティブコンプ・再生ヘッド）は
  共有し、ビュー状態（ズーム/パン/スクロール/表示対象）はインスタンスごとに
  独立（Document/View 分離）。Viewer の複数枚は評価コストが可視インスタンス数に
  比例する（同一コンプ・同一フレームはキャッシュ共有）。
- **再配置操作**: タブの D&D（エリア端ドロップ = その方向に分割、中央 =
  タブ合流、ウィンドウ外 = デタッチ）とエリアメニュー（右/下に分割・
  複製して分割・エリアを閉じる）。境界ドラッグでリサイズ。
  Blender 式コーナードラッグは採用しない。
- **View トグル**: レイアウトツリーに無いパネルのトグルは `PanelKind` ごとの
  既定スロットへ挿入する（#181 の解消。`panel-placement-plan.md` を吸収）。
- **永続化**: 全ウィンドウのレイアウトと配置をアプリレベル設定に保存し
  起動時に復元。カスタムワークスペースの名前付き保存/復元。`.ravprj` への
  埋込は保存時オプトイン（既定 OFF）で、開いたときの適用はセッション限定 —
  アプリレベルの既定レイアウトやプリセットは書き換えない。
- **デフォルトプリセット**:
  - **Edit**: タイムライン + ビューア + メディアビン + プロパティ
  - **Node**: ノードグラフ + ビューア + プロパティ + カーブエディタ
  - **Color**: ビューア + スコープ群 + ノードグラフ（カラコレチェーン）
  - **Motion**: ノードグラフ + ビューア + カーブエディタ + テキストエディタ
- **受入条件**:
  - [x] デフォルトプリセットで起動できる
  - [x] プリセットを切り替えられる
  - [x] パネルの追加/削除/リサイズが可能
  - [x] タブ D&D とエリアメニューで分割・タブ合流・複製分割ができる
  - [x] 同一パネルを 2 枚出し、ビュー状態が独立している
        （Viewer を「Duplicate into Split」で 2 枚並べ、片方だけグリッド
        オーバーレイを ON にして状態が分かれることを実機確認。インスタンスは
        別エンティティなので独立は構造上の帰結。なお `ravel_ui::ViewStates`
        自体は現時点で呼び出し元ゼロ）
  - [x] 全プリセットで全 17 パネルの View トグルが機能する
        （`view.toggle_*` は 14 コマンドで 17 種すべてに到達する —
        `view.toggle_scopes` が Waveform / Vectorscope / Histogram / Parade を
        まとめて動かす。網羅テストは `ravel-ui` の
        `every_panel_kind_is_reachable_from_a_view_toggle_command` と
        `every_panel_toggles_into_every_preset`）
  - [x] レイアウトがアプリ再起動で復元される
  - [x] カスタムワークスペースを保存/復元できる
  - [x] `.ravprj` 埋込レイアウトがオプトインで保存・適用され、アプリ既定を
        書き換えない
- **依存**: REQ-UI-001

## REQ-UI-009: マルチモニタ + デタッチ + 専用ビューアウィンドウ

- **優先度**: Should
- **ステータス**: Revised (v2 — 2026-07-31 全ウィンドウ同型モデル)
- **説明**: パネルをメインウィンドウから切り離して別モニタに配置可能。
  ワークスペースは「N 個のウィンドウ、各々が 1 本のレイアウトツリー」で、
  メインウィンドウは windows[0] に過ぎない（全ウィンドウ同型）。デタッチ
  ウィンドウも分割・タブ受け入れ可能で、メイン/分離でコードパスを分けない。
  ビューアを専用全画面ウィンドウとして別モニタに表示するモード。OCIO + GPU
  LUTを適用したカラースペース考慮のプレビュー。GPUIの複数ウィンドウ対応を活用。
- **クローズ意味論**: 分離ウィンドウのクローズはパネルインスタンスの破棄
  （多重インスタンスにより喪失は起きない）。戻し導線はタブの窓間 D&D と
  `Cmd+Shift+R`（フォーカス窓の全パネルをメインへタブとして戻して閉窓）。
- **メイン窓との連動**: メインのクローズで全分離窓が閉じ、メインの最小化に
  分離窓が追従して隠れる（復帰で再表示）。フォーカスは連動しない。
- **TitleBar**: 全ウィンドウが共通のカスタム TitleBar（`gpui_component::TitleBar`
  ベース）を持つ。メイン = プロジェクト名、分離 = ウィンドウタイトル
  （単一パネルならパネル名、複数なら件数）+ AlwaysOnTop ピン。
  **プリセット切替は TitleBar に置かない**（`Cmd+F1`〜`F4` と Workspace
  メニューが経路。バーは窓の識別に徹する）。
- **AlwaysOnTop**: 分離ウィンドウを常に前面に固定できる（TitleBar のピンで
  実行時トグル。gpui-ce-ravel フォークの `set_always_on_top` を使用）。
- **受入条件**:
  - [x] パネルをデタッチして別ウィンドウにできる（タブの窓外ドラッグ /
        `Cmd+Shift+D`）
  - [x] 分離ウィンドウ内で分割・タブ合流ができる
  - [x] 分離ウィンドウをクローズボタンで閉じてもシェル状態が矛盾しない
        （MED-APP-01 の解消）
  - [x] 分離ウィンドウに共通 TitleBar が表示され、AlwaysOnTop を
        トグルできる
  - [x] メインの最小化・クローズに分離窓が追従する
  - [x] 分離ウィンドウでダイアログ・通知が表示される
  - [ ] ビューアを全画面ウィンドウとして表示できる
  - [ ] デタッチウィンドウにOCIOカラースペースが適用される
- **依存**: REQ-UI-001, REQ-UI-005

## REQ-UI-011: Viewer ツールシステム（選択・移動・ペン・シェイプ描画）

- **優先度**: Must
- **ステータス**: Draft (v1 — 2026-07-21 設計確定)
- **説明**: Viewer 上で直接操作するツールセットを導入する。v1 は
  選択/移動 (V)・ペン (P)・矩形描画 (R)・楕円描画 (E)・ハンド (H)・
  ズーム (Z)。ツール状態は durable Global、切替は CommandId + Action、
  ツールバーは Viewer 内上部ストリップ（lucide アイコンを既存の
  vendoring 方式で追加）。どのツール中も中ボタンドラッグ = パン、
  H はタップで切替・ホールドで一時ハンド（当初案の Space 一時ハンドは
  トランスポートの再生/停止と衝突するため H ホールドへ変更）。
- **選択モデル**: 選択の正を `CanvasSelection`（NetworkPath + ノード集合）
  の durable Global に一元化し、Node Editor はパネル内部の選択状態を
  廃止してこれを読み書きする（二重状態による同期漏れの排除）。
  Viewer クリック選択のヒット対象は v1 ではアクティブレイヤー
  （Node Editor が開いている network）内の geometry ノードに限定する
  （ヒット候補の評価コストが選択駆動評価の既存経路に閉じるため）。
  他レイヤーへのフォールバック（アクティブ内ヒットなし → 他レイヤー）は
  v1.5 で拡張する。ヒットは評価済みジオメトリの AABB 近似
  （ピクセル精度ヒットは v2）。Shift+クリックでトグル追加。
- **バウンディングボックス**: 選択ノードの評価済み bounds を Viewer に
  オーバーレイ表示する（複数選択は合成 AABB + 薄い個別枠）。表示には
  レイヤー殻 transform を順方向に適用し、見た目と常に一致させる。
  編集（移動・ペン）は殻 transform が identity のレイヤーでのみ有効とし、
  非 identity では読み取り専用表示にする（原則:「表示は常に正しく、
  編集可能条件は明確に」。見た目座標での逆変換編集は v2）。
- **移動セマンティクス**: bbox ドラッグで移動できるのは「位置を自身の
  パラメータに持つノード」のみ — `center_x`/`center_y` を持つノード
  （shape 系・scatter 系）、`PathPoints` を持つノード（全制御点 `p` の
  一括オフセット。接線は点からの相対オフセットなので値を保持）、および
  直下流に既存の `geometry.transform` がある
  ノード（その translate を書く）。ツールによる暗黙のノード自動挿入は
  行わない（ノードグラフが正という原則を守る）。ドラッグ中は bbox 枠を
  ローカル予測で即時追従させ、ジオメトリ本体は背景評価に追従させる。
  1 ドラッグ = 1 undo（apply → commit、Esc で revert — Timeline の
  バー移動と同規約）。複数選択は移動可能ノード全部へ同一デルタ。
- **シェイプ描画**: ドラッグ矩形から shape.rect / shape.ellipse ノードを
  生成する（中心→center、寸法→size、Shift=正形、Alt=中心から描画）。
  生成先はアクティブレイヤーの network で、既存 rasterize の geometry
  入力が空いていれば自動接続（埋まっていれば未配線で置く。merge の
  自動挿入はしない）。レイヤーが無ければ Shape レイヤーテンプレートを
  自動作成する。polygon/star はドラッグ 1 回で決まらないため
  Add Node 経由のまま（v1 対象外）。
- **ペン**: ベジェは予約点属性 `in_tan`/`out_tan`（Vec2）で表現し、
  `Primitive::Path` は不変。点列は `ParameterValue::PathPoints`
  （`Vec<PathPoint>`、PathPoint = p/in_tan/out_tan）として
  `shape.custom_path` のパラメータに保存する（undo・RON 永続化・
  Properties は既存経路に乗る）。描画はクリック=コーナー/ドラッグ=
  スムーズ対称/始点クリックで閉路/Esc 確定、既存点・ハンドルの移動可。
  点の挿入/削除/Alt でのハンドル分離は v1.5。新規パス描画時は
  path→rasterize を自動配線し選択を切り替える。曲線の描画は
  comp 空間固定 tolerance の**共有フラット化**（CPU zeno と GPU に
  同一折れ線を渡し、GPU/CPU 等価性テストを維持）。GPU シェーダでの
  曲線直接評価は将来展望（v2 以降）。座標系は comp ピクセル空間
  （レイヤー殻の逆変換は v2）。パスアニメーション（点列の時間変化）は
  実装せず、PathChannel の設計書のみ実装計画に含める。
- **吸着・定規・ガイド**: ドラッグ中の吸着はスクリーン距離 8px を閾値とし、
  コンプ枠の端と中心・セーフエリア・ユーザーガイド・動かしていないレイヤーの
  bbox を候補にする。抑制はプラットフォームの主修飾キー（Cmd / Ctrl）で、
  Alt は中心描画とアンカー基準スケールに割り当て済みなので使わない。Shift が
  拘束として効くジェスチャー（シェイプ描画・殻のスケール）では吸着しない。
  ユーザーガイドは Viewer の定規からドラッグして置き、`Composition.guides` に
  持つ（`.ravprj` の版は上げない追加フィールド）。表示 / 非表示とロックは
  セッション状態で、ロック中のガイドは動かせないが吸着候補には残り、非表示の
  ガイドは候補から外れる。
- **受入条件**:
  - [ ] V/P/R/E/H/Z でツールが切り替わり、ツールバーに現在ツールが示される
  - [ ] H ホールドで一時ハンド、離すと元ツールに戻る。中ドラッグは常にパン
  - [ ] 選択ノードの bbox が Viewer に表示され、殻 transform 込みで
        見た目と一致する
  - [ ] Viewer クリックでアクティブレイヤー内のシェイプを選択でき、
        Node Editor のハイライトと Properties が追従する
  - [ ] bbox ドラッグで shape / custom_path / 直下流 transform 持ちノードが
        移動でき、1 ドラッグ = 1 undo、Esc でキャンセルできる
  - [ ] ドラッグで rect / ellipse を描画でき、rasterize へ自動配線される
  - [ ] ペンでコーナー/スムーズ点の混在パスを描き、閉路・確定でき、

  - [ ] 曲線が CPU / GPU 両経路で同一に描画される

  - [x] Cmd / Ctrl 押下で吸着が消え、Shift が拘束として効く経路では吸着しない

## REQ-UI-012: カーブエディタ（グラフエディタ）

- **優先度**: Should
- **ステータス**: Draft (v1 — 2026-07-21 設計確定)
- **説明**: キーフレームカーブ（時間-値）をベジェハンドルで編集する
  グラフエディタ。既存の `Keyframe` モデル（`tangent_in`/`tangent_out` +
  Bezier/Linear/Step）をそのまま編集対象とし、データモデルの変更はない。
  **Timeline 内の切替ビュー**（AE 方式）として実装する — タイムライン
  右ペインをヘッダのトグル（lucide アイコン）でグラフ表示に切り替え、
  時間軸スケール・ズーム・playhead・スクラブ・キーフレーム選択
  （Timeline の ◆ と同一集合）・undo（Document スナップショット、
  1 ドラッグ = 1 undo）をすべて Timeline と共有する。独立パネル間の
  時間軸/選択同期プロトコルを作らないための判断。表示対象カーブは
  左ペインの選択プロパティ行（複数選択で重ね描き、チャンネルごとに色分け）。
- **共有ウィジェット基盤**: カーブ描画・点/ハンドルのヒット・ドラッグ編集は
  「軸の意味を知らない正規化座標のカーブ編集ウィジェット」として
  gpui-component 非依存で自前実装する（独自 UI ライブラリ方針）。
  将来の値-値カーブ（カーブ版 remap ノード / `ParameterValue::Curve`、
  別計画）が同ウィジェットを Properties 埋め込みで再利用する前提の抽象。
- **WYSIWYG 原則**: エディタが描く曲線は core の `evaluate`
  （コントロール点 x の区間クランプ込み）をフレームサンプリングした
  結果そのもの — 描画とアニメーション評価のズレを構造的に排除する。
  ハンドルのドラッグ確定値は隣接キーフレーム区間内へクランプして保存する。
  ただし他の点の移動で区間が後から縮んだ既存ハンドルの保存値は
  書き換えない（評価側クランプに任せる非破壊方針。区間を戻すと
  ハンドルが復元される）。
- **v1 編集操作**: 点の移動（Shift で時間/値の軸拘束）、ハンドル編集
  （既定は対称連動・**Alt で分離** — ペンツール REQ-UI-011 と同一の
  修飾キー規約）、補間タイプ切替（Bezier/Linear/Step、選択点一括の
  右クリックメニュー）、カーブ上ダブルクリックで点追加、Delete で削除、
  ボックス選択、値軸オートフィット（表示カーブ群の合成 min/max）+
  ホイール縦ズーム/パン（水平ズームは Timeline の ppf と共有）。
  値軸は実値表示。
- **v1.5**: イージングプリセット（Easy Ease 等）、ボックススケール
  （選択群の時間/値一括伸縮）、正規化ビュー（各カーブを自身の min/max で
  0..1 に重ねる比較表示）。
- **受入条件**:
  - [ ] Timeline のトグルでグラフビューに切り替わり、時間軸・playhead・
        スクラブが Timeline と一致する
  - [ ] 選択プロパティ行のカーブが色分けで重ね描きされる
  - [ ] 点とハンドルをドラッグ編集でき、描画カーブが評価結果と常に一致する
  - [ ] ◆（Timeline）とグラフ上の点の選択が同一集合として連動する
  - [ ] 補間切替・点追加・削除・ボックス選択が機能する
  - [ ] 編集が undo / redo / 保存・再読込で破綻しない（1 ドラッグ = 1 undo）
- **依存**: REQ-UI-001, REQ-UI-003, REQ-CORE-001

## REQ-UI-013: Outliner + コンポジション管理

- **優先度**: Must
- **ステータス**: Draft (v1 — 2026-07-25 設計確定)
- **説明**: プロジェクト構造のビューとしての Outliner パネルと、
  コンポジションの作成・切替・設定編集・複写・削除を行う軽量な管理 UI を
  導入する。Outliner は **Composition → Layer → Node の 3 階層ツリー**で、
  Timeline が「アクティブコンプの時間ビュー」であるのに対し
  「プロジェクト構造ビュー」を担う。旧 `ui-spec.md` の「ジェネレータ起点の
  オブジェクトリスト」は Track/Clip 時代の設計であり、本要件で
  layer-network モデル（REQ-LAYER）に置き換える。
- **アクティブコンプ**: UI の表示対象を `ActiveComposition` の durable
  Global に一元化し、Timeline / Viewer 評価 / PlaybackController の
  duration・fps / Properties はすべてこれに従う。`Document.root_comp` は
  モデル上のルート（ドキュメントを開いたとき最初に active になるコンプ）
  として残し、UI の切替では書き換えない — コンプ切替を undo 履歴と
  保存差分に載せないための分離。アクティブコンプ自体は
  `.ravprj` の `ui_state.json`（新規エントリ）に永続化し、
  エントリ欠落時は `root_comp` にフォールバックする（既存アーカイブと互換、
  format_version の引き上げは不要）。
- **選択モデル**: レイヤー選択の正を `LayerSelection`（CompId +
  順序保持の LayerId 列）の durable Global に一元化する。`TimelineState`
  のパネル内部選択は廃止し、Timeline と Outliner の双方がこの Global を
  読み書きし、Node Editor / Properties / Viewer bbox は observe する
  （REQ-UI-011 で `CanvasSelection` に対して行った一元化と同一方針）。
  不変条件として `LayerSelection.comp` は常に `ActiveComposition` と
  一致する。ノード行の選択は `CanvasSelection` へ書き込み、Node Editor の
  ハイライトと Properties は既存経路で追従する（ui-spec の双方向同期）。
- **ツリー構築**: レイヤー配下のノード行は `net.out` を根として
  `inputs_of()` で上流を深さ優先に展開する（`net.out` 自身は非表示）。
  既出ノードは二度目以降は子を展開しない参照マーク付きの葉にする
  （DAG の指数膨張防止）。`net.out` に到達しないノードは末尾の
  Unused グループにまとめる。サブネットノードは葉として表示し、
  ダブルクリックで Node Editor の既存 dive（`NetworkPath::entered`）に
  委譲する（Outliner のツリー深さは 3 階層で固定）。
- **操作**: コンプ行はシングルクリックで選択（Properties にコンプ設定が
  出る）、ダブルクリックで active 切替。非アクティブコンプも展開して
  中身を閲覧できるが、その子行はシングルクリックでは選択できず
  （薄い表示）、ダブルクリックで「active 切替 + 選択」になる。
  レイヤー行はシングルクリックで選択、ダブルクリックで Node Editor を
  そのノードにセンタリング、D&D で同一コンプ内の並べ替え（= 合成順）、
  右クリックで Rename / Duplicate / Delete。solo/mute/lock 列は
  Timeline 側の責務として Outliner には出さない。親子（parenting）は
  ツリーのネストで表示するが D&D では変更しない（並べ替え D&D との
  ジェスチャ衝突を避けるため別途設計）。
- **コンプ管理**: `CompositionNew` / `CompositionSettings` /
  `CompositionDuplicate` / `CompositionDelete` を CommandId に追加し、
  メニューバーに Composition メニューを新設する（Outliner のボタンと
  右クリックも同一 Action を dispatch）。設定（名前 / 解像度 / fps /
  duration / 背景色）は Properties の Composition ターゲットで常時編集でき、
  加えて新規作成と明示的な設定編集は gpui-component の `Dialog`
  （`window.open_dialog`）で行う — 新規作成をダイアログにするのは
  未確定のコンプをドキュメントに作ってから直す形（undo 2 段）を避けるため。
  新規作成の初期値は active コンプ → **プロジェクト設定の既定フレームレート**
  （`SET-6`。他のフィールドは下の既定へ落ちる）→ 1920×1080 / 30fps / 300f の順で
  解決する（`manifest.json` の project 既定は参照しない — `ProjectState` は
  読み込んだ manifest を保持しないので、その既定はこの最終段と同じ値になる）。削除はレイヤーを含むコンプの
  ときだけ確認ダイアログを出す（空コンプは即削除、undo 1 回で復元）。
  コンポジション 0 の状態を正当な状態として認め、Outliner / Timeline /
  Viewer / Properties が空状態を描く。
- **複数選択の範囲**: 選択 UI（Shift 範囲 / platform 修飾トグル）と読み取り側
  （Node Editor の閉じた状態、Properties の件数と共通値）を先に入れ、編集側
  （レイヤー単位 bbox とその同時ドラッグ、一括削除・一括フラグ・一括複写）を
  続けて入れる。レイヤー単位 bbox は「そのレイヤーのネットワークの shape
  ノードの bounds の和 → シェル変換」で、shape ノードを持たないレイヤーには
  出さない。Properties の複数表示は読み取り専用のまま（件数と共通値、相違は
  「—」）で、値の一括編集はスコープ外。ツリーの検索・フィルタ欄、親子付け替え D&D、
  PreComp（コンプ間参照、`PathSegment::Comp` は予約のみ）、
  メディアアセットの Outliner 表示は対象外。
- **受入条件**:
  - [x] Outliner にコンプ → レイヤー → ノードの 3 階層が表示され、
        ノード行が `net.out` からの上流順に並ぶ
  - [x] コンプ行のダブルクリックで active が切替わり、Timeline / Viewer /

  - [x] レイヤー行の選択が Timeline の選択と常に一致する（双方向）
  - [x] ノード行の選択で Node Editor のハイライトと Properties が追従し、

  - [x] 非アクティブコンプを展開して閲覧でき、その子行のダブルクリックで

  - [x] コンプの作成・複写・削除・設定編集がメニューと Outliner の

  - [x] レイヤーの並べ替え・削除・リネームが Outliner から行える
  - [x] コンポジションが 0 個でも各パネルが空状態を描き、そこから

  - [x] アクティブコンプが保存・再読込で復元され、`ui_state.json` を

  - [x] Shift の範囲選択と platform 修飾のトグルで複数レイヤーを選択でき、
        Timeline と Outliner の双方で同じ結果になる（Node Editor は
