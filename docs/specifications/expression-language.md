# 式言語 仕様

パラメータ式（REQ-CORE-014）とフィールド式（REQ-CORE-015）が共有する
スカラー式言語の規範。字句・文法・意味論・組み込み関数・変数の語彙・
互換規則をここで定める。

対応要件: REQ-CORE-014 / 015、REQ-CORE-007 / 010 / 012、REQ-INFRA-007。
実装計画と設計判断の理由は
[implementation/done/expression-language-plan.md](../implementation/done/expression-language-plan.md)。

**この文書の綴りは `.ravprj` に永続化される。** 式ソースは文字列のまま
プロジェクトに保存されるので、名前や意味を後から変えることは保存済み
ユーザーデータの移行問題になる（§9）。

**実装状況**: この文書が定める言語は実装済み。パラメータ式は
`ChannelSource::Expression` として、フィールド式は `field.expression` として
評価され、フィールド式は**サンプル対象ドメインの任意の属性**を読む。
Properties パネルはノードパラメータへの式の付け外しと編集を提供する
（[実装状況](../ui-impl-status.md)）。**レイヤーの殻プロパティに式を付ける
UI はまだ無い** — 殻のチャネルも式を評価するが、付け外しの操作はノード
パラメータにしかない。設計判断の理由は
[implementation/done/expression-language-plan.md](../implementation/done/expression-language-plan.md)。

## 1. 流儀

C / After Effects 系。AE のエクスプレッションが JavaScript なので、
そこから移ってくる人が読み書きできる形を選ぶ。

- 三項は `cond ? a : b`
- 論理は `&&` `||` `!`（`and` / `or` / `not` は採らない）
- **べき乗演算子は無い。** `pow(a, b)` を使う。`^` は言語によって xor なので
  曖昧

**式はスカラー 1 個を返す。** ベクトル・色を返す式は v1 の対象外で、
成分ごとに式を置く（`Channel2` / `Channel3` は成分ごとにチャネルを持つ）。

## 2. 字句

- 空白・改行は非有意
- 数値リテラルは 10 進のみ。`1` / `1.5` / `.5` / `1.` / `1e-3` / `2.5E6`。
  16 進・アンダースコア区切りは無い。指数部が不完全なもの（`1e`、`1e+`）は
  字句エラー
- 識別子は `[A-Za-z_][A-Za-z0-9_]*`。**大文字小文字を区別する**
- 属性は `@` + 識別子 + 任意の `.` 成分連鎖（§8）
- 文字列リテラルは無い（文字列を取る組み込みが無い）
- **コメントは v1 に無い**
- **予約語は無い。** ユーザーが名前を持ち込めるのは属性（`@` 側）だけで、
  sigil の無い識別子は宣言済みの名前集合としか照合しない。だから予約する
  必要が無く、レキサに予約語テーブルを持たせない（§9）

## 3. 文法

```text
expr           := ternary
ternary        := logic_or ( '?' ternary ':' ternary )?             // 右結合
logic_or       := logic_and ( '||' logic_and )*
logic_and      := equality ( '&&' equality )*
equality       := relational ( ('==' | '!=') relational )?          // 非結合
relational     := additive ( ('<' | '<=' | '>' | '>=') additive )?  // 非結合
additive       := multiplicative ( ('+' | '-') multiplicative )*
multiplicative := unary ( ('*' | '/' | '%') unary )*
unary          := ('-' | '+' | '!') unary | primary
primary        := NUMBER
                | attribute
                | call
                | path
                | '(' expr ')'
path           := IDENT ( '.' IDENT )*
attribute      := '@' IDENT ( '.' IDENT )*
call           := IDENT '(' ( expr ( ',' expr )* )? ')'
```

優先順位は上ほど緩い。`IDENT '('` を見たら `call`、そうでなければ `path`。
1 トークン先読みで足りる。

- **`.` は `path` と `attribute` の内側にしか現れない。** 呼び出しの結果に
  `.` は付けられない（`noise(x).y` は構文エラー）。式はスカラーを返すので
  成分が無い
- 末尾カンマは許さない（`min(a, b,)` は構文エラー）
- **比較と等値は非結合。** `a < b < c` は 2 つ目の演算子の位置で構文エラーに
  する。C 系なら `(a<b)<c` として通るが、値が数値しか無い言語では真偽値と
  数値を比べることになり必ずバグなので、Rust と同じ扱いにする。エラーは
  括弧を付けるか `&&` を使うよう案内する
- **文・代入・ループ・関数定義の形は文法に存在しない。** ループを書けない
  ことが停止性の保証であり、実行時のサンドボックス機構を不要にしている
  （REQ-INFRA-007 の段 0）

### 入力の大きさの上限

コンパイルは**式の大きさに 2 種類の上限**を課し、どちらを超えても位置付きの
コンパイルエラーになる。加えてコンパイル済みプログラムの評価スタックにも
上限がある。

| 定数 | 値 | 縛るもの |
|---|---|---|
| `MAX_TOKENS` | 1024 | 式の**総量**（トークン数） |
| `MAX_NESTING_DEPTH` | 64 | 式の**ネスト深さ** |
| `MAX_STACK_SLOTS` | 64 | コンパイル済みプログラムの評価スタック |

いずれも入力検証であって整形の趣味ではない。**スタックオーバーフローは
`Result` で運べない abort になる**ので、「実行時エラーが存在しない言語」と
いう主張はコンパイル時のクラッシュも許さない。式ソースは `.ravprj` 経由で
外部から来うる。

**深さと総量の両方が要る。どちらも他方を含意しない。**

- `((((…))))` は**深いが短い**。深さ上限が捕まえる。1 段は「部分式への
  再入」1 回、すなわち括弧・呼び出し引数・`?:` の分岐・前置演算子のいずれか。
  **式そのものは 1 段に数えない**ので、括弧はちょうど 64 重までが通り、
  65 重で落ちる。エラーが言う数字が実際に書ける数字である
- `x + x + x + …` は文法上のネストが無い。パーサも再帰せずループで読む。
  **しかし `+` は左結合なので、項の数だけ左に傾いた木ができる。** 木を辿る
  後段の処理（名前解決・定数畳み込み・スタック量の算定・命令列の生成、
  そして木の `Drop` そのもの）はすべて項の数だけ再帰する。数千項でスタックが
  尽きる。深さ上限はこれを 1 段も数えないので、**総量の上限だけがこれを
  縛れる**

総量の判定は**字句解析の時点**で行う。木ができてから弾くのでは間に合わない
── エラーを返すときにその木を drop することになり、その drop 自体が
溢れる再帰だから。トークン数を数えるのは O(1) で、入力の形（連鎖・深い
ネスト・巨大な引数リスト）を問わず一律に効く。

1024 トークンは手書きの式には十分に大きい（§8 の例で約 25 トークン）。

`MAX_STACK_SLOTS` に触れるのは 3 引数の呼び出しを数十段ネストした式だけで、
その場合もコンパイルエラーになる。

## 4. 意味論

### 数値

- **内部評価は f64。** f32 への変換は出力境界だけ
  （`ChannelSource::evaluate` の戻り、フィールドの `AttributeArray` 書き込み）。
  `EvalContext.time` と連続フレーム位置が f64 なので、途中を f32 で回すと
  時間の精度を落とす
- **IEEE 754 をそのまま伝播する。** `1/0` → `inf`、`sqrt(-1)` → `NaN`、
  `log(0)` → `-inf`。REQ-CORE-014 が明示的に固定している
- **式言語の側では有限でない値を潰さない。** 既定値に落とすのはチャネル境界
  （`ChannelSource::evaluate`）の仕事で、1 箇所に閉じる

### 全域性

**言語は全域**。すべての演算がすべての入力に対して値を返し、評価に失敗の
経路が無い。

- 名前解決と引数個数はコンパイル時に済む
- 演算と組み込み関数は `f64` 全域で定義される
- 再帰とスタック使用量はコンパイル時に上限が確認される

これにより `ChannelSource::evaluate` は `Result` を返さずに済む。
シグネチャを `Result` にすると、対処できないエラーを伝播させるだけの
コードが 100 箇所以上に増える。

### 真偽値

bool 型を持たない。

- 比較 `== != < <= > >=` は `1.0` / `0.0` を返す
- 真の判定は `x != 0`。したがって **`NaN` は真**（`NaN != 0` が真）
- `!x` は `x == 0 ? 1 : 0`
- `&&` / `||` は**オペランドの値ではなく `1.0` / `0.0` を返す**（JS と違う）
- **短絡評価は意味論上の差を生まない。** 全域かつ副作用が無いので、
  防ぐべきエラーも触れるべき状態も無い。`x != 0 && 1/x > 2` はガードに
  ならないが、除算が全域（`inf`）なのでガードが要らない

### 空の式

空文字列と空白のみは**「式が無い」**として扱い、構文エラーにしない
（UI で空欄にした状態が赤くならないように）。呼び出し側は
`Program::is_empty()` で判別し、自分の既定値を使う。

### 決定性

同じ式・同じ入力の評価は常に同じ値を返す。三層キャッシュ（REQ-CORE-006）が
「同じ入力なら同じ出力」を前提にキーを作るため。`noise` も座標から決定的に
導出し、実行ごとに変わる乱数状態を持たない。

## 5. 組み込み関数 — WGSL / GLSL 準拠

意味論は WGSL の同名ビルトインに合わせる。理由は §6。

| 関数 | 定義 |
|---|---|
| `sin(x)` `cos(x)` `tan(x)` | ラジアン |
| `asin(x)` `acos(x)` `atan(x)` | 1 引数 |
| `atan2(y, x)` | **`y` が先**（WGSL / C と同じ） |
| `exp(x)` `exp2(x)` | |
| `log(x)` | **自然対数** |
| `log2(x)` | |
| `pow(a, b)` | |
| `sqrt(x)` | |
| `abs(x)` | |
| `sign(x)` | `-1` / `0` / `1`。`NaN` は `NaN` |
| `floor(x)` `ceil(x)` | |
| `round(x)` | **偶数丸め**（`0.5` → `0`、`1.5` → `2`、`2.5` → `2`） |
| `fract(x)` | `x - floor(x)` |
| `min(a, b)` `max(a, b)` | 片方だけが `NaN` なら他方 |
| `clamp(x, lo, hi)` | `min(max(x, lo), hi)`。`lo > hi` も未定義動作にせず、この式のとおりに評価する（結果は `hi`） |
| `mix(a, b, t)` | `a + (b - a) * t`。**`t` を clamp しない**ので外挿できる |
| `step(edge, x)` | `x < edge ? 0 : 1` |
| `smoothstep(e0, e1, x)` | `t = clamp((x - e0) / (e1 - e0), 0, 1); t * t * (3 - 2 * t)` |
| `noise(…)` | §7 |

`%` は WGSL の float 剰余に合わせ、**符号は被除数に従う**（C の `fmod`、
Rust の `%` と同じ。`-7 % 3 == -1`）。

引数の個数が合わなければ位置付きのコンパイルエラー。

### 定数

`pi` と `e`。**言語の定数であってコンテキスト変数ではない**ので、
`2 * pi` のような部分式は評価前に定数畳み込みで潰れる。同名の変数を
スコープが宣言しても定数が優先する。

## 6. なぜ WGSL に合わせるか

REQ-CORE-015 は「式を WGSL へ落とす経路が閉じない」ことを AST を持つ理由に
挙げている（フィールド式は要素ごと × フレームごとに走るので、いずれ GPU で
評価したくなる）。

そのとき CPU 版と GPU 版で `round` の丸め方や `mix` の clamp の有無が
違っていると、**GPU 化した瞬間に絵が黙って変わる**。ずれに気づくのは
レンダーを見比べたときで、原因に辿り着くのは難しい。

いま WGSL に合わせる代償は「`0.5` が `0` に丸まるのを意外に思う人がいる」
だけで、後から合わせる代償は誰にも書けない移行になる。

## 7. `noise`

**値そのものがユーザーの絵になる**ので、実装を仕様として固定し、
ゴールデンテストで値をピン留めする（`crates/ravel-core/src/expression/noise.rs`）。
後から差し替えると保存済みプロジェクトのレンダーが全部変わる。

- **改良 Perlin（勾配ノイズ）**、3 次元。格子点ごとに立方体の辺方向 12
  勾配のいずれかをハッシュで選ぶ
- アリティ 1 / 2 / 3 で多重定義（`noise(x)` / `noise(x, y)` /
  `noise(x, y, z)`）。使わない座標は 0 なので、1D は 2D の断面、2D は 3D の
  断面になる
- **値域 `[-1, 1]`**、**格子点で `0`**
- 補間曲線は改良版の `6t⁵ - 15t⁴ + 10t³`
- ハッシュ関数は実装で固定し、具体値のゴールデンテストで拘束する
- **決定的**。実行ごとに変わるシードを持たない
- 有限でない座標は `0` を返す
- simplex は特許の懸念があるので採らない

`ravel_core::geometry::NoiseField` は別実装（simplex）のままで、この
`noise` とは独立している。既存のフィールドが作る絵を変えないため。

## 8. 変数

**ドット名は第一級オブジェクトではない。** `comp` という値は存在しない。
パーサは `ident ('.' ident)*` を 1 つのパスとして読み、**宣言された名前集合に
対して文字列全体で照合する**。未定義なら位置付きのコンパイルエラーで、
綴り全体を出す（`unknown variable 'comp.widht'`）。

この形にしたのは、`@P.x` と同じ「名前の中の `.`」機構で済み、将来
`layer.opacity` や `audio.level` を足しても名前空間が汚れないため。

### パラメータ式の語彙

```text
frame          連続フレーム位置（モーションブラー・タイムリマップで小数になる）
time           秒
fps
res.width      出力解像度   ← EvalContext.resolution
res.height
res.aspect     width / height
comp.width     コンプ解像度 ← EvalContext.comp_resolution
comp.height
comp.aspect
pi  e          （§5 の定数。変数ではない）
```

`frame` は整数インデックスではなく**連続位置**（`EvalContext::sample_frame()`
相当）。サブフレーム位置で連続的に評価される必要がある。

パラメータ式で `@` が現れたら**専用メッセージのコンパイルエラー**にする
（`attributes are not available here`）。字句エラーにはしない。

### フィールド式の語彙

パラメータ式の全部に加えて:

```text
@P.x @P.y @P.z    位置
@index            要素番号
@N.x @Cd.r …      標準属性
@myattr           任意名の属性
elem.count        要素総数
```

例:

```text
noise(@P.x * 0.1, time) * (1 - @index / elem.count)
```

### 属性の規則

- 成分は `.x` `.y` `.z` `.w`。`.r` `.g` `.b` `.a` を同じ成分の別名として
  受理する
- **成分を付けないベクトル属性（`@P` 単体）はコンパイルエラー。** 式は
  スカラーを返すため。メッセージで成分を選ぶよう案内する。将来ベクトル値の
  式を足すときは、このエラーを緩和するだけで済む
- 標準属性（`P` / `N` / `Cd` / `index`）は幅が既知なので、`@P.w` のような
  存在しない成分はコンパイル時に落とせる
- **存在しない属性名はコンパイル時に判定できない**（ジオメトリがまだ無い）。
  任意名は受理し、サンプル時に既定値へフォールバックして警告する。
  ここだけが「未定義名はコンパイルエラー」の例外
- **依存抽出は属性名を変数名と区別して返す。** キャッシュキーと EXPR-6 が
  別々に扱うため

### 依存抽出

コンパイル済みプログラムは、参照する変数名の集合と属性名の集合を返す
（それぞれ整列済み・重複なし）。定数畳み込みは定数だけの部分式しか潰さない
ので、**畳み込みの有無で依存集合は変わらない**。キャッシュキー（REQ-CORE-006）
と dirty 伝播がこの集合に乗る。

## 9. 互換規則 — 構文をどう育てるか

**式ソースは `.ravprj` に永続化される。** したがって構文の変更は保存済み
ユーザーデータの移行問題になる。次を不変条件とする。

> **構文の変更は、今エラーになる式を通す方向にしか行わない。
> 今通る式の意味は変えない。**

許されるのは「無効 → 有効」の緩和だけで、「有効 → 別の意味」の再解釈は
許されない。この規則を守る限り、保存済みの式は将来のどの版でも同じ値を返す。

これを守るために次を予約しておく。

- **字句として空けてある記号**: `=` `;` `{` `}` `[` `]` `^` `~` `#`。
  現状すべて字句エラー。将来の文法拡張はここから取る
  （`=` だけは `==` の打ち間違いが多いので専用のメッセージを出す）
- **コンテキスト変数・組み込み関数に使わない名前**:
  `let` `if` `then` `else` `for` `while` `fn` `return` `var` `const`
  `true` `false` `and` `or` `not` `in`。
  **これは字句上の予約語ではない**（§2 のとおりユーザーは識別子を
  持ち込めないので予約する必要が無い）。仕様を育てる側の自己規律

## 10. v1 に入れないもの

いずれも §9 の規則のもとで後から安全に足せる。

- **文と束縛（`let` / `if`）**。ループではないので REQ-INFRA-007 の停止性の
  議論では排除されないが、v1 のスコープ外。追加するときは `=` と `;` を
  字句エラーから昇格させるだけなので、保存済みの式は壊れない
- コメント
- ベクトル・色を返す式（`@P` 単体のエラー緩和で入る）
- ユーザー定義変数・関数
- `wiggle()` 相当の AE 互換ヘルパ
- 式から他ノードを参照する構文（`ChannelSource::NodeOutput` が担う）
- 式の GPU 評価（AST があるので道は閉じない。REQ-INFRA-009 の後）
