# Properties Inspector 仕様

> 最終更新: 2026-08-21 ／ 索引: [`../ui-spec.md`](../ui-spec.md)

選択されている対象を編集する。関連要件: REQ-UI-002、REQ-UI-012、REQ-CORE-002。

## 対象の決まり方

表示対象は `SelectedPropertiesTarget` Global が持つ。**Global は対象を
「識別」するだけで値は持たない** — 値は毎回ライブの Document から解決する
（stale な値を持たないため）。

**タブが手前にない間は値の再解決を走らせない。** 裏で起きたドキュメント編集も
裏で流れた再生フレームも、表に戻ったときに 1 回で追いついてから描く
（[`../ui-spec.md`](../ui-spec.md) の設計原則）。プレイヘッドで再サンプルされる
ものが何も無いときは、表にいても再解決しない。

| 対象 | 誰が設定するか | 編集 |
|---|---|---|
| `Empty` | 選択が無いとき | — |
| `Nodes { network, ids }` | Node Editor / Viewer の選択 | ✅ |
| `Layer { comp, layer }` | Timeline / Outliner のレイヤー選択（1 枚） | ✅ |
| `Layers { comp, layer_ids }` | 同（2 枚以上） | 🔲 読み取り専用（件数と一致する値のみ） |
| `Composition { comp }` | Outliner のコンプ行、コンプ管理コマンド | ✅ |
| `MediaAsset { id }` | MediaBin の選択 | ✅ パスと参照形式（表示名は MediaBin の行が持つので読み取り専用） |
| `Project` | `CommandId::ProjectExposedParameters`（Cmd+Shift+K / コンポジションメニュー） | ✅ 公開パラメータ宣言 |

複数レイヤー選択を `Layer` と別 variant にしているのは、**一括編集がどの
レイヤーにも適用先を持たないウィジェットから漏れ出さないようにする**ため。

## セクション

対象によって出る節が変わる。

| 節 | 内容 |
|---|---|
| Layer | 名前、ラベル |
| Timing | 開始フレーム、表示区間（in / out） |
| Transform | parent（親レイヤーのドロップダウン。候補は自身と子孫を除く同一コンプのレイヤー）+ anchor / position / scale / rotation（各成分がアニメーション可能なチャネル） |
| Compositing | 不透明度、ブレンドモード、調整レイヤーフラグ、solo / mute / lock |
| Audio | ゲイン、フェード（音声を持つ殻のみ） |
| Composition | 名前、解像度、フレームレート、尺、背景色 |
| Node Info | ID、型、ラベル |
| Parameters | ノードのパラメータ。グループ宣言があれば複数のセクションに割れる（下記） |
| Ports | `net.in` / `net.out` のポート一覧（REQ-LAYER-002/003） |
| アセット | メディアアセットの probe が記録した値（名前・種別・解像度・fps・長さ・コーデック・音声ストリーム数）。**すべて読み取り専用** — ファイルを述べているだけで設定ではない。記録の無い項目は行を出さない |
| ファイル | メディアアセットの参照そのもの（下記「メディアアセットの参照」） |
| 公開パラメータ | プロジェクトの外部契約（REQ-PROJ-006）。`Project` 対象のみ |

### パラメータグループ (PGRP-1〜PGRP-4)

パラメータ数の多いノード（10 個超）で関係の無い項目が縦に連なるのを、
**1 階層**のグループに割って解く。設計判断の経緯は
[`../../implementation/done/parameter-groups-plan.md`](../../implementation/done/parameter-groups-plan.md)。

- **グループを宣言するのはノード型**（`NodeTemplate::param_groups`、
  「グループ名 → パラメータキーの並び」）。組み込みのグループ分けはコードに
  あるので **`.ravprj` には何も入らない**。ofx の Page / Group も
  プラグインの descriptor 側の宣言なので、`OFX-5` はこの同じ場所へ載せる
- **入れ子にしない。** ofx の Page → Group は 2 階層だが、どちらも Ravel の
  1 階層グループへ潰す。「どちらの階層を畳んだのか」を状態に持たないため
- **例外はネットワークインターフェースの In ノード**。カスタムパラメータは
  ユーザーが実行時に足すもの（`NETIF-2`）で型が知らないので、In ノードだけ
  インスタンス側に宣言を持つ（`Node::param_groups`、**パラメータキー →
  グループ名**の対）。割り当ては Ports セクションのカスタム行の「グループ」欄
  から行う。**パラメータを持たないポート**（固定ポート、wire 専用型）には
  欄が出ない
- **同じ In ノードに型宣言とインスタンス宣言の両方があればインスタンスが勝つ。**
  ユーザーが手で割り当てたものなので、片方ずつ混ぜるとどちらに従っているのか
  説明できない。**In ノード以外の非空 `Node::param_groups`**（手編集した
  `.ravprj` でしか作れない）は表示側が無視して型宣言に従い、`validate` では
  弾かない（「保存できたが開けない」を作らないため、`HIGH-26`）
- **宣言に現れないパラメータは、宣言されたグループより前**の暗黙セクションに
  入る。したがってグループ宣言の無いノードは今までどおり 1 枚に並ぶ
- **宣言の破れは黙って吸収する**: 宣言に無いキーは落ち、メンバが 0 になった
  グループはセクションを作らず、同じキーを 2 つのグループが挙げたら先に
  挙げた方が勝ち、同じグループ名を 2 回宣言したら 1 セクションに統合する
  （名前が開閉キーなので、同名 2 セクションは区別できない）
- **見出しのロケールキーは `node.<type_key>.group.<name>`**（`DISC-1` の体系）。
  `ravel-core` にロケールキーは持たせず、`ravel-ui` の表示境界
  （`node_locale::group_key`）が組む
- **組み込みで宣言しているのはパラメータ 6 個以上の 9 テンプレート**:
  `attribute.set` / `style.stroke` / `field.apply` / `math.remap` /
  `math.curve` / `scene.camera` / `scatter.grid` / `scatter.circular` /
  `scatter.scatter`。このしきい値はテスト
  （`every_built_in_with_six_or_more_parameters_declares_groups`）が強制する
  ので、6 個目のパラメータを足したテンプレートはグループ宣言も足すことになる
- **畳んだ状態は `(type_key, group)` で `ui_state.json` に持つ**（`PGRP-3`）。
  ノードごとではなく**ノード型**をキーにするので、同じ型のノードを選び直す
  たびに畳み直さなくてよい。**既定は全展開**で、畳んだものが 1 件も無ければ
  エントリごと書かれない。パラメータグループ**以外**のセクション
  （Node Info / Ports / 宣言 / 説明）は畳めるようにしていない

受け入れた上限:

- **セクションの順はポートの並べ替えに追随しない。** インスタンスグループの
  セクション順は `node.parameters` の登場順で決まるが、`Graph::reorder_ports`
  はポート配列だけを並べ替える。要求が出たら別単位
- **グループ名がロケールキーと衝突すると翻訳される。** インスタンスグループの
  名前は自由入力で、`PropertySection.title` はホストが `t!` を通すので、
  `properties.section.parameters` のような内部キーそのものを打つとその翻訳が
  見出しに出る。畳み判定は位置で引くので**別のセクションを畳む事故は起きない**
- **開閉の永続化は明示的な保存に乗る。** 折り畳みは `ui_state` を dirty に
  するだけで保存を起こさない（自動保存は `SET-9` で未実装）

### 公開パラメータ節 (REQ-PROJ-006)

プロジェクトが外へ出している契約 — CLI の `--param`、サブグラフテンプレートの
公開入力 — の一覧で、**プロジェクトに属するので選択では辿り着かない**。
コンポジションメニューとキーバインドから開く（`Project` 対象）。

- **宣言はパラメータ行の公開トグル（□ / ■）から作る。** この節に追加行は
  置かない。宣言は名前・型・既定値・説明・**束縛**を持ち、束縛は「どの
  パラメータか」であって、それを言う一番良い方法はそのパラメータを指すこと。
  文書中の全パラメータから選ばせるピッカーは、同じことをより悪く行う
- **型と既定値は読み取り専用。** 公開した時点でパラメータから導かれ
  （`exposed::apply::seed_value`）、後から変えると `apply` が書き戻せない宣言に
  なる。編集できるのは名前・説明・並び順・存在の 4 つだけ。
  **アニメーション中の成分の既定値は再生ヘッドのフレームでの評価値** —
  パネルが現に表示している値。書き戻せないことは公開パラメータ節が
  `AnimatedComponents` として出す
- **束縛先の内部 ID は見せない。** 契約が隠すためにある当のものなので、
  行に出さない
- **解決不能は隠さず、理由ごとに違う言葉で出す。** 判定はコア
  （`exposed::apply::resolve`）が持ち、`BindingIssueReason` の各値に 1 つずつ
  ロケールキーを当てる。「壊れている」で 6 種類をまとめると、「ノードが無い」と
  「キーフレームなので値が入らない」の区別が消える
- **改名の衝突は拒否して理由を出す。** 名前は契約そのものなので、勝手に
  付番して回避しない（テンプレートの 2 個目の貼り付けだけは別扱い。
  ユーザーが表明した命名ではないので `<name>_2` へ付番する）

### メディアアセットの参照 (REQ-UI-008)

`MediaAsset` 対象の「ファイル」節。関連: `MEDIA-6` / `MEDIA-7`、
[`media-bin.md`](media-bin.md)、
[`../data-model.md`](../data-model.md) のアセット参照モデル。

- **解決先**（読み取り専用）— `resolved` の絶対パス。解決しなければ
  MediaBin のバッジと同じ語（オフライン）を出す
- **パス形式**（Select: 絶対 / プロジェクト相対 / 変数）— **ファイルを変えずに
  形式だけ書き換える**。いまの位置で表せない形式（ルートの無いプロジェクトでの
  相対、ルート外のファイルの相対）は**近似せず拒否**し、Select は元の形式へ
  戻る
- **パス**（Input）— 保存される文字列そのもの。確定するとその文字列から形式を
  再判定するので、相対の欄に絶対パスを打てば絶対になる（ディスク上のファイルを
  読む規則と同じ）
- **`Relink…`**（ボタン）— ファイルダイアログで選んだファイルを
  バックグラウンドで probe し、パス・種別・メタデータを **1 undo** で差し替える。
  probe が読めないファイルは参照を変えず、理由を出す（取り込みが拒否するのと
  同じ判定）
- この節は**ディスクを触らない**。したがって「オフライン」は参照が解決しない
  ことだけを指し、解決するパスのファイルを消しただけでは出ない

## 値の編集

- **数値はスクラブ入力**: 横ドラッグで値を変える。カーソルは `ResizeLeftRight`。
  ダブルクリック（またはクリック）で直接入力に切り替わる。パラメータ範囲
  （`ParamRange`）があればソフトクランプする
- **列挙は dropdown**: `param_options` を持つ文字列パラメータは自由入力にしない
- **キーフレーム菱形**: 各アニメーション可能フィールドの左に置く。現在フレームに
  キーがあれば塗り、無ければ枠のみ。クリックで現在フレームのキーを追加 / 削除
- **ポートトグル**: パラメータを入力ポートとして露出する（未露出 / 露出 /
  接続済みの 3 状態）。接続済みのパラメータは値の編集を受け付けない
- **カーブはインライン展開**: カーブパラメータ（`field.curve_remap` の
  `points` など）は折り畳み時にサムネイルを出し、行クリックで直下に
  カーブエディタを開く。点はドラッグで移動、空所のダブルクリックで追加、
  点のダブルクリックで削除、クリックで選択。展開高さは下端のハンドルを
  ドラッグして変える。**複数行を同時に展開できる**（排他にしない）
- **グリッドと目盛**: 入力軸・出力軸それぞれにグリッド線と目盛ラベルを出す。
  刻みは表示範囲から導き、幅・高さに応じて間引く。軸が短いときはラベルを
  落として線だけ残す（刻みの算出は Timeline のグラフエディタと同じ
  `widgets/curve_view.rs`）
- **選択点の値**: 選択中の制御点の入力 / 出力をツールバーに数値で出し、
  スクラブ入力で編集できる。未選択のときはその旨を表示する
- **補間種別と接線**: 選択点の補間（Linear / Bezier / Step）をツールバーで
  切り替える。Bezier の区間は接線ハンドルが出てドラッグで形を変えられる。
  Shift で画面上の 45 度にスナップ（Timeline のキーフレーム編集と同じ操作）
- **両端 2 点は x を固定**し、y だけ編集できる（ドラッグ・数値入力の両方）。
  両端はカーブの定義域そのものなので、出力を狙って動かした結果として定義域が
  黙って縮んだり、端が表示範囲の外に出たりするのを防ぐ
- **定義域が変わるのは次の 2 操作だけ**。`field.curve_remap` の入力は
  フィールドの値で `0..=1` とは限らない（距離フィールドなら `0..=500`）ので、
  定義域は固定しない:
  1. **現在の定義域より外側に点を追加する** → その点が新しい端になり定義域が
     広がる（それまでの端は普通の内部点になる）
  2. **端の点を削除する**（制御点が 3 つ以上のときのみ） → 定義域が隣の点まで
     縮む
- 制御点は最少 2 点。2 点しか無いときはどちらも削除できない（残るのは定数に
  なり、空のエディタと見分けが付かないため）
- **表示範囲**: 入力軸・出力軸の min / max をツールバーで数値編集でき、
  ホイールで出力軸（Shift + ホイールで入力軸）をズームする。**Fit** で
  両軸をデータ追従に戻し、範囲外に出た点を必ず取り戻せる
- **展開状態と表示範囲は Document に入らない**。どの行が開いているか・
  どの高さか・どの範囲を見ているか・どの点を選んでいるかはパネルと
  エディタのビュー状態で、undo には積まれず undo で変わりもしない。表示
  対象が変わると展開は捨てる（`points` のような素のキーはどのノードのもの
  か区別しない）
- スクラブ 1 ジェスチャ = 1 undo。ドラッグ中はプレビューを適用し、離したときに
  1 スナップショットを積む。カーブの点ドラッグも同じ規約
- キーフレーム付きチャネルの編集は**チャネルを平坦化しない**。現在フレームに
  キーを挿入 / 更新する
