# 設定ダイアログ 仕様

> 最終更新: 2026-08-03 ／ 索引: [`../ui-spec.md`](../ui-spec.md)

関連要件: REQ-PROJ-004（設定の層マージ + 設定 UI）、REQ-UI-006（テーマ）、
REQ-UI-007（キーバインド）。

**この文書は「こう動くべき」を書く。** どの項目が今出ていてどれが効くかの正は
[`../../ui-impl-status.md`](../../ui-impl-status.md)、未対応の設定とその担当は
REQ-PROJ-004 の表。ここには重複させない。

## 2 画面と書き込む層

設定は `default → global → project → user` の 4 層マージで解決する
（後ろが強い）。**画面が書き込む層を決める。**

| 画面 | 開き方 | 書き込む層 | 置き場 |
|---|---|---|---|
| 環境設定（Preferences） | `Edit ▸ Preferences…`（`Cmd+,`） | `global` | `<config_base>/ravel/settings.toml` |
| プロジェクト設定 | `Composition ▸ Project Settings…` | `project` | `.ravprj` 内の `settings.toml` |

**この向きでないと壊れる。** 環境設定を最上位の `user` 層に書くと
プロジェクト設定が環境設定に負け、REQ-PROJ-004 の「プロジェクト固有設定で
グローバル設定を上書きできる」が成立しない。`global` こそが per-user の
グローバル設定で、そこに書けば `project` が正しく上書きする。`user` 層は
マシン固有の最終上書き / CLI からの一時上書き用の枠として空けてあり、
**画面からは書かない**。

行ごとに層を選ぶ UI は持たない。画面で決まるので、誤ってグローバルへ書く事故が
構造的に起きない。

## 出し方

どちらもモーダルダイアログ。ドッキング可能なパネルにはしない（常時見るもので
ないのにパネル登録とワークスペースプリセット資産の全更新が付いてくる）。独立
ウィンドウにもしない（分離ウィンドウの既知負債 `MED-APP-01` を前提にしてしまう）。
**将来方向**: カラー管理が入って Viewer と見比べる必要が出たら独立ウィンドウ化を
検討する。

ダイアログはサイドバー（ページ一覧）+ ページ本体。ページはその画面に属する
ものだけを出す。ダイアログを開いている間もワークスペースの focus 所有権は
移らない（ダイアログは自分で focus を持つが `FocusedPanelGlobal` を書き換えず、
閉じると元のパネルへ戻る）。

## 即時適用。undo には載せない

- 変更した瞬間に反映する。フッターは閉じるボタンのみ — 確定もキャンセルも無い。
- **設定は `Document` ではないので undo に載せない。** 載せると undo 履歴が
  「編集の履歴」でなくなる。
- 永続化は層ごと。`global` は変更ごとに即時・アトミックに書く。`project` は
  `.ravprj` の一部なので**次のプロジェクト保存で書かれ、それまではプロジェクトが
  未保存状態になる** — ユーザーが変えてまだ保存していない設定は、他の未保存の
  変更と同じ扱い。
- 書き込み失敗を無言にしない。通知を出し、変更自体はそのセッションには効いた
  ままにする（黙って元に戻るコントロールを作らない）。

## 「既定に戻す」= その層の値を消す

各行には「その層に明示値があるとき」だけ reset が出る。押すと**その層から値を
消す**ので、下位層の値へ戻る。

- **既定値を書き戻さない。** 層モデルでは、既定値と同じ明示値を書くのは
  「上書きを消す」ことと別の状態（下位層が後で変わっても追従しなくなる）。
- reset が出る条件は**編集中の層に値があるか**で、マージ後の値が既定と違うか
  ではない。だからプロジェクト設定の画面で、環境設定に入れた値を reset することは
  できない（それはその画面のものではない）。
- 逆に、行が**表示する**値は解決後の「効いている値」。プロジェクト設定の画面が
  環境設定由来の値を表示することはあり、それは仕様 — そうでないと「プロジェクトが
  環境設定を上書きした」ことが画面から分からない。

## 「出す項目 = 効く項目」

**設定画面に項目を出す条件は、その設定が挙動に反映されること。** 効かない項目は
画面に出さない（コメントアウトでもグレーアウトでもなく、存在させない）。

- 受入条件は UI ではなく**挙動**で書く。「言語を切り替えると次の描画で UI 文字列が
  変わる」であって「言語の dropdown がある」ではない。
- 機能が未実装の設定は画面に存在せず、要件側に「未対応」と担当計画を書く
  （REQ-PROJ-004 の表）。
- 項目の無いページはサイドバーに出ない。前提機能より先にページを足しても、
  ユーザーには何も見えない。

## ページ

| 画面 | ページ | 内容 |
|---|---|---|
| 環境設定 | 一般 | 停止したら再生開始位置へ戻す、起動時にコンポジションを作る |
| 環境設定 | 外観 | テーマモード（システム / ライト / ダーク）、ライト用テーマ、ダーク用テーマ |
| 環境設定 | 言語 | 表示言語。選択肢は各言語自身の表記で並べる |
| 環境設定 | キャッシュ | VRAM 上限（MiB）、メモリ上限（MiB）、sim 予約率（0〜1）、キャッシュの置き場 |
| 環境設定 | キーバインド | 現在の割り当ての**読み取り専用**一覧（コマンド / chord / 由来）。編集は `SET-12`（[keybindings.md](keybindings.md)） |
| プロジェクト設定 | プロジェクト | 既定フレームレート |

テーマの選択肢はそのモード用のテーマだけを出す（ライト枠にダークテーマを
入れられると、ライトへ切り替えた瞬間に読めない画面になる）。

キャッシュのディスク層（有無 / 上限）は**このページに出さない**。`Tier::Disk`
に課金する経路がまだ無く、層の実装は `cache-plan.md` の `CACHE-11` だから
（「出す項目 = 効く項目」）。上限と予約率は走行中の予算へ即時に効くが、置き場は
キャッシュを作る側が読む値なので**次回起動から**効く — その違いは項目の説明文
に書く。上限と予約率は数値入力（範囲つき）で、置き場は絶対パスのテキスト入力。
相対パスは起動時の作業ディレクトリ次第で置き場が変わるので受け付けず、空欄は
「自分の置き場を持たない」= 上書きの削除として扱う。

## 既定フレームレートの優先順位

プロジェクト設定の既定フレームレートは、**新規コンポジションが何も引き継げない
ときの値**。優先順位は上から:

1. **アクティブなコンポジションの書式**（あればこれが勝つ）。より局所的な
   シグナルを優先する — 24 fps のシーケンスで作業している人は、そのシーケンスの
   別カットを作っている。
2. **プロジェクト設定の既定フレームレート**（アクティブが無いとき、および
   `File ▸ New` の root コンポジション）。
3. **組み込みの既定**（1920×1080 / 30 fps / 300 フレーム）。設定値が解釈できない
   ときもここへ落ちる。

**1 が設定を隠す。** コンポジションを開いた状態で既定フレームレートを変えても、
次の `Composition ▸ New…` の初期値は変わらない。これは意図した挙動で、配線漏れ
ではない。

`.ravprj` を開いたときは別で、保存済みのコンポジションの書式が正。**設定が
保存済みの事実を書き換えることはない。**

値の書式は fps 表記（`30`、`29.97`）または正確な有理数（`30000/1001`）。
`29.97` のような放送レートは正確な `30000/1001` として読む（`2997/100` に
すると timecode がずれる）。**解釈できない値は層に書かせない** — 画面が出す
選択肢は必ず読める値だけにする。

## 非対象

- キー割り当ての**編集** UI（`SET-12`）。一覧までが本仕様。
- 設定の**インポート / エクスポート**（`SET-13`）。
- **プラグイン設定**（REQ-PLUGIN 系が未実装）。
- **UI スケーリング・色覚多様性テーマ・アニメーション削減**（`SET-14` / `SET-15`。
  REQ-UI-006 の残りの受入条件）。
- **分離ウィンドウ化**（`MED-APP-01` を前提にするので将来方向）。
- **設定を undo に載せること。**
