# ワークスペース・レイアウト・ウィンドウ 仕様

> 最終更新: 2026-08-01 ／ 索引: [`../ui-spec.md`](../ui-spec.md)

関連要件: REQ-UI-005 (v2)、REQ-UI-009 (v2)、REQ-UI-013。
実装状況の正は [`../../ui-impl-status.md`](../../ui-impl-status.md)、
永続化ファイルの形式は [`../../dev/persistence.md`](../../dev/persistence.md)。

## モデル

**ワークスペース = N 個のウィンドウ**で、各ウィンドウが 1 本のレイアウトツリーを
持つ（`WorkspaceLayout { windows }`）。メインウィンドウは `windows[0]` に過ぎず、
全ウィンドウが同じホスト（タイトルバー + ドック + ダイアログ / 通知レイヤー）で
描かれる。

レイアウトツリーは 2 種のノードだけで構成する。

| ノード | 内容 |
|---|---|
| `Split` | `orientation`（`horizontal` / `vertical`）、`ratio`（先頭の子に与える割合、`(0.0, 1.0)`）、`first` / `second` |
| `Area` | `tabs`（パネルインスタンスの並び。空にならない）と `active`（アクティブタブの添字） |

**タブの 1 枚 1 枚がパネルインスタンス**（`PanelInstance { id, kind }`）。
同じ `PanelKind` を何枚でも開ける（全 16 種、例外なし）。区別するのは
`PanelInstanceId` で、ワークスペース全体で一意。

- **ドキュメント状態は共有する**: プロジェクト、選択（`LayerSelection` /
  `CanvasSelection` / `MediaSelection`）、アクティブコンプ、再生ヘッド。
- **ビュー状態はインスタンスごと**: ズーム / パン / スクロール / 表示対象。
  インスタンスはそれぞれ別のビューエンティティなので、状態は構造上分かれる
  （`ravel_ui::ViewStates<T>` は「エンティティより寿命の長いインスタンス別状態」を
  置く場所として定義してあるが、現時点で使っているパネルは無い）。

レイアウト操作（分割・エリアを閉じる・タブ移動・detach・窓を閉じる・複製・
既定スロット挿入）はすべて `ravel-ui` の純粋な状態遷移で、GPUI に依存しない。
ドック UI（`ravel-dock`）はツリーを描いて操作をイベントとして emit するだけで、
モデルは書かない。

## プリセット資産の形式

`assets/workspaces/*.toml`。`name` はロケールキー、`layout` は `split` / `area` の
再帰構造で、モデルの serde 表現そのまま。

```toml
name = "workspace.preset.edit"

[layout]
type = "split"
orientation = "horizontal"
ratio = 0.82

[layout.first]
type = "split"
orientation = "vertical"
ratio = 0.65

# … 中略 …

[layout.first.first.first.first]
type = "area"
active = 0

[[layout.first.first.first.first.tabs]]
id = 0
kind = "outliner"
```

- `split` は `orientation` と `ratio`、`first` / `second`
- `area` は `tabs`（`id` + `kind`）と `active`。**プリセットでもタブ統合を
  表現できる**（1 エリアに複数 `tabs` を並べる）
- `kind` は `PanelKind::panel_id()`。**変えると保存済みレイアウトが読めなくなる**
- プリセット内の `id` はプリセットの中でだけ一意。取り込むときにライブの
  カウンタから振り直される

## 同梱プリセット

| プリセット | キーバインド | 配置されるパネル |
|---|---|---|
| Edit | `Cmd+F1` | Outliner, Media Bin, Viewer, Node Graph, Timeline, Properties |
| Node | `Cmd+F2` | Outliner, Viewer, Node Graph, Dopesheet, Properties |
| Color | `Cmd+F3` | Viewer, Node Graph, Waveform, Vectorscope, Histogram, Parade, Dopesheet |
| Motion | `Cmd+F4` | Outliner, Viewer, Node Graph, Text Editor, Properties, Dopesheet |

Dopesheet / スコープ 4 種 / Text Editor は `PlaceholderPanel`
（[パネル一覧](../ui-spec.md#パネル一覧)）。プリセットは配置するので、
開くとプレースホルダが出る。

**プリセット切替はメインウィンドウのツリーだけを差し替える。** 分離ウィンドウは
「ユーザーが意図して切り出した参照面」なので触らない。切替の経路は
`Cmd+F1`〜`F4` と Workspace メニューだけで、**タイトルバーには置かない**。

## 再配置の操作

### タブのドラッグ & ドロップ

タブを押して 4px 以上動かすとドラッグになる（それ未満はタブの切替クリック）。
ドラッグ中はウィンドウ全体のカーソルが `ClosedHand`、成立しない位置では
`OperationNotAllowed`。`Escape` とマウスボタンの喪失でキャンセルする。

ドロップ先は**カーソル下のエリアの中の位置**で決まる。エリアの内容領域
（タブバーの下）を縦横それぞれ 4 分割し、外周 1/4 が分割、中央半分が合流。

| 落とす位置 | 結果 |
|---|---|
| 左 1/4 | そのエリアの左に新しいエリア（水平分割、比 0.5） |
| 右 1/4 | 右に新しいエリア |
| 上 1/4 | 上に新しいエリア（垂直分割） |
| 下 1/4 | 下に新しいエリア |
| 中央 | そのエリアのタブ列に合流 |
| タブバーの帯 | 常に合流 |

角で重なる場合は近い辺を採る。ドロップ先はドラッグ中に半透明のアクセント色で
ハイライトし、**結果が変わらないドロップ**（同じエリアの中央に落とす等）は
ハイライトも出ないし何も起きない。

**ウィンドウの外で離す**と、そのカーソル位置にワークスペースの別ウィンドウが
あればそのウィンドウへ移り（そのウィンドウの最初のエリアに合流する）、
どのウィンドウも無ければ**新しい分離ウィンドウ**になる。重なっている場合は
論理ウィンドウ ID の大きい方（＝後から作られた方）を選ぶ。

タブが 1 枚だけの分離ウィンドウのタブをデスクトップへ落としても何も起きない
（同じものを作り直すだけなので）。

### エリアメニュー（⋮）

各エリアのタブバー右端。

| 項目 | 結果 |
|---|---|
| Split Right | アクティブタブを右の新しいエリアへ移す |
| Split Down | アクティブタブを下の新しいエリアへ移す |
| Duplicate into Split | アクティブタブと同じ `PanelKind` の**新しいインスタンス**を作り、右の新しいエリアへ置く |
| Close Area | エリアごと閉じる（中の全タブを破棄） |

Split Right / Split Down は**タブが 2 枚以上ないと無効**（1 枚のエリアから
出すとエリアが空になる）。1 枚のときは Duplicate into Split を使う。

### スプリッタ

`Split` の境界（当たり幅 5px、線 1px）をドラッグして `ratio` を変える。
比は `[0.05, 0.95]` にクランプするので、どちらかのペインが到達不能にならない。
ドラッグ中はプレビューだけを描き、離したときに 1 回だけモデルへ書き戻す。

### エリアが空になったとき

タブが 1 枚も残らなくなったエリアは消え、親の `Split` は残った子で畳まれる。
最後のエリアが消えた分離ウィンドウはウィンドウごと閉じる。
**メインウィンドウの最後のタブは動かせない**（空のメインウィンドウを作らない）。

### View トグルと既定スロット

View メニュー / キーバインドのパネルトグルは、メインウィンドウのツリーを見る。

- そのパネルのインスタンスがメインウィンドウに**ある** → 最初のインスタンスを
  エリアから取り除く
- **ない** → `PanelKind::default_slot()` のエリアへ挿入してフォーカスする

これで**アクティブプリセットが配置していないパネルもトグルで出せる**
（プリセット配置に依存しない）。

| スロット | 解決の仕方 | 既定にしているパネル |
|---|---|---|
| `Left` | 最も左のエリア | Outliner, Media Bin |
| `Right` | 最も右のエリア | Properties, Waveform, Vectorscope, Histogram, Parade, Text Editor |
| `Bottom` | 最も下のエリア | Timeline, Dopesheet, Curve Editor, Lua Console, Render Queue |
| `Center` | 各分割で大きい側の子を辿った先のエリア | Node Graph, Viewer, Shader Editor |

View メニューのチェック状態は「メインウィンドウにそのパネルのインスタンスが
1 枚以上あるか」から導出する（分離ウィンドウは数えない）。

挿入・除去はレイアウトモデル側で 16 種すべてに対応し、**View メニューの
コマンド 13 個が 16 種すべてに届く**（`view.toggle_scopes` が Waveform /
Vectorscope / Histogram / Parade をまとめて動かすので、コマンド数はパネル数より
3 つ少ない）。プリセットが配置していないパネルもトグルで出せる
（[パネル一覧](../ui-spec.md#パネル一覧)）。

## ウィンドウ

### detach と reattach

| 操作 | 意味 |
|---|---|
| タブをウィンドウの外へドラッグ | そのインスタンスを新しいウィンドウへ |
| `Cmd+Shift+D` | **フォーカス中のパネルインスタンス**を新しいウィンドウへ |
| `Cmd+Shift+R` | **フォーカス中インスタンスのウィンドウの全パネル**をメインへタブとして戻し、そのウィンドウを閉じる |

`Cmd+Shift+D` は、そのインスタンスがメインウィンドウの最後のタブのとき、および
既に単独で分離ウィンドウにいるときは何もしない。`Cmd+Shift+R` はフォーカスが
メインウィンドウにあるときは何もしない。

戻ってきたインスタンスは `PanelKind` の既定スロットへ入る（ID は保たれる）。

### 分離ウィンドウを閉じる

クローズボタンは**そのウィンドウのインスタンスを破棄する**（メインへ自動で
戻らない）。多重インスタンスがあるので「1 枚しか無いパネルを失う」ことは無く、
同じパネルはトグルで出し直せる。クローズは必ずシェルを通るので、レイアウトと
ウィンドウハンドル表が食い違わない。

### タイトルバー

全ウィンドウが同じコンポーネント（`title_bar::RavelTitleBar`）を描く。
プラットフォームのウィンドウコントロール + ドラッグ領域 + ウィンドウの中央に
寄せたラベル + 窓種別のスロット。

| ウィンドウ | 中央のラベル | スロット |
|---|---|---|
| メイン | 開いているプロジェクトファイルの stem（保存前は `app.untitled_project`） | 先頭にアプリ名 |
| 分離 | パネル 1 枚ならパネル名、複数なら `window.panels`（「N 個のパネル」）、0 枚ならアプリ名 | 末尾に AlwaysOnTop ピン |

分離ウィンドウの OS ウィンドウタイトルも同じ規則で、タブ構成が変わると
書き換わる。

### AlwaysOnTop

分離ウィンドウのタイトルバーのピンで、そのウィンドウを常に前面に固定する。
状態は `WindowLayout.always_on_top` が持ち、**ウィンドウごとに独立**。
ウィンドウを開くときにも適用するので、固定したまま終了して再起動しても
固定されたまま戻る。

### メインウィンドウとの連動

- **クローズ追従**: メインを閉じると全分離ウィンドウも閉じる
- **最小化追従**: メインの最小化に分離ウィンドウが追従して最小化し、復帰で
  一緒に戻る（復帰後はメインウィンドウがキーウィンドウになる）
- **フォーカスは連動しない**（AlwaysOnTop と噛み合わないため）

### ダイアログと通知

全ウィンドウがダイアログレイヤーと通知レイヤーを持つ。分離ウィンドウで開いた
ダイアログもそのウィンドウに表示される。

## 永続化

| 対象 | どこへ | いつ |
|---|---|---|
| 全ウィンドウのツリー・配置・AlwaysOnTop・名前付きレイアウト | `<config>/ravel/layout.toml` | コマンド 1 つごと（内容が変わったときだけ、バックグラウンド）と終了時 |
| 現在のレイアウト | `.ravprj` の任意エントリ `workspace_layout.toml` | **オプトイン（既定 OFF）**のときだけ、プロジェクト保存時 |

- 起動時に `layout.toml` を読んでレイアウト・ウィンドウ配置・AlwaysOnTop を復元
  する。復元されたウィンドウはホストが開き直す。
- 記録した配置は手で編集できるテキストなので、開けないウィンドウ
  （画面外・サイズ 0・非有限値）になる記録は捨てて既定サイズで中央に開く。
- **埋込を適用するのはセッション限定**。埋込ありのプロジェクトを開いても
  `layout.toml` のアプリ既定は書き換えない。埋込なしのプロジェクトを開いた
  ときは前回のアプリ既定を使う。
- 埋込エントリには**ユーザーの名前付きレイアウト集と埋込設定そのものを
  書かない**（他人のプロジェクトへ漏らさないため）。
- 読めないファイル（切り詰め・非 TOML・未知の `layout_version`）は既定
  レイアウトに倒す。**レイアウトが起動を妨げてはならない。**
- ディスクへの書き出しはコマンドの境界と終了時だけで、1 操作ごとではない。
  コマンドを経由しない変更（AlwaysOnTop ピン、埋込チェックボックス、
  ウィンドウの移動）はモデルにはすぐ入るが、次のコマンドか終了までファイルには
  現れない（フレームごとの I/O を避けるための意図的な設計）。

### 名前付きレイアウト（Manage Layouts）

Workspace ▸ Manage Layouts… で開くダイアログが名前付きレイアウトの唯一の導線。

- 名前を付けて**現在のメインウィンドウのツリー**を保存する（分離ウィンドウは
  含めない — プリセット切替と同じ理由）
- 一覧から Apply（メインウィンドウのツリーを差し替え）、Delete（ライブラリから
  忘れる。適用中のものを消しても表示は変わらない）
- **`.ravprj` への埋込トグルはこのダイアログにある**。保存ダイアログは OS 純正の
  ファイル選択パネルで自前のコントロールを載せられないため。挙動としても
  「このユーザーのプロジェクトをどう書くか」の常設選択

アクティブコンポジションは `ui_state.json`（`.ravprj` の任意エントリ）に
永続化する（欠落時は `Document.root_comp` にフォールバック）。

## 制約 — できないこと

| 項目 | 状態 |
|---|---|
| ビュー状態のウィンドウ間移送 | 🔲 detach したパネルは分離ウィンドウで既定状態から始まる。分離ウィンドウ内で作ったビュー状態は reattach で失われる（元のウィンドウ側の状態は保たれ、戻すと同じものが出る）。GPUI のパネルフォーカス購読がウィンドウに束縛されているため、エンティティをそのまま運ぶと `Cmd+Shift+D` / `R` のフォーカス解決が壊れる |
| `Cmd+Shift+D` の直後の `Cmd+Shift+R` | 🔲 何も起きない。開いた分離ウィンドウはホストの focus handle を取るだけで、中のパネルはフォーカスを受け取らない → `Cmd+Shift+R` が見るフォーカス中インスタンスが `None` になる。分離ウィンドウのパネルを 1 度クリックすれば動く |
| ドラッグ中のタブのプレビュー描画 | 🔲 非対象。運んでいるタブそのものは描かず、フィードバックはカーソルの形と（ドラッグ元のウィンドウの中だけの）ドロップ先ハイライトだけ。ウィンドウをまたぐドラッグでは落とすまで行き先が見えない |
| 新しい分離ウィンドウが開く位置 | 🔲 落とした位置ではなく画面中央（640×480）。配置を持たない新規ウィンドウは既定サイズで中央に開く |
| ウィンドウ内フローティングパネル | 🔲 採用しない。浮くパネルは分離ウィンドウに一本化する（データ構造上も表現しない） |
| Workspace メニューのプリセットチェック | 🔲 手でレイアウトを組み替えても（タブ D&D・分割・View トグル）直前のビルトインを指したまま。名前付きレイアウトを Apply したときだけモデル上は解除される。ネイティブメニューはそもそもチェックマークを描けない（[制約](../ui-spec.md#制約前提条件)） |
| ビューア専用全画面ウィンドウモード | 🔲 未実装（REQ-UI-009 の残項目）。全ウィンドウ同型モデルの上に載る後続機能 |
| 分離ウィンドウへの OCIO カラースペース適用 | 🔲 未実装（REQ-UI-009 の残項目）。カラーマネジメント側の計画に属する |
| 非 macOS のタイトルバー中央寄せ補正 | ⚠️ Windows / Linux では実機未検証（右側のウィンドウコントロール幅をバーの高さから導出している） |
| `Cmd+F1` | ⚠️ macOS 側でディスプレイのミラーリングに割り当てられている機体では OS に飲まれて Ravel に届かない。`F2`〜`F4` と Workspace メニューは影響を受けない |
