# [HIGH-34] オフラインの素材はレンダー結果を黙って透明にする — 機械可読な警告が無い

| 項目 | 内容 |
| --- | --- |
| 深刻度 | high |
| 種別 | bug |
| 領域 | ravel-cli / render, ravel-nodes / media |
| 該当 | `crates/ravel-nodes/src/media.rs`（`fallback_frame`）, `crates/ravel-cli/src/plan.rs`（`Warning`）, `crates/ravel-cli/src/report.rs` |

## 現状

`media` ノードは素材が解決できないとき**透明フレームを返して評価を続ける**。
これは意図的な設計で、1 つの素材が見つからないだけで合成全体が失敗するのを
避けるためのもの。落ちる代わりに `tracing::warn!` を 1 度だけ出す。

問題は**その警告が機械可読な出力に出ないこと**。`ravel-cli render` の
`Warning` 列挙には音声側（`AudioNotRendered` / `AudioSourceSkipped`）しか無く、
**映像側のオフラインに対応する variant が無い**。その結果、次の 3 つが起きる。

- `ravel-cli render` は**成功終了し**、真っ黒（透明）のフレームを書き出す
- レポート（`report.rs`）にも `--json` 出力にも何も出ない
- 気づけるのは `tracing` のログを読んだ人だけ

音声側は同じ状況を `AudioSourceSkipped` で「絵は残す価値がある、しかし
無言にはしない」として扱っており、**映像側だけが無言**という非対称になっている。

## 影響

**出力が静かに間違う。** `roadmap.md` の基準 0（出力の誤りを先に）に該当する。
バッチレンダーや CI から回す使い方では、素材のパスが変わっただけで
「成功した真っ黒な納品物」が出る。

`AID-1` / `AID-2`（`.ravprj` v9、素材の同一性）で**オフラインに到達する経路が
増えた**ので、頻度は上がっている:

- 素材を削除したあとの参照は、v9 では「オフライン」が正常な状態になった
- プロジェクト間でレイヤーをコピーした参照は、v9 では**繋がらない**のが正しい

どちらも設計どおりだが、レンダーがそれを言わないと「繋がらなかったこと」が
ユーザーに届かない。

## 修正方針

**決着済み**: `docs/implementation/render-warning-channel-plan.md` の
`WARN-2` が実施する。収集経路は下記 (b)（レンダー前の静的走査）— 同計画の
`WARN-1` が識別子パラメータを静的な値だけに畳むので、
**「評価しないと分からないオフライン」が存在しなくなる**。以下は判断の記録。

`Warning` に映像側の variant を足し、評価が返したオフラインを収集して
レポートと `--json` に出す。**素材ごとに 1 行**（レイヤー名 + 素材の表示名 +
理由）で、音声側の `AudioSourceSkipped` と同じ粒度に揃える。

収集経路の判断が要る: `media` プロセッサは評価中に警告を出すので、
(a) 評価結果に警告を載せて返すか、(b) レンダー前に文書を走査して
「解決できない参照」を数えるか。(b) のほうが安いが、**評価しないと分からない
オフライン**（時間依存で素材が変わる経路）は拾えない。

`--strict` のような「オフラインがあったら失敗させる」オプションを足すかは
別の判断。バッチ用途では欲しいはず。

## 備考

`AID-2` のレビュー中に発見した。**この欠陥は `AID-*` が持ち込んだものではない** —
オフラインの素材が透明フレームになる挙動と、`Warning` に映像側が無いことは、
どちらも以前からある。`AID-*` はそこへの到達可能性を上げただけ。
